## 编码说明

数据集原始编码是**压缩形式**，不是标准 GB/T 2260 六位码：

- 省级 2 位（`11` = 北京市）
- 市级 4 位（`1101` = 市辖区）
- 区县级 6 位（`110101` = 东城区）

`scripts/import_regions.py` 导入时把省/市编码**右侧补零到 6 位**（`11`→`110000`、
`1101`→`110100`），以对齐 GB/T 2260 标准。

## 已知取舍

1. **乡镇/街道级节点已排除**。数据集中有 82 个 9 位 code，实际是乡镇/街道，
   全部属于东莞市、中山市、儋州市、嘉峪关市这 4 个「直筒子市」——它们在行政上
   不设区县，直接管辖乡镇。按「最小只能选到区县」的要求排除，这 4 个市到市级即为终点。

2. **直辖市多一层「市辖区」**。北京/天津/上海/重庆 的市级节点名为「市辖区」
   （重庆另外还有「县」），因此树形会是 `北京市 → 市辖区 → 东城区`。
   这是数据集的真实行政结构，未做改写；如果前端希望显示成 `北京市 → 东城区`，
   可以在展示层折叠这一层，或在导入脚本里做映射。

3. **港澳台未导入**。它们在 `HK-MO-TW.json` 中，顶层是 dict 而非 list，结构与大陆
   不一致，且当前业务数据源（datacenter MCP）覆盖范围为主陆。需要时再单独处理。

## 更新方式

区划每年会变（撤县设区、撤市设区等）。更新流程：

1. 重新下载 `pca-code.json`，更新上表的 commit 与下载日期；
2. 重跑 `python scripts/import_regions.py`（幂等，只 upsert 不删除）。

> 注意：脚本不会删除数据库中已存在但新数据集里没有的区划——避免误删被
> `user_followed_regions` 引用的行。区划撤并需要人工确认后再清理。
