# 聊天输入限制规格增量

## Purpose

为用户提供清楚且一致的单次文本输入长度约束，使页面能够在发送前解释超长输入，后端继续拥有最终校验权。字符限制独立于模型 token 容量，防止模型窗口扩展、企业切换或前后端配置漂移使同一段文字产生不可预期的发送结果。

## ADDED Requirements

### Requirement: 单次用户文本限制独立可配置

系统 SHALL 保留默认 8,000 字符的单次用户文本限制，可由受保护部署配置修改；模型上下文窗口或摘要比例改变不得自动放大该限制。三个公开图 SHALL 使用一致的字符计数和校验语义；摘要、工具结果及完整历史不得当作用户本次文本一起计入字符上限。

#### Scenario: 模型窗口扩展
- **WHEN** 模型窗口从 192,000 更新为 1,000,000 token，未修改输入字符限制
- **THEN** 用户本次文本上限仍为 8,000 字符，页面不显示为百万字符

#### Scenario: 边界与 Unicode
- **WHEN** 相同已提交文本在页面和后端分别校验，包含中文、英文、换行或 emoji
- **THEN** 两端计数和规范化规则一致，长度等于上限可提交，超过上限不可提交
- **AND** 不将 UTF-16 代码单元、UTF-8 字节和模型 token 混称为字符

### Requirement: 页面读取后端权威限制

系统 SHALL 通过已认证同源读取向页面提供当前生效的输入限制，响应不得包含凭据或模型内部规则。身份、企业、上下文版本或图变化后的迟到结果 MUST 被丢弃；配置未知或读取失败时页面不得把本地常量宣称为当前服务端配置。

#### Scenario: 部署限制改变
- **WHEN** 后端将限制配置为 12,000 字符
- **THEN** 页面读取后显示并执行 12,000，绕过页面直接提交仍由后端执行相同限制

#### Scenario: 配置读取失败
- **WHEN** 配置接口返回未登录、无权、身份服务故障或网络错误
- **THEN** 页面提供对应状态与重试入口，保留草稿，并在取得可信限制前不发送
- **AND** 不通过匿名接口、跨企业缓存或旧页面结果假装配置已就绪

### Requirement: 超长文本在发送前获得明确反馈

页面 SHALL 显示当前字符数量与上限，并在超限时通过按钮、表单提交和键盘发送路径一致阻止提交。粘贴和输入法组合输入 MUST 保留草稿并得到可理解的超限反馈，不静默裁断文本；未超限的中文输入法确认操作不得误触发送。

#### Scenario: 粘贴超过上限
- **WHEN** 用户粘贴超过当前限制的文本并点击发送或按发送快捷键
- **THEN** 页面明确提示超出字符限制，草稿保留，不创建线程运行或受理请求

#### Scenario: 输入法与窄屏
- **WHEN** 用户使用系统中文输入法确认候选词，或在窄屏查看超限提示
- **THEN** 候选词确认不触发发送，计数与说明可读取，键盘操作和焦点保持正常

### Requirement: 后端是不可绕过的最终校验

系统 SHALL 在用户文本进入模型或工具执行前进行服务端长度校验，包括直接 API 提交与首次无历史的请求。浏览器传入的限制值不能覆盖服务端配置；超长输入不得产生模型或业务工具外呼，不得被静默截断后继续执行。

#### Scenario: 绕过页面提交
- **WHEN** 用户直接向三个公开图之一提交超限文本，或伪造更大的客户端限制
- **THEN** 服务端明确拒绝执行并说明字符限制，模型及业务工具请求数均为零
- **AND** 同一身份提交未超限文本的正向控制可正常进入获准流程
