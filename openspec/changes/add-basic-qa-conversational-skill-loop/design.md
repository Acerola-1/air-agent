# 基础问答多轮 Skill 循环设计

## Context

动机及范围见 [proposal.md](proposal.md)。本设计的代码基线为 `7d79526`，以下是源码核对结果，不是已完成的新功能：

- `src/common/business_graph/nodes.py` 的 `classify_intent`、`resolve_skill` 仅取最后一个 HumanMessage；向量 top1 决定内联规则。`prompting.py` 禁止模型改选。
- `builder.py` 已有 `call_model → execute_tools → call_model` 循环和独立 `answer_model → ledger_finalize`；构造了 `load_skill`，却未将其注册为实际模型/执行工具。
- `skill_content.py` 目前返回规则字符串并发观测事件，不能作为持久化加载状态；其 mtime 缓存不同于 `capabilities.py` 的材料内容指纹。
- `_available_tools` 的注释声称按 Skill 收窄，实际 data_query 分支只做能力选择过滤；执行包装器可动态绑定业务工具，需要真实执行入口门禁。
- 消息由同一 thread 恢复，模型实际输入经过 `context_preparation.py` 投影/整理；不能把全部 checkpoint 消息直接塞回模型，也不能删除治理以换取追问能力。
- 本图现有九个 Skill。声明包含 `text2sql_*`、`chart_*` 等历史名称；不能直接把未经核验的声明当成已存在工具，也不能因缺失放开全部工具。
- `tool_recovery.py` 当前限制每用户轮最多八个含工具调用的规划批次，并对重复拒绝止损；新控制工具需要纳入该有界机制。
- `docs/CURRENT-RUNTIME.md` 指向三仓权威运行清单；本次规划未启动服务、未探测真实连接、未验证线上模型行为。

主规格存在历史漂移：`business-graph-architecture`、`progressive-skill-tool-disclosure` 只存在于归档变更，不是当前主规格。`skill-three-layer-system`、`skill-content-basic`、`composite-backend-routing` 仍是缺 Purpose 的早期 delta 格式，CLI 无法将部分文件作为完整主规格解析。本提案提供与本范围相关的完整 MODIFIED 块，不重写所有历史架构；未来同步前需先作保持语义的主规格格式整理。其他活动变更中的未完成验收不由本提案宣布完成。

## Goals / Non-Goals

**Goals:**

- 将是否检索和选哪个 Skill 交给拥有会话上下文的模型；将是否合法加载、可执行哪些工具交给服务端。
- 保持有记忆的外层用户会话和本轮模型/工具循环相互独立；材料可以复用，执行资格必须重新校验。
- 给加载、工具范围、并行顺序、终答、恢复提供可执行断言，避免只改 prompt。

**Non-Goals:**

- 不迁移为 Deep Agents，不新增多 Agent、文件系统、shell 或自动跨图调度。
- 不恢复 Skill/MCP 人员绑定，不扩展企业角色权限体系，不修改 IAM 仓库。
- 不新增污染源归因 Skill，不重构 tracing，不恢复 data-analysis 专项开发。
- 不承诺 embedding/模型必然选对，也不将测试通过表述为所有对话语义均可确定性保证。

## Decisions

### 1. 保留现有图，重接 Basic QA 入口

目标接线：`受理与输入检查 → 初始化本轮 → 准备模型上下文 → call_model ⇄ 工具执行 → answer_model → ledger_finalize`。初始化负责识别可信 submission/attempt 及真实用户消息边界；每轮默认空活动 Skill。只保留长度等确定性拒绝检查，Basic QA 不再由最新一句的 chitchat/knowledge/data_query 分支预先锁定能力。纯聊天也由有上下文的模型决定，不另加一个强制意图模型。

保持当前最终正文专用发送阶段，内部选择、控制工具和草稿不作为用户正文。模型不再调用工具时直接进入既有终答阶段；finish_planning 保持无参数的可选结束信号。共享 builder/nodes 的新增行为使用明确 Basic QA 策略入口，data-analysis 自有菜单流程和 tracing 调度保持原样。

替代方案：只给 embedding 改写问题仍保留强制检索和 top1 决策；整图迁移 Deep Agents 会同时改变工具面、状态与输出。本次选择已有循环上的渐进改造。

### 2. 目录常驻、搜索可选

首次规划提供九个 Skill 的精简目录：`skill_id`（`skill:basic-qa:<slug>`）、名称、简介、`material_version`、可用状态。目录过滤沿用实时业务、已受理显式选择及工具范围；显式模式仅可加载锁定项。

`search_skills(query: str)` 复用 `SkillSemanticRouter.amatch` 的 embedding 检索，query 由模型根据上下文形成；不另加固定查询改写模型。输入校验限制长度、禁止空串；默认最多返回五个当前有效候选（ID、简介、版本、可用性、匹配分数），不返回正文、不自动加载。实际次数受本轮循环预算约束。搜索失败时可使用现有目录直接加载；只有模型选择确有匹配且加载校验成功才执行，不以失败作为放宽门禁理由。

不能默认把整段会话拼成 query。提示词要求最小业务检索语句，普通日志移除现有 router 的查询原文输出；搜索缓存不以明文对话作为共享 key，使用作用域、目录版本与查询摘要且有界失效，不能跨用户/企业混用。embedding 的网络调用仍经过逐发送守卫；已启用的受控 Langfuse 采集继续遵守现有独立正文契约，不擅自改其开关。

替代方案：每轮先搜索再让模型决定仍浪费调用且可能误导上下文；只给 load 而不保留搜索则损失现有语义召回。此方案保留两条路径。

### 3. load_skill 是规则和工具集的受控状态转换

工具输入建议为 `load_skill(skill_id: str, expected_version: str)`。模式取服务端有效配置，不接受模型覆盖；不接受路径或自由工具列表。

加载顺序：核验可信受理/业务 → 校验图和显式选择 → 读取登记目录及材料快照 → 校验版本/模式/工具依赖 → 生成完整规则及稳定工具映射 → 原子提交活动状态和成功 ToolMessage。读取及提交使用同一快照，复核指纹防止加载期间材料变化。文件读取失败应明确错误，不使用当前指纹函数中“读取失败视为空字节”的行为来认可材料。

缓存键至少包含图、Skill ID、材料指纹和模式；缓存只保存静态材料，不保存人员许可、凭据或已发现的实时工具资格。缓存命中也重新核验资格、连接修订、选择及材料。总纲和模式文件缺失均失败；不沿用旧加载器专家模式缺失回退 fast 的行为。工具成功返回必要规则及受限工具描述，下一次模型请求重新绑定 schema；加载不隐式运行查询。

新状态建议：`skill_runtime_version`、可信 `turn_key`、`active_skill`（ID、材料版本、模式、load_call_id、受理范围摘要）、历史加载引用、控制失败计数和证据引用。活动工具集合由上述可信信息及实时目录重算。客户端传入的活动状态、旧规则字符串、进程级观测缓存一律不能激活工具；原生入口须拒绝/忽略伪造状态并从可信运行重建。状态更新可用 LangGraph Command 或专用控制节点，但不能依赖逐节点就地改 `config`。

### 4. 新轮重置、顺序切换、显式锁定

每个新用户轮清空活动状态，不清除对话历史及证据。需要业务工具时模型再次 load；同 Skill 通常命中材料缓存且无需 search。这样增加一次轻量模型/工具往返，但规则和工具资格边界可直接验收。线程缓存自动激活作为以后可能的优化，不纳入首版。

每次发送必须明确写出“本轮未加载”或当前活动 Skill；模型投影中的过往加载回执标为历史记录，不能保留模糊的当前成功含义，原始执行记录不改写。未加载时模型仍可能从历史沿用工具名，执行入口应返回可恢复的 `skill_not_loaded` 和先加载再查询的说明，而不是人员权限403。该错误不永久耗尽目标工具；模型补加载后仍可继续原查询。当前 Skill 不匹配或加载记录失效分别提示换技能或重载。真正的身份/业务授权拒绝继续停止，不能转成重载提示或自动放行。

首版仅一个活动 Skill；自动模式可在循环中顺序切换，替换当前规则与工具，不做工具并集。S1 的数据证据继续保留 S1 版本/城市/时间来源；S2 不得改写旧结果归属。尝试切换失败则清空活动执行状态，要求重新成功加载，防止模型按新任务误用旧工具。显式模式仅允许已受理 S1，冲突时解释限制，用户用新 submission 改选。

用户“复述上一轮”不强制 load；只使用有来源的已有事实，不引入新业务计算结论。mode、身份上下文或材料变化都不能通过历史活动状态静默跨越。resume 不是新用户轮：保留原受理范围，恢复有效已加载版本；版本/连接/资格失效拒绝恢复，要求新提交。

### 5. 工具分类与双处约束

分类集中登记，禁止由模型决定：

- 控制工具：search、load、finish；不作为数据获取成功。
- 通用工具：现有时间、knowledge_search、create_artifact 等；仍保留知识引用、受控产物和本身作用域限制，不开放任意地址/代码/数据读取。
- 受限证据处理：计算及已归档结果读取只能处理当前用户/企业/线程获准的证据引用；不能借计算工具绕过加载做新的外部业务查询。
- 领域数据工具：MCP 及本地业务查询/分析函数，要求活动 Skill；未知类型默认不作为通用例外。

工具集合取交集：开发侧业务注册 ∩ 受保护连接与 `approved_query_tools`（适用时）∩ 本次已受理选择 ∩ 活动 Skill 工具声明。人员只检查业务使用资格（企业开通 ∩ 本企业角色），没有人员→MCP 授权关系。

先修正九个 Skill 的历史工具别名、声明和实际稳定 ID 对应；禁止仅按同名匹配跨服务工具。根据用户2026-10-28确认，非绘图工具均声明为必需依赖，绘图工具声明为可选依赖；缺必需工具时加载失败，可选绘图工具不可用不影响正文规则加载，并跳过该绘图步骤、说明图表缺失。工具存在但调用后无数据仍按原材料的数据缺失规则处理，不等同于工具不存在。声明覆盖总纲和模式文件实际引用；该分类不授权新增工具或替换原数据源。不借路由重构改指标或法规。

在模型 schema 构建和 `composed_tool_wrapper`/实际 MCP 与本地业务入口两处使用同一范围判定；重试重新判定，保留原身份/受理/删除门禁。加载与业务调用同批、多个 load 同批，整组冲突控制/领域调用拒绝，无领域外呼，返回每个 tool_call_id 的配对错误结果，要求模型单独加载。load 与 finish 同批也拒绝，避免加载即结束而跳过新规则。没有 load 的独立业务工具仍允许按同一已提交活动状态并行，取消后尚未发出的调用不得启动。

### 6. 每次实际发送恢复规则，自然结束规划

规划、nudge、终答、cleanup 的实际请求都从有效活动状态构造规则，再走现有 `prepare_model_request`；不能只在 prepare_model 节点拼一次字符串。历史 ToolMessage 的规则是执行记录，不是当前权威材料；避免重复内联旧规则，Skill 返回不走会丢失规则的普通大业务数据压缩链。每次上下文计量包含目录、有效规则、工具 schema、证据和摘要；不能容纳时按原预算受控终止，不截掉刚性规则。

`finish_planning` 保持无参数，仅表示规划完成；模型没有工具调用时也可自然进入终答。终答保留有效历史、摘要、当前规则与原始工具结果，通过既有上下文预算和流式发布链路生成。接口字段含义由模型依照 Skill 和工具说明理解，不要求供应商回显查询城市、时间或指标，不新增回答类别、证据 ID、时间覆盖或派生结果的服务端语义校验，也不据这些字段缺失拦截回答。原有知识引用、业务失败提示、身份和工具范围检查维持各自职责。

此前新增的结果结构适配器、check_finish 和证据白名单投影已按用户2026-10-28明确纠正撤销。实际工具样本可以作为排错记录，不再是本次多轮循环接线的前置条件。回答是否准确、指代是否正确由固定多轮用例及真实模型验收评估，不额外构建通用接口结果审计系统。

不引入额外常驻评审模型。保留本轮八个含工具调用的规划批次上限（search/load 同样计数）；同参数同失败的控制调用最多允许一次纠正重试，身份/范围拒绝不自动重试。整体超时、取消及服务商上下文恢复沿用既有更紧限制；达到预算通过受限终答收口，不重启顶层 attempt。

### 7. 观测与固定验收

使用既有稳定 ID、submission/attempt 和事件链区分 searched/matched、selected、loaded、实际领域执行；具体事件使用既有枚举兼容映射，必要新增字段同步契约及校验器。直接 load 没有 matched 事件；缓存 load 仍是本轮 loaded，业务未调用不能记 executed。`observe_skill_executed` 不能仅根据规则字符串存在判成功；实际执行关联真实工具结果，HTTP200、加载完成或最终消息生成均不构成成功数据证据。

创建 `bqa-conversation-loop-v1` 固定验收集，继承现有九 Skill 单轮参考集，补至少以下多轮链：

1. 湖州今天 → 那杭州呢 → 可能原因 → 缩成两句 → 谢谢。
2. 无历史省略提问；查询后换完全不同领域问题；多个城市后模糊“那里”。
3. 先当前空气质量再排名/趋势，覆盖 Skill 切换；显式 Skill 不合适时限制说明。
4. 摘要覆盖首轮后追问、原生持久化重开、旧 checkpoint、mode/材料变化。
5. 搜索无命中/超时、目录直接加载、必需/可选依赖缺失、两次同失败、预算耗尽。
6. load+查询同批、load+finish、多 load、旧 schema、伪造活动状态、同名跨服务工具、MCP 空集合。
7. 加载后撤权/取消/删除、企业上下文切换，配有效正向控制；验证真实计数服务新增外呼为0。

固定用例清单须逐条给输入、允许/禁止动作、期望目标城市/时间、回答依据及计数范围；冻结数据时钟和工具样本。受控测试精确断言；真实模型每条语义核心链至少运行三次并保留所有结果，人工核对9个 Skill 的选择与领域边界。关键范围反例必须全通过；核心语义链不得存在未解释失败，不以总体平均分掩盖串城或虚构事实。

同样用例在旧基线与新版记录搜索/embedding/load/业务外呼/模型次数、首正文和总延迟、可得 usage 与错误；真实数据变化时不直接比较值。新增 load 的延迟成本实测披露，不预设一定更快，不把小样本当容量结论。使用自有临时资源验证真实 SDK/checkpointer 和本地计数 MCP，真实配置模型、真实服务、浏览器另列证据。当前官方入口/共享服务只按授权读取，不在正式库造测试数据或重建退役评测栈。

## Risks / Trade-offs

- [模型可能漏选或错选 Skill] → 简介覆盖九个现有能力、保留可选搜索、加载/执行门禁、固定真实模型多轮验收；门禁只保证过程，语义质量另外验收。
- [每个新业务轮 load 增加往返] → 缓存材料、跳过不必要搜索、并行独立业务查询；量化成本，不提前引入自动激活优化。
- [规则切换后历史证据混淆] → 单活动 Skill、按调用保存来源/版本/对象/时间、保留历史来源供模型理解；规则不做无条件并集。
- [旧提示配置仍禁模型换 Skill] → 检查代码提示与 Langfuse 管理提示的兼容性，按批准范围更新版本；不在运行中让旧远程模板覆盖新硬约束。
- [跨图共享包装器回归] → 图策略显式隔离，data-analysis 菜单与 tracing 主子任务做必要共享回归，不扩展封存图范围。
- [既有主规格不规范/历史冲突] → 本变更保持有范围 delta，未来同步前做格式规范化与差异审查，不通过归档重演旧目录或权限架构。

## Migration Plan
