## MODIFIED Requirements

### Requirement: 服务连接独立于人员授权
系统 SHALL 从平台维护的部署配置解析业务可用服务，支持明确的企业连接或共享只读连接，不查询旧企业/成员授权绑定。配置须声明服务键、地址、启停、认证方式、秘密引用、作用范围及修订，浏览器不能指定连接或凭据。Basic QA 的 Skill 加载只控制当前任务的规则和工具启用，不生成连接或新增人员授权。

#### Scenario: 无旧绑定也能查询
- **WHEN** 有业务资格的用户没有任何旧MCP绑定，业务有有效服务连接
- **THEN** 可以发现业务范围内工具，不要求用户手动选择Skill或人工给该成员绑工具；Basic QA 领域工具由模型按需加载 Skill 后执行，其他图保留既有执行策略

#### Scenario: 连接缺失或配置变化
- **WHEN** 服务未配置、凭据缺失、停用或运行中连接修订改变
- **THEN** 明确报连接不可用或要求新运行，不回退其他企业连接、旧凭据或测试协议

### Requirement: 业务范围与用户选择共同约束
实际工具 SHALL 属于开发侧声明的业务范围并满足本次已受理选择；普通Skill无需独立人员许可。Skill依赖、材料版本、菜单及子任务约束继续检查，模型不能通过自造工具调用扩大执行集合。Basic QA 领域工具还 SHALL 满足当前活动 Skill 的执行范围，不因自动模式绕过加载前置条件。

#### Scenario: 不经 Skill 的 MCP 调用
- **WHEN** 自动模式直接请求业务允许的查询工具且连接正常
- **THEN** Basic QA 未加载 Skill 时拒绝领域工具并要求先加载，实际外呼为0；其他图按原执行策略运行，均采用同一业务准入且无需人员工具绑定

#### Scenario: 用户明确不用 MCP
- **WHEN** 运行选择MCP空集合，模型或子任务仍尝试调用工具
- **THEN** 网络请求为0；取消逐项RBAC不取消本次用户选择限制
