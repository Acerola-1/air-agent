## MODIFIED Requirements

### Requirement: 服务连接独立于人员授权
系统 SHALL 从平台维护的部署配置解析业务可用服务，支持明确的企业连接或共享只读连接，不查询旧企业/成员授权绑定。配置须声明服务键、地址、启停、认证方式、秘密引用、作用范围及修订，浏览器不能指定连接或凭据。Basic QA加载Skill或独立工具只管理会话中的材料和工具披露，不建立人员授权或由模型指定新的连接。

#### Scenario: 无旧绑定也能查询
- **WHEN** 有业务资格的用户没有任何旧MCP绑定，业务有有效服务连接
- **THEN** 可以发现业务范围内工具，不要求人工给成员绑定；Basic QA可经Skill或独立工具加载执行，其他图保持原策略

#### Scenario: 连接缺失或配置变化
- **WHEN** 服务未配置、凭据缺失、停用或运行中连接修订改变
- **THEN** 明确报连接不可用或要求新运行，不回退其他企业连接、旧凭据或测试协议

### Requirement: 业务范围与用户选择共同约束
实际工具 SHALL 属于开发侧声明的业务范围并满足本次已受理选择；普通Skill无需独立人员许可。Skill依赖、材料版本、菜单及子任务约束继续检查，模型不能通过自造工具调用扩大执行集合。Basic QA执行 SHALL 核对本次模型实际收到的工具定义、真实模型调用与参数、当前身份／业务／连接及不可变受理选择。Skill归属、独立加载记录或当前激活状态不得作为额外的执行权限；加载用于准备模型上下文。

#### Scenario: 不经 Skill 的 MCP 调用
- **WHEN** 自动模式成功独立加载业务允许的查询工具且连接正常
- **THEN** Basic QA可执行该工具，与Skill路径采用同一业务准入；其他图不因此增加新的加载机制

#### Scenario: 用户明确不用 MCP
- **WHEN** 运行选择MCP空集合，模型或子任务仍尝试调用工具
- **THEN** 网络请求为0；取消逐项RBAC不取消本次用户选择限制

#### Scenario: 停用一项Skill仍有其他有效来源
- **WHEN** 当前工具仍被另一活动Skill或独立激活引用
- **THEN** 工具继续按当前范围可用，不因退出的Skill而错误撤销，也不因此绕过实时业务和连接检查

#### Scenario: 已披露工具不要求独立加载凭证
- **WHEN** 工具定义已由服务端提供给本次模型请求，工具与真实模型调用绑定一致，schema和当前授权均有效，但没有对应Skill或独立加载记录
- **THEN** 可以执行，不因缺load_ref或不属于活动Skill而拒绝；实际请求由业务发送边界核权

#### Scenario: 已提出调用后激活状态变化
- **WHEN** 本次模型已经使用有效工具定义提出调用，之后仅上下文激活状态变化，真实授权、选择、工具定义及调用绑定均未变化
- **THEN** 不因激活状态变化单独拒绝本次执行；后续模型请求仍按当时的上下文状态提供定义
