# IAM 权限目录交接

本文件是配置契约，不授权修改IAM代码、正式库或任何现有root口令。现有IAM的通用权限/角色管理应能承载精确新码，无需重新做身份服务；若实际API不支持，记录具体阻塞，由IAM负责人补一个窄change，不能在Agent伪造权限。

| 权限 | 来源 | 使用 |
|---|---|---|
| `agent:metrics:read` | 已有 | 安全聚合/榜单 |
| `agent:operations:read` | 已有 | 企业运行、可识别用户用量、反馈明细 |
| `agent:content:read` | 已有 | 问题/回答/意见/说明/样本正文；与ops并用 |
| `agent:feedback:manage` | 6新增 | start/resolve/reopen反馈处理；必须另有ops |
| `agent:insights:manage` | 7新增 | 作业启动/授权续期、分类纠错/合并拆分/重算；必须另有ops+content |

两新码是后台运营操作资格，不是业务使用权限，不加入`agent:business:*:use`，不恢复工具或Skill逐人授权，也不新建一个“后台业务”去套图运行entitlement。

真实IAM自有测试环境步骤：通过已授权平台管理接口注册目录项→企业可授予范围→企业角色授予→测试成员绑定→重新内省读回精确码→确认移除后下一请求403。测试root和正式root不同，不复制正式口令或使用源码固定密码。真实IAM环境无法配齐时，不可把mock令牌测试记作授权配置通过；本地纯功能测试可以继续。

未授新码的正式用户（含root）不能写对应新功能。生产配置列入发布清单，由已有授权的管理员按正常界面/API执行并审计；不因先前root三业务配置而自动授予未来后台写权限。
