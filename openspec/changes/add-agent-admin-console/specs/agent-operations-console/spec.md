# Spec Delta

## Purpose

让企业运营人员在同一个中文后台连续完成使用情况查看、异常定位、运行下钻和反馈处理。界面复用既有会话与企业切换，清晰区分真实零值、数据缺失、权限拒绝及服务故障，避免后台展示成为身份和正文保护的旁路。

## ADDED Requirements

### Requirement: 单一运营后台与身份管理分工
系统 SHALL 提供总览、用户用量、对话运行、反馈处理、业务能力、性能与成本入口，并保留统一身份管理跳转。页面 SHALL 按当前有效权限展示，用户、企业、部门和角色管理仍由IAM提供；需求洞察作为同一后台的可扩展模块。

#### Scenario: 统计角色进入后台
- **WHEN** 企业成员仅有统计读取权
- **THEN** 可查看授权聚合页面，不能进入其他用户运行或正文，直接API访问同样拒绝

#### Scenario: 动态业务目录
- **WHEN** 新业务图完成注册，或历史图已退役但仍有可读记录
- **THEN** 当前筛选与历史记录可解释地展示，不依赖固定三项或六项页面数组

### Requirement: 一致筛选与可追溯下钻
系统 SHALL 在各页面提供明确的业务日窗口、适用维度、分页和回到来源列表的路径。共享过滤条件应一致传递；不支持的过滤必须拒绝或明确显示，不能静默忽略。敏感原文与自由文本检索内容 MUST NOT 进入URL、分析事件或普通日志。

#### Scenario: 总览进入异常明细
- **WHEN** 用户点击某业务的失败运行数量
- **THEN** 明细沿用相同业务、窗口和状态口径，并说明attempt与逻辑问题的数量差别

### Requirement: 企业上下文与迟到结果隔离
系统 SHALL 按用户、企业、context_version、请求代次和筛选隔离页面数据与缓存。切换、撤权或退出时清除旧明细与正文；A到B再到A也不能接收原A请求的迟到结果。

#### Scenario: 切换后旧正文迟到
- **WHEN** A企业正文读取未完成时切到B，再返回A
- **THEN** 旧响应不显示，重新授权的新请求才可填充正文

### Requirement: 完整状态与可访问交互
页面 SHALL 提供加载、无数据、无结果、部分失败、未采集、过期和无权限状态，保留稳定布局及恢复路径。交互 SHALL 支持键盘、中文输入法、可访问名称和窄屏；表格有有界导航，错误不以零值或空列表替代。

#### Scenario: 输入法与慢查询
- **WHEN** 用户组合输入中文并快速修改筛选，服务端旧查询较晚返回
- **THEN** 组合期间不提前提交，清除操作立即生效，旧查询不覆盖新结果

#### Scenario: 桌面与窄屏
- **WHEN** 用键盘及390像素宽窗口查看运行、展开详情并返回
- **THEN** 企业选择与主要操作可用、焦点可见并恢复，表格不撑破全页

### Requirement: Langfuse复用与访问边界
系统 SHALL 通过已授权运行映射提供受控Trace信息及同步状态。共享Langfuse项目 MUST NOT 向企业用户提供控制台旁路或凭据；评测集、评分及版本实验使用Langfuse现成功能，不在本后台另建评测平台。

#### Scenario: 共享项目Trace详情
- **WHEN** 企业运营人员打开已授权Trace且外部服务不可用
- **THEN** 本地运行仍可查看，Trace标为暂不可用；不回退共享控制台直链，不暴露其他企业数据
