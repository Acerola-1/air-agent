# 前后端消息流与上下文治理设计

## Context

现状与失败样本见 `docs/reviews/2026-10-11-langgraph-frontend-backend-assessment.md`。三个显式图共享 ToolNode 包装器，手动绑定模型工具；前端以 values.messages 重建历史并无差别追加 messages 增量。现有 PG 归档表缺少归属、保留期和处理状态。quickjs-rs 0.2.5 已锁定且本地完整数据探针通过。参见 proposal.md 的范围与确认决策。

## Goals / Non-Goals

**Goals:** 完整数据依据、可恢复的摘要覆盖、完整请求预算、唯一终答和真实运行状态；新增代码可针对失败样本验收。

**Non-Goals:** 不迁移图到 DeepAgents、不开放通用 OS 沙箱、不展示或编辑内部历史摘要、不修改无关分析技能或部署产品、不自动提交或发布。

## Decisions

### 1. 保留聊天历史，独立投影模型上下文

继续让平台 checkpointer 保存完整 messages，新增 `summary_covered_message_id` 水位、摘要和最近 `context_metrics`。所有意图在模型准备前共同处理摘要；仅归纳水位之后且早于最近三轮的新消息，按整轮推进。旧线程无水位时不能仅凭旧 summary 排除历史，先安全重新建立覆盖。成功摘要后持久化水位；失败保持旧水位。调用模型时仅过滤已覆盖消息并注入摘要，其余按轮次保护 tool_call_id 闭合。替代方案“直接 RemoveMessage”会破坏当前历史读取，暂不采用。

### 2. 完整模型预算与模型选择

增加共享预算工具，内容、reasoning、工具调用参数、系统提示、工具定义和生成预留全部计入。主模型保持现有配置；摘要模型新增独立名称／地址／密钥覆盖（未配置复用主通道）、窗口、输出和安全余量。优先可用 tokenizer，可通过独立编码配置指定匹配 tokenizer；未知别名使用区分 ASCII／中日韩／其他 Unicode 且默认乘以 1.25 余量的多语言近似，并标明估算来源。此前 UTF-8 字节上界在专家模式普通查询中导致错误拒绝，已改为合理近似；近似不保证严格数学上界，另保留窗口安全余量，提供商 usage 单独展示。工具 schema 保留名称、类型、必需参数与枚举／数值约束，仅按可配置上限精简冗长 description 和 examples；按实际绑定的 schema 计量，执行工具仍由原始验证器校验。可精简时以工具定义占预算 40% 为目标，给 ReAct 后续工具结果留空间；参数约束优先于目标占比。页面以 ≈ 区分估算并提供规则／聊天结果／工具定义／请求开销的拆分。执行最终校验；仍超限时返回可读未完成信息，不能“当前轮豁免”后无限放行。上下文指标记录实际或估算来源、窗口、输入预算、输入估算、输出预留、最新 usage，区分费用用量与工作上下文。

### 3. 结构化数据与 QuickJS 工具

超限工具载荷先可靠归档；解析完整 JSON，提取字段、数据路径、总记录数与小样本，在 ToolMessage.content 返回小型 manifest 与 artifact_id。新增 `compute_artifact(artifact_id, code)` 工具；读取时校验当前 run 的用户和线程，宿主向公共 `quickjs_rs.Runtime` 注入原始 JSON 字符串，模型只生成代码，不重复传原始数据。每次计算新建执行域，不使用中间件私有 registry 或跨轮 heap 快照；在隔离 worker 执行并有外层等待与取消回收。输入字节、heap、执行时间、结果字节、重试次数均有配额。输出包含来源、完整输入记录数、计算范围和覆盖状态；过大结果归档为派生记录或明确拒绝，禁止截断 JSON 后标成功。

执行提示约定数据变量与字段，提供固定污染等级函数（按照仓库规则区分因子、日／小时与新旧日期）及通用受测试的遍历、过滤、统计辅助。模型可生成针对当前问题的只读代码；保留代码摘要、版本、原始归档关联与计算结果用于复核。至多一次错误修正，同一数据整理阶段默认 90 秒，单次 JS 5 秒／64 MiB。对不能完整加载的资料使用有配额的分块全量处理或明确未完成，不能默默取前缀。先采用公共 Runtime 封装工具，避免 PTC 绕过现有工具治理；需要多步 REPL 的独立计算子图不属于本次必要结构。

### 4. 非结构化数据与摘要失败

摘要输入按专用模型实际可用预算分块，逐批处理完整输入，再在有界预算内逐级合并；不能在一次合并中再次塞入全部大摘要。每块记录字符范围、成功状态；任何块失败都不输出“未包含目标”或“完整摘要”。所有内部模型调用加 `nostream` 标签。摘要输出需要长度／类型检查，失败不推进历史覆盖；错误载荷先判断业务失败，不能当普通数据摘要。

### 5. 原始与派生归档生命周期

对现有表做加列兼容迁移：user_id、thread_id、run_id、parent_artifact_id、kind、status、expires_at、processing_metadata；原始全文保持权威来源，摘要与派生结果关联保存。psycopg 显式使用已锁定 3.3.4 的 binary extra，消除本机缺 libpq 的安装差异，其他依赖版本保持。生产 DATABASE_URI 指定 PG 时写入失败明确失败，不静默写容器内临时 SQLite；开发未配置 PG 才用 SQLite。后台有界清理过期载荷，读取也检查过期；默认 30 天，0 可代表显式关闭自动过期。旧记录保留但不授权读取。关联归档读取／分页经认证同源接口，服务器从已验证会话派生 user_id；运行和线程的 user_id 也由代理注入并校验 metadata 归属。删除线程必须在服务端校验所有权并清理关联归档，重复清理幂等。

### 6. 事件与前端状态契约

增加版本化 `context_status`／`context_metrics`／`tool_status` 事件（携带 run/thread 身份，工具事件带 tool_call_id）；压缩和计算有 started/completed/failed。metrics 同时保存在图 state，刷新可恢复。最终可见 AIMessage 增加 `ui_visible` 标记，处理历史兼容时仅接受不含 tool_calls 的旧终答。主模型内部输出先缓冲确认是否终答，确认后通过 `final_output_done` 发布；data-analysis 清洗阶段先缓冲完整文本，经同一终答校验后用 final_output_done 发布，失败仅发布可读降级说明，同轮原稿用稳定 ID 替换。不要发布未确认的工具调用轮正文。

前端 API 层读取完整 state，订阅 custom／values／messages／error；store 以每次运行 generation、thread_id 和 run_id 防止过期结果。内部 messages 不追加正文，只用于已确认的工具／终答状态；正文由可见终答及 final_output 事件驱动。停止使用 SDK cancel 管理 run_id，代理转发 request signal；完成／取消／错误保留确认内容，重新拉取状态。工具诊断主动展开才显示 JSON，归档徽标只有实际成功时出现并提供回读。历史整理只显示状态与用量，不显示 summary 字段。使用当前组件与 tokens，补共享 DESIGN.md/UX-CONTRACT.md 记录稳定行为。

### 7. 实施与验收凭据

先做故障样本回归，再后端存储／模型／工具、图接线、前端契约与真实验收。测试登录用户名为 admin，密码使用用户在本轮对话明确提供的测试凭据，任何仓库文件、测试快照、截图、日志不保存密码。只对本地测试站点登录，不创建新账号、不修改认证配置。

## Risks / Trade-offs

- 初次大 JSON 解析与沙箱启动有成本 → 原文以字符串注入、明确配额、测量真实链路，不承诺纯计算探针耗时代表总时延。
- 模型代码可能选错字段或单位 → 固定业务函数、完整数据 manifest、范围和结果断言、不同形态样本验收；无法核验就标未完成。
- 终答身份需等待模型工具决策 → 不公开未经确认的草稿；状态提示覆盖等待，data-analysis 清洗草稿同样缓冲，避免清洗失败或返回 JSON 时短暂泄露。
- 完整聊天 state 仍增长 → 本次不删历史；模型投影与数据外置降低工作输入，后续存储策略应单独验证。
- 现有容器服务曾不可达 → 在实施时重查；不能用模拟 PG 或未登录截图替代真实验收。

## Migration Plan

增量添加表列与 state 字段，保持旧线程加载；新参数默认保守并写入 .env.example。真实部署仍使用项目 Apple Container 流程与源码挂载，不改其他服务的数据。失败可停用计算能力回到明确的数据不足行为，绝不回到前缀假完整。回滚代码保留已添加的兼容列和归档，不执行破坏性迁移。未完成真实验收前不归档本变更。
