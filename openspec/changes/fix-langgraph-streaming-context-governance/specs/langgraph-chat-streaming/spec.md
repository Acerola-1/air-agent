# langgraph-chat-streaming 规格增量

## Purpose

为三个显式业务图建立稳定的用户可见消息与运行状态契约，使回答正文、工具诊断和内部计算互不混淆，并在刷新、取消和切换会话时保持一致。

## ADDED Requirements

### Requirement: 消息分类与唯一正文

系统 SHALL 仅展示标记为用户可见的终答正文。工具消息、调用计划、摘要模型与计算草稿 MUST NOT 进入正文；工具失败说明和主动展开的诊断详情 SHALL 保留。

#### Scenario: 工具错误不闪现

- **WHEN** 工具返回参数错误 JSON，随后收到完整状态
- **THEN** 任何增量帧及快照正文都不出现该 JSON，工具卡显示失败，展开可查看诊断

#### Scenario: 内部输出隔离

- **WHEN** 历史摘要或代码生成产生文本
- **THEN** 该文本不进入正文、复制终答或历史终答列表

### Requirement: 运行身份与状态恢复

系统 SHALL 以会话和运行身份隔离异步结果，处理流内错误、中断、取消和完成；重新打开线程 SHALL 恢复上下文统计与整理状态。

#### Scenario: 过期回调

- **WHEN** 用户切换线程后旧运行结束
- **THEN** 旧回调不修改新线程消息、错误、生成标记或取消句柄

#### Scenario: 运行取消

- **WHEN** 用户点击停止
- **THEN** 后端运行收到取消请求，部分确认内容保留，界面停止，重复取消幂等

#### Scenario: 流内错误

- **WHEN** 服务器通过流事件返回运行失败
- **THEN** 显示可读错误与恢复入口，不把失败当成功

### Requirement: 用户可见整理状态

系统 SHALL 显示历史整理与数据计算的进行中、完成、失败，以及上下文用量变化和实际保留轮次；MUST NOT 展示或编辑内部历史摘要。

#### Scenario: 整理结束

- **WHEN** 整理完成或失败
- **THEN** 状态记录保留可辨识结果，容量使用后端统计，失败不声称已成功整理
