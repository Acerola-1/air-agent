# 企业 MCP 业务平台授权

## Purpose

让多个企业共用同一 MCP 业务平台时，每次工具发现与执行均使用已验证的企业或成员授权身份，明确凭据和外部主体的来源，并在并发、重试、轮换或权限失效时保持数据与身份隔离。

## ADDED Requirements

### Requirement: 已验证外部授权契约与身份绑定

系统 SHALL 按可信企业/成员解析统一平台的授权绑定和外部主体，只有核验过的认证协议及有效绑定可以发起企业 MCP 调用；协议、凭据或绑定缺失时必须安全拒绝，不采用全局匿名兜底。

#### Scenario: 未提供生产授权契约
- **WHEN** 只能确认平台匿名调用成功，无法证明企业认证或数据约束
- **THEN** 系统保持企业 MCP 禁用并说明授权不可用，不能宣称跨企业隔离已通过

#### Scenario: A/B 独立授权
- **WHEN** A/B 企业使用同一工具服务发起已授权查询
- **THEN** 各自使用已绑定外部身份，实际结果遵循该平台对应授权范围

#### Scenario: 绑定缺失或失效
- **WHEN** A 的绑定停用、凭据不可用或身份依赖失败
- **THEN** A 调用被拒绝，不使用 B 或旧全局身份代替

### Requirement: 主体参数与凭据由服务器注入

系统 SHALL 依据已验证工具契约设置认证证明和调用主体；模型或客户端不得决定企业/成员授权身份，业务查询对象与授权主体必须区分，实际凭据仅在受保护发送边界使用。

#### Scenario: 模型伪造 userId
- **WHEN** A 运行生成了指向 B 授权主体的工具参数
- **THEN** 系统拒绝或按验证契约覆盖为 A 的真实主体，不更改合法业务目标参数

#### Scenario: 查看错误、配置与 Trace
- **WHEN** 调用失败或用户查看运行记录和诊断
- **THEN** headers、token、密码和凭据值不出现在模型消息、checkpoint、响应或 Trace

### Requirement: 披露和实际执行均校验权限

系统 SHALL 仅披露当前成员可用的 MCP 能力，并在实际执行与重试前检查工具、图和成员授权；仅靠模型提示、Skill 文本或前端选择不能授予权限。

#### Scenario: 越权工具调用
- **WHEN** 任一公开图产生未授权工具的调用，即使工具 schema 未展示
- **THEN** 执行前拒绝且不向 MCP 发送请求

#### Scenario: 授权在重试前撤销
- **WHEN** 第一次调用失败后成员权限或绑定被撤销
- **THEN** 下一次重试不发送，不能复用旧许可继续执行

### Requirement: 认证状态与缓存并发隔离

系统 SHALL 按企业、外部主体授权范围和绑定版本隔离 MCP 连接身份、发现结果、退避和数据缓存；并发请求不得通过修改全局环境或 headers 注入请求凭据。

#### Scenario: A/B 屏障并发
- **WHEN** A/B 同时初始化并调用同名工具，其中 A 延迟或失败
- **THEN** 请求认证、返回结果及重试始终属于各自身份，B 不受 A 的身份状态影响

#### Scenario: 同一用户的两企业与凭据轮换
- **WHEN** 同一用户的 A/B 运行并发，随后 A 绑定轮换
- **THEN** 缓存与客户端不因相同 user_id 混用，新 A 调用使用新绑定，B 绑定保持

### Requirement: 绑定管理和验证证据可追溯

系统 SHALL 限定外部授权绑定的管理权限并审计变更，只公开引用和脱敏状态；真实平台隔离验证必须与受控模拟验证区分，缺少真实证明时不得标记相关验收完成。

#### Scenario: 企业管理员修改平台凭据
- **WHEN** 未获得绑定管理权限的企业管理员提交变更
- **THEN** 系统拒绝，不因普通角色管理权限允许改动外部授权

#### Scenario: 只有模拟测试通过
- **WHEN** 受控 A/B MCP 测试通过而真实平台凭据/样本缺失
- **THEN** 报告明确模拟范围及缺失材料，真实验收任务保持未完成
