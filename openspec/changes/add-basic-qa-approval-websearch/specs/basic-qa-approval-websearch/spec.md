# Spec Delta

## Purpose

约束 Basic QA 在现有 MCP 与知识库之外，按用户逐轮批准使用外部联网搜索补充数据的行为，包括审批、预算、恢复、来源引用、数据权威边界与审计。

## ADDED Requirements

### Requirement: 单一联网搜索入口
Basic QA SHALL 只向模型披露一个联网搜索工具 `web_search`，MUST NOT 再披露或执行 Serper 或其他搜索工具；其他图不受本能力影响。

#### Scenario: 模型工具列表
- **WHEN** Basic QA 为规划请求构造工具定义
- **THEN** 工具列表中最多出现一个 `web_search`，不存在 `websearch_tool` 或第二搜索入口

#### Scenario: 旧调用被拒绝
- **WHEN** 模型或旧客户端尝试调用已退役的 Serper 工具
- **THEN** 执行层拒绝该调用并返回不可用，不发出任何外部搜索请求

#### Scenario: 其他图保持原状
- **WHEN** 检查 data-analysis 或 intelligent-tracing 的工具配置
- **THEN** 不因本能力新增或移除联网搜索入口

### Requirement: 人工审批与每轮搜索预算
每次用户问题触发的运行中，第一次 `web_search` SHALL 通过用户审批后才可外呼；一次批准覆盖本轮最多 3 次外呼，失败与超时同样计入 3 次硬上限；拒绝后本轮 MUST NOT 再次弹窗或外呼；新的用户问题重置额度。

#### Scenario: 批准后使用额度
- **WHEN** 用户批准第一次搜索，模型随后再次请求搜索且已用次数小于 3
- **THEN** 后续搜索不再弹窗，直接外呼，并在每次外呼后递增已用次数

#### Scenario: 拒绝
- **WHEN** 用户在审批弹窗选择禁止
- **THEN** 本轮所有后续搜索请求直接返回不可得，不再弹窗、不发出外部请求

#### Scenario: 失败也计数
- **WHEN** 已批准的一次搜索超时或返回错误
- **THEN** 已用次数仍加 1，不自动重试，后续搜索继续受剩余额度约束

#### Scenario: 额度用尽
- **WHEN** 已用次数达到 3 后模型再次请求搜索
- **THEN** 不弹窗、不发出外部请求，直接返回不可得

#### Scenario: 新问题重置
- **WHEN** 用户发送新的问题并在需要时申请搜索
- **THEN** 新运行的已用次数从 0 开始，并重新触发一次审批

### Requirement: 审批中断与恢复
审批 SHALL 在独立的 gate 节点通过 LangGraph `interrupt()` 实现；interrupt 之前 MUST NOT 有外部调用或状态写入；恢复值只接受批准与否，恢复时 MUST 只重跑 gate，不重新执行已完成的工具调用。

#### Scenario: 恢复只重跑 gate
- **WHEN** 用户批准后图从 checkpoint 恢复
- **THEN** 只有 gate 节点重新执行并发出搜索，规划节点和此前已完成的工具调用不重复执行

#### Scenario: 刷新后仍可审批
- **WHEN** 用户在审批等待期间刷新页面
- **THEN** 从线程状态读取未完成的中断并重新显示同一审批弹窗，批准或禁止后仍能恢复原运行

#### Scenario: 等待中停止
- **WHEN** 用户在审批等待期间点击停止
- **THEN** 本次运行按拒绝收尾，不发出搜索请求，不把未确认状态显示为已完成

#### Scenario: 不自动超时
- **WHEN** 用户长时间不操作审批弹窗
- **THEN** 运行保持等待，不自动批准、不自动拒绝，也不产生后台定时器

### Requirement: 来源编号与引用输出
联网结果 SHALL 由服务端按唯一 URL 分配连续编号 `[web:n]`；回答中的联网内容 MUST 使用已分配的角标，并在文末输出“互联网来源”列表，包含标题、站点、URL 与检索日期；知识库引用 MUST 继续使用独立格式，不得与联网来源混用编号。

#### Scenario: 多来源引用
- **WHEN** 回答使用了两个不同网页来源
- **THEN** 正文出现 `[web:1]`、`[web:2]`，文末列出两条来源，编号与正文一致

#### Scenario: 重复 URL
- **WHEN** 多次搜索命中同一 URL
- **THEN** 该 URL 只占一个编号，不重复列出

#### Scenario: 未知编号
- **WHEN** 模型引用了未分配的 `[web:n]`
- **THEN** 服务端不把它渲染为来源，文末不生成对应条目，回答不得声称存在该来源

#### Scenario: 与知识引用共存
- **WHEN** 同一回答同时包含知识库引用和网页来源
- **THEN** 两种引用分别渲染，编号空间互不影响

### Requirement: 联网数据的补充边界
联网搜索 SHALL 只用于补充 MCP 与知识库未取得的数据，包括政策公告、新闻背景和缺失的数字；同一数据冲突时 MUST 以 MCP 或知识库为准；网页数字 MUST 带来源与时间，MUST NOT 伪装成监测数据。

#### Scenario: 与 MCP 数据冲突
- **WHEN** 联网结果与已取得的 MCP 监测数据在同一对象和时间上不一致
- **THEN** 回答采用 MCP 数据，联网内容仅作补充或省略，并说明来源差异

#### Scenario: 自有数据缺失
- **WHEN** MCP 与知识库都没有用户需要的数据，联网结果提供了可用数字
- **THEN** 回答可呈现该数字，但必须标注互联网来源与检索时间，并说明不是本系统监测数据

#### Scenario: 法规限值
- **WHEN** 用户询问具体法规、标准条款或限值
- **THEN** 仍须使用知识库检索与 citation，不得用网页结果替代

### Requirement: 拒绝与失败的用户话术
用户拒绝、额度用尽或搜索失败时，回答 MUST 继续基于现有数据组织，并只用业务语言说明部分数据暂时无法获取；MUST NOT 提及审批、拒绝、额度或外部服务错误，也不得编造缺失数据。

#### Scenario: 拒绝后的回答
- **WHEN** 用户拒绝联网且在审批前已获得部分数据
- **THEN** 回答基于已有数据完成，并说明“部分数据暂时无法获取，无法进一步分析”，不出现“未批准”“审批”等字样

#### Scenario: 搜索失败后的回答
- **WHEN** 已批准的搜索超时或返回错误
- **THEN** 回答按同样通用话术说明数据不可得，不暴露服务名、状态码或重试细节

#### Scenario: 额度用尽后的回答
- **WHEN** 3 次额度已用尽仍有数据缺口
- **THEN** 回答停止尝试并说明数据暂不可得，不请求第四次

### Requirement: 隐私、审计与成本
审批弹窗 SHALL 明示外部提供方、拟发送的查询词与本轮剩余额度，用户主动批准后才可外发；系统 MUST 记录批准、拒绝、每次外呼与剩余额度，网页搜索费用 MUST 作为外部工具成本单列，且不得记录或回显密钥。

#### Scenario: 弹窗内容
- **WHEN** 首次搜索触发审批
- **THEN** 弹窗展示提供方、查询词、检索理由与剩余额度，仅提供“批准”和“禁止”两个操作

#### Scenario: 审计记录
- **WHEN** 用户批准或拒绝
- **THEN** 台账记录对应决定、运行归属与时间；后续每次外呼记录调用事实与已用次数

#### Scenario: 成本记录
- **WHEN** 一次搜索返回 HTTP 200 且结果非空
- **THEN** 记录 0.005 元外部工具费用并标明来源，不伪造模型 token usage

#### Scenario: 未产生可计费结果
- **WHEN** 一次搜索失败、超时或返回空结果
- **THEN** 已用次数仍加 1，外部工具费用记 0

#### Scenario: 密钥保护
- **WHEN** 搜索客户端配置或报错
- **THEN** 日志、事件与回答中不出现 API 密钥或完整请求头

### Requirement: 提示词规则
Basic QA 系统提示 SHALL 通过一段独立、可拼接的文本声明联网搜索的适用条件与禁止条件，且 MUST 与数据缺失处理、引用规则保持一致。

#### Scenario: 允许申请
- **WHEN** 问题涉及政策公告、新闻背景，或 MCP 与知识库无法取得的数据
- **THEN** 提示允许模型调用 `web_search` 并说明缺口，不得自行假定数据

#### Scenario: 禁止申请
- **WHEN** 所需数据已能由 MCP 或知识库取得
- **THEN** 提示要求先使用现有工具，不得用联网搜索替代或绕过权限

#### Scenario: 引用要求
- **WHEN** 模型使用联网结果组织回答
- **THEN** 提示要求使用服务端分配的 `[web:n]` 角标，并在文末保留互联网来源列表
