# Proposal

## Why

溯源当前按分析时段取数，却在同一快照查找前七天基线；基础事实依赖异常检出，且气象时效、网格时空语义不完整，造成有数据仍缺少可用结论。需要按站点历史、气象、排放源、轨迹及卫星四步建立可验证的数据和结论链，避免把流程跑通当成污染诊断正确。

## What Changes

- 第一步：显式规划目标、基线、滑动统计所需时间窗口，分开记录覆盖与缺失；保留无基线时仍可验证的峰值、均值、范围、首末变化，区分未知与无异常。
- 第二步：修正现有 MCP 气象来源、起报及有效时间的归一化；观测优先且不冒充观测。网格按同一时刻和真实几何分析，邻站按距离与覆盖选择，不把不同时刻峰值拼成连片污染。
- 第三步：逐步接入获授权的企业/排口底图、CEMS/工况，生成带支持/反证的核查线索；清单年份、版本、范围与排放指标须明确，不能把许可量、排口颗粒物当环境 PM2.5 贡献。
- 第四步：独立建设并验收轨迹与火点/卫星证据，记录气象驱动、时空分辨率和不确定性；旧不可用轨迹/PSCF MCP 保持禁用，实际启用须完成连接、业务白名单及发布规格协调。
- 报告按观测事实、统计异常、空间气象、过程解释、待核查线索分层；缺少一类证据只降级依赖该证据的结论。保留确定性证据门禁、身份/租户/运行/删除边界。
- 用户确认目前只有现有业务 MCP：首批实施第一步与第二步现有渠道内的修复；第三、四步保留完整交付任务和真实数据验收依赖，不能用 mock 或未知来源冒充接入完成。

## Capabilities

### New Capabilities

- `tracing-data-products`: 四类数据产品的时间计划、覆盖、来源、授权及接入生命周期。
- `tracing-layered-evidence`: 观测、异常、气象空间与来源线索的独立证据要求、报告及验收。

### Modified Capabilities

无。本轮不改变已有 `agent-business-access`、`agent-service-connections` 的授权规则；溯源主规格尚未归档，新增行为由独立 delta 管理，并在启用轨迹等后续阶段前协调相关活动 change。

## Impact

主要涉及 `src/intelligent_tracing/{data_access,schemas,evaluation,station_analysis,spatial_analysis,claims,gate,meteo_analysis}.py`、本域测试和使用指南。既有主图/四专员、会话路由及统一终答出口保持；首批不改前端、IAM、RAG、数据库结构或依赖锁，保留其他任务的未提交改动。外部接入仅从受保护配置及有效授权取得，新增连接、依赖或模型运行需要按对应阶段验证；不提交、不推送、不部署、不归档。
