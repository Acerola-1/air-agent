# Proposal

## Why

需要一套可重复执行的本机并发压力测试流程，衡量当前模型和部署下同时处理独立问题的能力，并保存可比较的时延、吞吐、成功率和资源证据。

## What Changes

- 唯一入口为 `docs/performance/pressure-testing-workflow.md`，流程为冻结条件、正常问答与预热、阶梯持续升压、相邻边界复测、报告与归档。
- 默认测真实模型端到端闭环并发，上游和平台模拟作为可选诊断。
- 资源保护、实际授权、预算、独立线程、正文与可信完成校验继续有效；区分本机/发压器限制和产品 SLO 失败。
- 提供可复制计划与报告模板，首正文、完整时延、成功率、成功吞吐及观测覆盖可复算；后续按真实执行时间保存轮次。
- 默认闭环专项与按需开放到达/长稳/故障/浏览器扩展分开，不夸大短测结论。保持上游物理模型并发和产品问题并发的区分。
- 按时间保存每轮冻结计划、实际条件和原始明细，维护结果索引及可复用题库。

## Capabilities

### New Capabilities

- `model-capacity-evaluation`：本机真实 Agent 闭环并发计划、执行约束、边界与证据报告。

### Modified Capabilities

无。

## Impact

流程和模板位于 `docs/performance/`，执行规则由 `model-capacity-evaluation` 规格约束。执行器复用发送/SSE/台账解析和资源监督模块；Locust 产品适配器待实现与验收。文档、受控工具验收和真实容量结果分别记录状态。
