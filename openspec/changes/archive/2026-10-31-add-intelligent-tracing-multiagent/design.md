# 智能溯源多 Agent 设计

## Context

修订日期为 2026-10-19。当前 `dev` HEAD 为 `6ff95dd872300f8dfdb8dfcf4a4ab99e63cf5706`，三图收敛已提交；溯源图仍是通用 DeepAgents 装配。此前“图收敛未提交”的描述已过时，实施者仍须先读取实际 HEAD、diff、`langgraph.json` 和正式运行态。

主环境 deepagents 为 0.7.5；独立升级环境 `/tmp/air-agent-upgrade` 为 0.7.28。升级 change 已记录依赖锁、导入、空库和容器调查，但真实模型、实际追踪、存量 checkpoint 与回滚等任务仍未闭环。本设计不修改或重写它的历史证据。

MCP 数据能力来自 2026-10-18 探针记录，后续对站点/网格/气象有效响应另做当前授权下的验证；不重试用户已停用的轨迹/PSCF，也不推断其服务端实现。

## Goals / Non-Goals

**Goals**

1. 先实现 PM2.5 的请求解析、取数、质控、分析、证据、报告和回读闭环。
2. 学习 DeepAgents 委派、`CompiledSubAgent`、隔离上下文、结构化回传和中间件实际覆盖。
3. 将空间分布与过程解释分开，输出支持证据、反证和限制，不把关联写成因果。
4. 以确定性 allowlist 和可信证据约束所有用户可见输出。
5. 用可复现析因实验区分编排收益与 LLM 审查收益。

**Non-Goals**

- 不调用、探测或修复轨迹/PSCF，不新增轨迹专员、ERA5/HYSPLIT、企业清单或组分数据。
- 不确认具体污染源、源类贡献、二次生成占比、VOCs 敏感性或因果归因。
- 不新增 GIS 页面、graph ID 或公共事件类型，不改其他图和现行权限语义。
- 不把 `include_tools`、`fork` 或自由代码执行纳入业务主链。

## Decisions

### D1. 固定版本，分开升级与业务验收

业务目标固定为 Python 3.13 + deepagents 0.7.28；完整包版本以升级 change 验收的 `uv.lock` 为准，不能只换 SDK 或把 0.7.5 结果算作目标版本结果。

| 关口 | 可开展工作 | 必须有的证据 |
|---|---|---|
| G0 独立研发 | 0.7.28 独立环境上的纯函数、fixture、fake model、并行和恢复测试 | 解释器、包版本、源码基线及锁摘要；不启动正式库迁移 |
| G1 正式配置联调 | 新版本上的官方 API/持久化与真实模型/MCP 闭环 | 升级 change 当前基线的真实模型、三图注册、观测/出网、镜像、空库及存量迁移/回滚证据；未完成项有明确处置 |
| G2 PM2.5 验收 | PM2.5 可交付，随后实施其他污染物 | 本 change 关键指标、真实 SDK/浏览器及回读证据；模拟结果与真实证据分开 |

升级 change 的旧六图、旧模型地址、历史临时库不适用于现用环境；实施前按 `langgraph.json` 和 `docs/CURRENT-RUNTIME.md` 重新核实。依赖锁/镜像修订归升级 change 单独审查，不和业务 diff 混记。升级未就绪时继续 G0，不静默回退版本、不替换正式运行态。QuickJS 等升级剩余项目仍留在升级 change；溯源不使用自由执行不能据此替整个升级标记完成。

升级制品见 [proposal](../upgrade-deepagents-0.7.28/proposal.md)、[design](../upgrade-deepagents-0.7.28/design.md)、[tasks](../upgrade-deepagents-0.7.28/tasks.md) 和 [规格](../upgrade-deepagents-0.7.28/specs/runtime-dependency-baseline/spec.md)。其中当前规范仍写“六图”，属于待更正的活动要求；不能把规范文本直接当作历史结果忽略。G1 前须在升级 change 内追加当前基线说明、修正现行图清单要求并补验，保留原六图历史实测和事故记录。本次仅修订溯源计划，未替升级 change 完成这些事项。

### D2. 先冻结 TracingRequest，再进行数据委派

`TracingRequest` 是服务端校验的领域请求，不等同于自然语言、模型工具参数或身份声明。至少包含：

| 字段 | 语义 |
|---|---|
| `schema_version` | 请求结构版本，初始 `tracing-request-v1` |
| `analysis_id` / `revision` | 本次分析标识与单调修订，不替代 submission/attempt/run ID |
| `target` | 站点/区域的规范代码、坐标来源与已授权范围；名称不能作为唯一标识 |
| `pollutant` | 阶段一只允许 PM2.5，后续按已实现画像开放 |
| `time_window` | 带时区的起止、左闭右开边界、小时数据时间戳含义 |
| `neighbor_radius_km` | 明确调查半径；作为配置/用户输入，不解释为源距离 |
| `baseline_window` | 距平比较窗口；缺失或不足时不生成相对异常结论 |
| `analysis_policy_version` | 固定质控、异常、同步与风场规则版本 |
| `capability_snapshot_ref` | 已受理选择的可信引用，必须回读核对，不能从草稿拼接 |
| `parent_analysis_ref` | 可选；同线程追问来源及变更字段 |

身份、tenant/user/thread/graph、context_version、attempt 和执行 epoch 由可信运行上下文绑定；不允许模型或浏览器通过 `TracingRequest` 改写这些值。请求摘要使用规范序列化，不含凭据。

处理链：自然语言生成候选请求 -> 确定性字段/授权/版本校验 -> 站点消歧与时间确认 -> 冻结 -> 委派。必要字段缺失、同名多站、时间歧义时先用现有交互补问，不发起数据查询；模型不能默选另一个城市或放大半径。用户明确要求不可达能力时说明限制。

原生 `task` 参数只有 `description`、`subagent_type`，不会自动产生这些领域字段。确定性子图从受控父状态的已校验 `request` 读取；`description` 只携带分析引用和任务说明，不是事实或授权来源。复合工具传入的时间/站点必须与冻结请求或受验证的补查子请求一致。改变时间窗、半径或站点产生新 revision，重新计算所有依赖该字段的发现。

### D3. 四专员，数据计算与解释分层

| 专员 | 实现与职责 | 边界 |
|---|---|---|
| `station-data` | 确定性 LangGraph + `CompiledSubAgent`；站点、周边、质控、异常 | 零模型，只回写 `station_findings` |
| `grid-data` | 确定性 LangGraph + `CompiledSubAgent`；空间覆盖、热点、高值区 | 零模型，只回写 `grid_findings` |
| `meteo-analyst` | 隔离的声明式专员；选择补查、调用确定性气象/风场计算 | 不能自算数字，不能提升结论权限；只回写 `meteo_findings` |
| `evidence-reviewer` | 隔离的声明式专员；找反证、冲突、遗漏及表达风险 | 无数据/文件/执行工具；只回写 `evidence_review`，不作事实源 |

业务候选默认使用四角色并启用 reviewer；析因评测的 R=关闭仅消融 LLM 审查，确定性门禁始终保留，不改变角色边界。

lead 使用 `task`、受限规则读取和溯源专用画布发布入口；不直接持有 MCP 数据工具、不使用 unrestricted GP。删除轨迹专员及三个轨迹/PSCF 工具的装配，确定性能力状态始终记录 `trajectory_unavailable`，每次运行相关实际请求数必须为零。

`tools=[]` 不足以证明 reviewer 无工具：框架可能通过中间件注入文件工具，必须检查最终模型 schema 与真实 dispatch。可用最小 `create_agent` 编译为预编译专员，或用目标 SDK 支持的装配方式限制；业务四角色及 reviewer 的受限职责不变，不为凑声明式 API 留下旁路。lead 与其他专员同样检查默认文件工具/execute/GP，而不是只检查显式业务工具数组。

### D4. 明确状态通道、并行与证据存储

主状态至少包含 `messages`、`request`、四个专员结果、`capability_status`、`validated_report_ref`；若使用自定义 state，须满足目标 SDK `DeepAgentState` 的兼容要求。子图必须包含 `messages`；固定子图结果写 `structured_response` 后，框架将其序列化为父 `ToolMessage`，不会自动转成父 `station_findings`，后者须由子图显式返回或受控适配器写入。

0.7.5 的子图返回会回写未排除的继承状态；0.7.28 增加未变字段过滤，但不能依赖它解决所有共享写冲突。每个子图仅导出自己的结果字段，原始序列保留于子图私有状态或受作用域证据存储，不回写主状态。`request` 不允许子图改写；公共证据通过执行层注册，不让并行专员共同覆盖单个普通字典。

至少实测两个数据专员同轮并发、结果不同顺序到达、失败部分返回、两轮追问以及中断恢复。并发请求数、时间区间和序列化耗时都需记录。样本独立可取时并行；依赖站点坐标/范围解析的任务先等待请求规范化。

复合 `analyze_wind_relation` 在内部使用受作用域 MCP 执行与共享数据快照，不允许直接 HTTP 或裸 MCP 客户端绕过当前选择。其隐式依赖也纳入选择冲突检查；被排除的任一依赖实际外呼为零。缓存键包括授权范围、请求 revision、数据产品版本与参数；缓存命中仍实时复查权限。

### D5. 可信证据先注册，模型不能自证

每条 `EvidenceRecord` 由取数/分析执行层生成，至少记录：唯一 ID、analysis/revision、工具稳定 ID、规范参数摘要、数据产品与来源类型、抓取时间、有效时间/时区、单位、质量标志、样本数、原始数据摘要、算法/策略版本、派生父证据 ID。

模式产品另含起报时间、有效时间、预报时效；缺失则记录未知，不能改称观测。网格如果来自站点插值，记录同源关系；来源关系未知时不当成独立交叉验证。原始数据受既有权限/保留期限制，不把正文、凭据或大数组放入普通事件。内容哈希用于溯源，不是授权证明。

`Finding` 关联已注册证据 ID；`Claim` 包含 `type`、允许参数、支持证据、反证及限制。lead/reviewer 提交未知 ID、其他租户/线程/修订的 ID，或存在但不支持该命题的证据，均不能通过门禁。只有匹配来源、计算、时间、单位和语义规则的引用才有效。

### D6. 空间格局、过程解释和源类假设分别输出

- `spatial_pattern`：`isolated` / `multi_station_sync` / `regional_contiguous` / `mixed` / `unknown`，描述观测空间分布。
- `process_assessment`：`local_accumulation_consistent` / `transport_association` / `mixed` / `insufficient`，是有支持与反证的解释，不是因果确认。
- `source_hypotheses`：可为空。源类只能是明确标记“待核查、未识别”的调查假设，不进入正式结论或最高等级。

多站同步、连片高值仅支持区域现象；增加空间有序的上风向先升、合理传播时差及一致风场等证据，才允许“与传输相符”。仍需讨论共同静稳等替代解释。孤立异常先检查设备/缺测/微环境，不能直接认定局地排放。静风、风向不稳定、覆盖不足或明显反证时不强行给方向。

| 类别 | 允许结论 | 限制 |
|---|---|---|
| L1 | 异常/无异常、时段、幅度、空间分布 | 数据不足不能等同无异常 |
| L2 | 经规则验证的风向扇区、梯度、滞后关联 | 关联不等于来源或距离 |
| L3 | 区域同步/连片现象，或有附加证据的传输关联 | 不因 L3 自动获得全部 L2 命题；各 claim 独立校验 |
| L4 | 只在 `source_hypotheses` 表达待核查源类 | 不可达证据等级，不作源类识别 |
| L5/L6 | 当前无 | 不输出贡献率、归因概率、具体企业/排口认定 |

不输出模型自填 `confidence=medium` 或来源概率。样本完整率、同步率和统计不确定性可以在有证据时输出，不得与源贡献混淆。调查距离必须引用实际站点/网格几何或请求半径，不能由风玫瑰推导源距离。

### D7. 确定性 allowlist 门禁与统一发布

规则引擎从可信发现生成 `allowed_claims` 和固定 `limitations`。reviewer 只能指出问题或建议降级；不能增加证据等级、恢复排除能力或自行确认源类。

发布顺序固定为：注册证据 -> 计算发现 -> 规则生成允许结论 -> 可选 LLM 审查 -> 校验报告计划 -> 受控模板渲染 -> 生成不可变 `ValidatedReport` -> 聊天/画布/持久化发布。

报告计划只允许白名单章节、claim 类型、证据引用和受支持参数；事实句和假设标签用受控模板生成。自由文本不得新增事实或归因；难以确定性验证的任意模型段落不进入正式报告。模型的调查计划与反证建议可回流分析，但不能绕过这一渲染边界。非法计划不重试模型洗白，回退同一可信事实的受限模板。

`ValidatedReport` 包含 request/revision、证据与策略版本、审核结果、正文/画布内容摘要及 scope 绑定；该引用必须由服务端发布层生成，模型提供的 `validated=true` 无效。`limitations` 至少包含轨迹、清单和组分缺失，按实际再加样本/时间/覆盖等问题。拒绝说明“无法计算贡献率”及有来源的完整率百分比必须正常通过；禁词扫描不能替代语义 allowlist。

- 聊天：只从已验证报告推送 `final_output_delta` / `final_output_done`；之前允许现有进度事件，不推送草稿正文或子代理回答。
- 画布：溯源专用入口接收已验证引用与展示选项，服务端渲染内容；底层可复用 `create_artifact`，但 lead 不能直接提交任意 HTML/Markdown 绕过门禁。
- 持久化：正式报告/画布保存的是同一已验证版本；内部模型消息与原始证据受控保存且不能标为 `ui_visible`，不得进入普通事件或历史展示。
- 回读/恢复：按当前身份与删除状态校验 scope、request revision、内容摘要和门禁版本；旧版本不可验证时重新验证或仅展示明确受限状态，不回退未经验证的最后一条 AIMessage。
- 停止/删除：发布前重新检查执行 epoch、取消事实与墓碑；失败关闭，不由晚到子任务重新生成已删除报告。停止意图与已取消必须区分。

当前代码有 `common/output_contract.py:visible_result`，但不能把它当现成证据门禁；旧主规格提到的清理中间件与原始消息回退不是溯源的安全降级。溯源使用更严格的局部发布入口，不改变其他图。若通用清理模型仍被调用，必须在最后一次文本变化后重新验证。

### D8. 数据与分析策略

首先核对 `docs/domain/air-quality-level-reference.md`、平台字段定义、Skill 和测试。法规超标、平台等级、统计异常是不同字段；缺少阈值/版本/平均时间证据时，只能输出统计变化，不猜补新法规边界。

实施阶段先冻结 `analysis-policy-v1`，将下列配置的具体数值、公式、边界、依据和适用范围写入可版本化策略及 fixture 期望；没有该策略不得执行完整评测。研究启发式阈值必须标为未经过领域校准，不冒充法规或统计显著性。

| 分析 | 必须明确的口径 |
|---|---|
| 质控 | 逐字段哨兵/范围、去重、单位转换、整点对齐、完整率分母、最大连续缺口 |
| 异常 | 比较窗口、基线最小覆盖、距平/变化率公式、持续时长、零基线处理；超标倍数须有有效法规阈值 |
| 空间 | 邻站有效性、最小站数、同步定义和分母、热点/连片算法、插值同源处理 |
| 风场 | 气象来向、u/v 分量去向、角度圆周统计、静风阈值、扇区边界、配对容差、每扇区最低样本和覆盖 |
| 滞后 | 0–6h 搜索方向、有效样本门槛、去日周期/自相关影响、重复比较；不将最大相关系数称作因果或概率 |
| 过程 | 允许传输关联的组合证据、静稳等反证、缺测/冲突时的降级规则 |

`-1` 不能全局转缺失：pblh 的已知哨兵值按字段处理，u/v 分量的负值可合法；真实零浓度、零风速不能当缺测。历史 NWP 是模式输出，保留起报/有效时间/时效；小时气象中的 `pblh=-1` 不参与计算。无可用 pblh 时标 `pblh_unavailable`，不拿其他字段代替。

### D9. 分阶段污染物支持

阶段一完整实现并验收 PM2.5：小时过程为主；24h 滑动作为补充统计，不冒充自然日均或法规判断。阶段二在阶段一通过后逐项扩展 PM10、O3、NO2、SO2、CO，并增加各自样本及禁用推断。

O3 保留小时序列用于过程/风场分析，日最大 8h 用于适用的评价；必须定义跨日、缺测与有效性，不用单小时替代 8h 评价，也不只保留日值。跨污染物排序不得直接比较不同单位浓度；首要污染物只采用有口径证据的平台字段或合法计算。OX 等指标要先处理物质量单位，缺少条件则不计算。

### D10. 权限、观测与运行预算

每个 LLM 专员显式装配身份守卫、subagent 观测和摘要观测；摘要模型也是外呼，单独验证实时身份守卫与失败关闭。确定性图自行保证作用域 MCP 执行与工具观测。模型结构化失败可解析受限 JSON，但失败率计入评测，不把错误文本当有效发现。

有效许可为当前身份许可、受理快照、图/专员域白名单及复合工具依赖的交集。主图、真实子任务、补查、重试、恢复、规则文件读取同样受约束。不能用隐藏 schema 代替执行层授权。

子任务使用独立 child execution/observation 标识关联已有 request/submission/attempt/platform run，不为每次 `task` 凭空新建用户请求或顶层 attempt。复用现有观测/台账扩展，不新增公共事件；覆盖要求是从实际委派数可逐一关联开始/完成/失败/取消及工具调用，不能仅凭顶层 success 推断。

Langfuse 回调在原生 worker 恢复可信配置后的图工厂中按执行创建，不在受理钩子的 JSON 载荷内保存 Python 对象。trace ID 由企业与服务端受理 attempt 确定，同 thread 的不同 attempt 分开，恢复 submission 保留原 attempt 的 trace。主图、模型、工具和专员继承同一个回调；平台回调由框架合并，不重复复制。2026-10-22 用户明确修订需求后，Langfuse 保留 SDK 可见的完整图状态、模型消息、工具参数/结果、元数据及实际异常；移除正文 mask、OTel 属性白名单和异常跨度丢弃。SDK 应用根标记、可信用户/线程标识和固定图名继续保留。普通业务台账与本地日志的安全规则独立。验收同时检查唯一应用根、子节点父链和真实入库，不能仅以 trace ID 相同判定完整。

2026-10-22 用户明确只使用 Langfuse 后，运行配置关闭 LangSmith 追踪，启动预检拒绝重新启用；框架依赖库和 licensed 原生服务的开发启动授权保留。使用原样官方 `langfuse.langchain.CallbackHandler`，只在顶层注入，子节点由 SDK 继承。删除临时的 LangSmith 祖先桥接、SDK 子类与私有 exporter/mask 修改，不将双追踪兼容作为现行要求。可信 trace 属性在受理授权边界覆盖客户端同名字段；SDK 内仅使用官方 metadata/trace_context 和标准回调执行标志。验收覆盖 LangSmith 客户端零创建/写入、并发隔离、本地业务观测关联及实际 Langfuse 入库。

Users 以稳定用户 UUID 聚合，Sessions 以 thread ID 聚合；同线程多 attempt 分 trace、不分 session。三图均在执行期绑定属性，并用官方 `propagate_attributes` 覆盖子观测。原生工厂上下文按任务保存可重入作用域；直接流式入口在每次读取/关闭内进入并退出作用域，不能跨 `yield` 留下 OTel 属性。进程内传播不启用 HTTP baggage。可读账号来自已有票据绑定对应用户的 IAM 同步引用，读引用前设置事务本地用户 GUC，保留 FORCE RLS；该标签不作为授权依据，不新增表或迁移。引用缺失时忽略客户端同名字段及其 configurable 别名，观测上下文不从 metadata 兜底取账号。

实现前定义并记录每轮 task/补查/模型调用上限、并发上限、总超时及每工具重试策略；预算耗尽返回已验证部分结果与限制。确定性参数错误和权限失败不自动重试；轨迹/PSCF 永远零调用。局部失败可以降级，身份失效、后端不可用和删除状态不能作为普通缺测继续外呼。

### D11. 独立框架实验

`include_tools` 和 `fork` 是可选、默认关闭的隔离实验，只记录机制与实测结果，不改变主链许可或阶段一完成条件。

- `include_tools`：先用两个受控工具和一个 Skill 测读前/读后/上下文压缩后的披露、执行及撤销。核对实际 resolver 接线。`profile=None` 仅表示不能依赖原生中途 schema 披露；0.7.28 有普通绑定回退路径，是否适配当前模型需实测。
- `fork`：与相同任务的 isolated 模式比较上下文、Token、摘要和权限继承；确认敏感状态不扩散、原约束不放宽。不能因上下文方便替换业务的隔离模式。

独立实验的 fixture/真实模型结果分开记录。不再重做升级 change 已有的锁解析、镜像和通用 API 调查；升级 change 负责可运行基线，本 change 的实验负责机制学习。
