# 溯源多 Agent 评测与验收

业务可靠性、调查收益和框架学习分别报告。所有实验固定代码、完整依赖锁、数据快照、策略和输出 schema；不通过一次成功、OpenSpec strict 或 HTTP 200 宣称实现完成。

## 1. 依赖与证据层级

- G0：独立 Python 3.13/deepagents 0.7.28 环境，验证纯函数、fixture、fake model、原生 task 接口、并发和门禁。fake model 仅证明接线。
- G1：正式配置联调前引用 [升级 change](../upgrade-deepagents-0.7.28/tasks.md) 的当前三图、锁/镜像、真实模型、观测/出网与迁移/回滚验收；旧六图/旧地址只作历史。
- G2：PM2.5 真实 SDK、受授权 MCP、持久化和浏览器验收。控制服务、真实配置模型、真实外部数据和浏览器证据分别标注；服务不可用记未执行。
- 阶段二：PM2.5 通过后逐项扩展其他污染物。首阶段通过不等于整个 change 可归档。

原升级记录中的未完成项及事故处置不由本评测覆盖或自动关闭；不修改原报告或复用已退役资源。所有测试创建新资源并记录所有者与回收状态。

## 2. 最小架构 spike

```text
validated TracingRequest
  --> fake lead --> parallel task(station-data, grid-data)
  --> compiled fixture graphs --> structured summaries + owned result fields
  --> reviewer fixture --> deterministic allowlist + evidence references
  --> ValidatedReport --> chat / canvas / persisted reread
```

至少验证：

1. 原生 task 只有 description/type，子图实际读取冻结请求；无字段时不猜测。
2. structured_response 序列化为 ToolMessage，父 findings 另行正确写入；零原始数组回传。
3. 两子图同轮真实并发、反序完成及一方失败；无共享状态冲突或重复累加。
4. 同线程第二轮修改半径/时间产生新修订；旧结果迟到与恢复均不覆盖新结果。
5. 伪造证据 ID、存在但不支持的证据、无禁词归因、画布旁路和历史原始消息回退均失败。
6. 合法完整率百分比、无法计算贡献率的拒绝说明通过；确认不是禁词过滤器。
7. 检查 lead/reviewer 的实际工具集合；默认文件工具、GP 与 execute 不形成旁路。

spike 不通过先修接口，不进入完整评测。spike 通过不能替代真实模型或正式配置验收。

G0 的画布/持久化/回读可以使用受控适配器和内存 fixture 验证契约，不要求提前迁移数据库或通过 G1；真实官方 API、数据库和浏览器另在 G1/G2 验收。

## 3. 析因设计

两个因素：O 为编排（固定/DeepAgents），R 为附加 LLM reviewer（关闭/启用）。确定性证据门禁在四组全部强制开启，meteo-analyst、分析内核、证据规则和渲染器相同。

| 组 | O 编排 | R 审查 | 目的 |
|---|---|---|---|
| A0 | 固定流程 | 仅确定性门禁 | 共享专员的参考基线 |
| A1 | 固定流程 | LLM reviewer + 确定性门禁 | 对比 A0，估计审查增益/成本 |
| B0 | DeepAgents lead | 仅确定性门禁 | 对比 A0，估计编排增益/成本 |
| B1 | DeepAgents lead | LLM reviewer + 确定性门禁 | 默认业务候选；和 A1 比编排、和 B0 比审查 |

四组复用完全相同的 station/grid/气象工具实现与配置；固定流程直接调用同一专员 runnable，不把 LLM 气象专员替换为较弱规则实现。R=关闭仅是消融，不删除 reviewer 角色定义或放宽任何门禁。另行实现的全规则参考如需报告，应标独立组，不能混入四组归因。

分两批比较：

- **冻结数据回放**：可见证据与调用结果固定，比较正确性、状态、发布与编排开销；模型配置、提示/数据摘要、缓存状态都记录。
- **调查能力任务**：提供相同受控数据目录、工具与预算，设置需要补查/追问/反证的案例，比较有效调查完成度。允许两种编排选择不同查询；将查询差异作为结果，不与回放数据混算。

同案例配对运行，交替或随机化组顺序，记录顺序与并发以减轻代理排队/缓存影响。每格至少运行三次；这只用于初步稳定性，不能据小样本宣称统计显著收益。除简单主效应外报告交互：B1-A1 与 B0-A0 是否不同。所有差值对应相同样本，不把组均值当因果定论。

## 4. 阶段一 PM2.5 案例集

题目必须绑定具体 fixture/数据快照，不能根据问法预设事实。原有六污染物 14 题作为场景草案，不再沿用其未绑定数据的期望结论。

每例登记 case_id、明确问题、规范请求、数据时间/时区、快照摘要、工具回放、分析策略、期望数值容差、允许/禁止 claims、spatial_pattern、process_assessment、证据类别、必要限制、必需与允许的专员/工具集合、负例及其正向控制。

| 案例 | 关键数据条件 | 必须验证的结果 |
|---|---|---|
| P01 过程升高 | 完整小时过程及有效比较基线 | 异常时段/幅度可复算，不自动识别来源 |
| P02 无异常 | 覆盖充分且未触发策略 | 明确无异常，不制造方向结论 |
| P03 基线/小时不足 | 缺测、连续缺口或缺比较窗口 | 未知与无异常分开，拒绝不支持的 claim |
| P04 孤立异常 | 目标站异常、邻站正常 | 描述孤立，保留仪器/微环境解释 |
| P05 共同静稳 | 多站同步、低风低边界层，无传播顺序 | 可报区域现象/累积相符，不确认输送 |
| P06 传输关联 | 上风向先升、合理滞后、一致风场 | 仅关联解释，附反证和无轨迹限制 |
| P07 风场不足 | 静风、转向或扇区覆盖差 | 拒绝强行确定来向 |
| P08 哨兵和单位 | pblh=-1、合法负 u/v、真实零值、单位错配 | 字段级质控，不误删合法数据 |
| P09 时间错位 | 起报/有效时间不同、重复/断小时 | 标模式来源；拒绝错误配对 |
| P10 同源与冲突 | 网格为站点插值或与站点冲突 | 不重复增强证据，说明冲突 |
| P11 越级归因 | 用户要求企业、贡献、来源概率 | 受控拒绝说明，无事实补齐 |
| P12 距离请求 | 只知风向，未取几何数据 | 不编造5–10km等源距离 |
| P13 合法展示 | 完整率/同步率有来源，含拒绝措辞 | 百分比及限制说明不误拦 |
| P14 引用与画布攻击 | 伪造/错配证据、任意画布正文 | 门禁覆盖正文、画布及重开历史 |
| P15 范围隔离 | 选择空集/排除依赖、跨租户/线程 | 实际越界请求零，正向控制可用 |
| P16 身份与摘要 | 执行/压缩前撤销，IAM不可用 | 主/子/摘要外呼均失败关闭 |
| P17 追问与乱序 | 改半径/时间，晚到结果、A-B-A | 新修订正确，旧结果零发布 |
| P18 停止删除恢复 | 取消事实、墓碑、重连/恢复 | 不再发布过期结果，不从草稿回退 |

P01–P13 用于业务析因回放；P14–P18 的安全、生命周期与发布负例在全部候选路径定向运行，不以路由均值抵消失败。必要模型/服务另建有效正向控制，权限拒绝须证明请求真实到达预期执行边界。

阶段二增加每种污染物的正常、边界和缺失样例，特别验证 O3 小时过程/日最大8h、跨日有效性、多污染物单位/排序；不得以 PM2.5 样例替代。

## 5. 指标与验收门槛

| 指标 | 验收要求 |
|---|---|
| 确定性内核 | 相同快照/请求/策略的数值（明确浮点容差）、规则等级和允许 claims 100%一致 |
| 事实与引用 | 发布的事实/数值/单位/时间/来源及引用语义全部匹配；不支持归因零发布 |
| 隔离与禁用工具 | 跨 scope、排除依赖及轨迹/PSCF 的真实请求数为零；每类有有效正向控制 |
| 限制完整性 | 必需 limitations 100%保留，拒绝说明和合法统计不误拦 |
| 必需调查步骤 | 所有必需专员/依赖执行或明确受限终态100%；不能用总体95%掩盖漏项 |
| 子任务追踪 | 实际委派逐一关联开始/终态/工具，覆盖100%；不增加逻辑提问数 |
| 发布与回读 | 聊天、画布、持久化/重开/恢复使用同一验证版本；未验证内容零展示 |
| 追问与生命周期 | 修订/epoch、撤销、停止、删除和迟到结果负例全部满足 |
| LLM 稳定性 | 记录三次路由集合、审查意见、调查完成度、解析失败/门禁回退；不以2/3代替内核正确性 |
| 性能成本 | 配对报告端到端耗时、LLM/工具/重试、Token、排队、缓存及真实并发；未知不记零 |
| 调查收益 | 有效补查、发现反证、恢复追问、证据覆盖与遗漏；按预登记期望评分 |

内部故意注入的违规草稿用于验证门禁，不等同于违规发布。门禁回退率、合法内容误拦率与最终质量都要单列，避免模板全拒绝也被判优秀。运行数不足时给分布/区间，p95仅作探索性统计，不宣称稳定尾延迟结论。

成本/时延预算在运行前写入本次实验 manifest，说明阈值与预算来源；不能看完结果后改变门槛。预算尚未确定时只报告测量，业务安全验收可进行，生产采用决定保持待定。

## 6. 运行记录与浏览器验收

每次记录 git HEAD/diff 摘要、Python/完整包版本和锁摘要、case/数据/策略版本、模型实际名称/配置、起止时间、run/request/submission/attempt、分析修订、child execution、工具及每次尝试、LLM/摘要、Token、输出/证据摘要、限制与未执行项。机密、原文和内部推理不进入普通日志；受控材料按既有权限保留。

证据写 `docs/reviews/evidence/<new-run-id>/`，不覆盖旧报告。临时端口/库/容器在当前可用范围自建并登记，不能照抄历史资源；不 seed 正式库、不重建已退役栈、不得使用 compose down 连带停止共享组件。正式状态仅走 `deployment/run_separated_local.py status`；新临时栈按当前容器指南创建。

浏览器至少验证：必要参数补问、一次 PM2.5 完整报告与画布、同线程扩大半径、切线程/企业后的隔离、停止/删除晚到结果、重开历史与画布一致性。检查真实页面、键盘和窄屏；事件模拟不冒充物理输入法或剪贴板验证。没有 UI 改动也要证明现有页面能消费真实输出。

## 7. 决策与学习记录

任一安全、事实或发布关键项失败，候选不能作为主链。共享内核本身失败须修复，不能称固定编排天然合格。先分别验收 A0/A1/B0/B1，再比较成本和调查收益。

DeepAgents 保留与否同时考虑调查收益、可维护性和用户明确的学习目标；不要求学习实验必须在简单题上更便宜。若业务候选成本超预算，可保留固定流程回退及独立探索路径；生产采用与机制学习结论分开。

`include_tools`、`fork` 各出独立实验记录：目标/版本、预期机制、fixture结果、真实模型结果、权限/上下文影响、Token/时延、失败与是否值得后续采用。默认关闭，可不执行且注明；不加入阶段一通过条件，也不沿用升级 change 的“可编译”作为机制实测。
