## Context

basic_qa 下的 7 个 Skill 是通用问题场景的核心执行单元，每个 Skill 包含 SKILL.md（路由+通用约束）、fast.md（快速模式规则）、expert.md（专家模式规则）三层结构。设计文档《数智大气-通用问题提示词》定义了 14 个通用问题的分类、气象数据要求层级、专属提示词/专家提示词的输出规范和缺失标注规则。

经过逐 Skill 对比，发现系统性偏差集中在三类：
1. **气象数据要求层级错误**：文档标"必须"的分类（实况查询、达标研判、趋势分析），Skill 中降级为"可选"或"用户要求才补充"
2. **模板格式与文档示例差距大**：多城对比缺浓度差值、保良模板缺逐小时控制阈值、县域考核缺多项指标
3. **数值预测数据缺少双向规则**：有预报数据时应结合分析，无预报数据时应标注局限

## Goals / Non-Goals

**Goals:**
- 使 7 个 Skill 的 fast.md / expert.md / SKILL.md 内容与设计文档要求对齐
- 气象数据要求层级与文档第三节3.1映射表一致（必须/可选/不必须）
- 数值预测数据在涉及当天/未来的 Skill 中建立独立步骤+双向规则
- 所有缺失数据场景都有规范标注（与文档措辞一致）

**Non-Goals:**
- 不修改设计文档本身
- 不修改代码层（graph.py、middleware 等）
- 不调整 Skill 路由逻辑或 find_skill 机制
- 不新增 Skill 或合并现有 Skill
- comparison-composition 不加入数值预测模块（仅查历史月度/年度数据）

## Decisions

### Decision 1: 气象数据"必须"含义的落地方式

**选择**：快速模式必须尝试调用气象工具获取数据，获取失败时必须标注缺失说明，不可省略气象模块。

**备选**：A) 快速模式也必须获取+必须标注 B) 快速模式尽量获取，获取不到可省略但不标注 C) 快速模式气象为可选，有就分析没有就省略

**理由**：设计文档第三节3.1映射表明确标注了"必须"的类别，且第四节专属提示词要求无气象时标注缺失。选择 A 与文档一致。

### Decision 2: 数值预测双向规则的格式

**选择**：在数据获取流程中以独立步骤呈现，包含调用条件、用途说明、双向规则（有数据必须分析/无数据必须标注局限）、降级措辞。

**备选**：A) 独立步骤+双向规则 B) 合并到气象步骤中

**理由**：数值预测与气象数据是不同数据源、不同调用条件（仅当天/未来）、不同分析维度，独立步骤更清晰。

### Decision 3: compliance-feasibility 保良模板的逐小时控制阈值

**选择**：模板按文档示例格式设计（包含累计浓度+未来2/3/4小时控制阈值+当前小时数据），但加 TODO 标记说明工具暂不支持逐小时控制阈值查询。

**理由**：模板应与文档规范对齐，工具能力不足不应降低模板标准，TODO 标记方便后续工具升级时对照修改。

### Decision 4: comparison-composition 的 allowed-tools 增加气象工具

**选择**：在 SKILL.md 的 allowed-tools 中加入 mcp_weather_forecast_daily、mcp_weather_forecast_hourly、mcp_weather_forecast_daily_history、mcp_weather_forecast_hourly_history。

**理由**：设计文档将同比/占比分类标注为"可选"气象，专家模式也应能获取气象数据。当前 allowed-tools 无气象工具导致 expert.md 被迫写"不得调用天气工具"，与文档意图矛盾。

## Risks / Trade-offs

- [Risk] comparison-composition 加入气象工具后，快速模式每次都调用气象可能增加响应延迟 → Mitigation：文档标注为"可选"，快速模式调用气象失败不影响主数据输出
- [Risk] compliance-feasibility 保良模板包含工具暂不支持的字段，实际运行时可能输出占位符 → Mitigation：加 TODO 标记，模板中使用条件判断，有数据时展示、无数据时标注缺失
- [Risk] 趋势分析强制获取气象数据，历史趋势场景气象工具可能无数据 → Mitigation：缺失时标注"缺失气象数据，未分析气象对趋势的影响"，不影响主趋势输出
