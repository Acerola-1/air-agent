# Design

## Context

动机见proposal。2026-10-19只读核验：正式分库已运行，`langgraph.json`公开三图；Agent工作区有溯源多Agent和DeepAgents升级未提交实现，不能覆盖。IAM工作区当时干净，已有通用资源开通。正式业务库只读汇总有150条旧绑定（business/analytics、v1、成员覆盖），root现有引用成员无有效绑定；这些是待清理存量，不是新系统连接来源，不导出行或秘密。

主要耦合已定位：`identity/db.py`查绑定，`mcp_authorization.py`只登记fixture协议，`mcp_scoped.py`连接/缓存/dispatch依赖绑定；`capabilities.py`、`admin/api/app/services/ledger.py`、`langgraph_auth.py`恢复校验均读绑定；admin绑定路由仍引用已退役身份表。现有角色并非已经有一套完整“每工具ACL表”，清理不能凭想象删表。

## Goals / Non-Goals

**Goals:** 以业务替换普通Skill/MCP人员准入，消除旧存储及fallback，root正常路径可用；共享契约见business-authorization-contract.md。

**Non-Goals:** 不重写IAM登录/SSO、不重建知识库、不实现外部MCP数据权限、不改变普通历史数据归属、不增加新图功能、不修改其他Agent的未提交实现。本项不自动执行commit/push/archive。

## Decisions

### 1. 单一业务策略与公共守卫

Agent建立版本化业务注册表，运行时校验其与实际公开Graph一致，给出稳定业务码、中文名、权限码、图及允许连接/工具范围。未知图默认拒绝；新业务不自动开通。实施时输出可供IAM核对的目录清单，不依赖跨仓读取生产文件。

新增公共业务守卫，复用IAM客户端；入口获取有效permissions并冻结精确许可及策略版本，原生hook按实际assistant解析图，核对台账。`guard_runtime_call`及同步/辅助发送入口检查可信业务快照、IAM执行引用和修订，避免每层各写一份规则。现有recheck只返回布尔/修订，必须证明资源/角色/成员改变均推进修订；不能假设它直接返回权限。入口可共享同一次请求身份解析，禁止跨请求正向缓存。

台账新增业务码/策略版本等仅非秘密字段，迁移接实际Alembic head（当前文件到0020，实施时复核分支）。旧记录保留历史事实，旧运行缺新可信快照时要求重新受理。新增或变动事件字段同步源登记、Python/TS validator和样本，不把权限全集写入普通事件。

### 2. 连接配置替换授权绑定

采用受保护部署配置而非新建成员/角色连接授权表。建议`AGENT_MCP_CONNECTIONS_FILE`指向私有JSON，结构含schema_version、revision、servers；每项有server_key、url、scope（tenant/shared_readonly）、tenant_id、auth_mode、credential_ref、enabled、approved_query_tools。业务注册表引用服务及允许工具集合。只保存秘密引用，实际值来自环境或受保护秘密源。

仅服务端可维护地址，不接受浏览器URL防止SSRF。显式共享只读连接不要求企业凭据，也不承诺企业数据隔离；须对当前真实服务完成查询工具审核，未分类工具不自动开放。企业连接使用真实协议；不再拿测试`v1`绑定充当生产认证。旧MCP_SERVER_URL等只可在发布工具中一次性转为显式配置，正式运行不保留双读fallback。

删除成员覆盖身份链路。保留作用域工厂功能但改缓存键为企业/业务策略/服务/连接修订/认证引用摘要，保留真实发送拦截与业务复查，避免缓存捕获第一用户。停止/重试/子任务统一走新dispatch；不要求Skill先被加载。

### 3. 保留选择契约而退出人员授权

Skill头部工具声明用于材料、依赖和编排；普通Skill不注册人员权限。Auto可直接MCP，显式Skill不静默换路由，用户指定空MCP集合仍禁止外呼。业务权限通过不等于任意Graph/任意工具执行，注册表仍限制技术范围，敏感写/外发工具不随普通查询自动开放。

现有能力选择表、不可变快照、事件/outbox、删除墓碑及观测行保留，不把它们误当旧授权垃圾。旧绑定修订字段若存在仅授权用途则移除；历史事件原文不重写成新模型实测。

### 4. 清理清单与验收

| 对象 | 处理 |
|---|---|
| mcp_identity_bindings及150条当前存量 | 新链路验证后DROP明确表；实际数量以切换前只读盘点为准 |
| 该表专属索引、策略、ACL、函数依赖 | 逐项显式移除；不用DROP CASCADE |
| McpIdentityBinding模型、Binding DTO、/mcp-bindings、旧只读页 | 删除，连接状态替换为部署维护说明/状态页 |
| enterprise:mcp、mcp:binding:read/manage及种子/关联 | 本库实际有则删；IAM归配套change；无则零项证明 |
| fetch_*_mcp_binding、resolve_binding、ScopeBinding、fixture协议开关 | 从当前业务热路径删除或以新连接实现替换，不留旧接口别名 |
| 测试fixture | 可保留模拟服务，但移除测试协议充当生产授权的机制 |
| 身份引用、台账/选择/观测/价格/反馈、有效城市范围规则 | 保留；原范围规则不能被误删为Skill/MCP人员权限 |
| 历史迁移/归档/验收 | 保留且注明被替代，不修改旧revision，不伪造旧任务通过 |

代码全仓搜索需区分历史文档/迁移与活跃代码；活跃路径残留为0才通过。DB检验`to_regclass`、pg依赖/ACL、旧权限边及配置目录，不只检查ORM删除。旧接口返回404/410且不修改数据库。

### 5. root和数据边界

IAM配置见配套change。Agent不特判root；使用真实用户登录、切企业、业务码和现有运营/正文读取权限验证全部当前业务。在自建空测试库构造他人记录验证root运营读和普通用户拒绝，不在正式库造假行。正式验收仅使用获准现存记录或root自然产生记录，遵守墓碑。

外部服务没有可证明的全数据协议时，交付写明root本系统权限全开、实际MCP查询范围和服务端数据权限待实施；不能通过关RLS、伪造主体、改模型或跳过用例凑“全数据”。

## Migration Plan

1. 只读冻结目标库身份、版本、旧对象计数与资源清单，不导出行；在自建空资源验证空库/旧schema升级和故障路径。
2. IAM先部署业务契约和root明确授权，新Agent仍未公开；维护窗口阻止新受保护运行，排空/停止旧任务，盘点检查点只存步骤和计数。
3. 启用新业务守卫、连接配置及root真实查询；旧代码停止读写但尚未删表的短窗口只用于本次受控切换，不是可发布终态。
4. 在明确事务内删除旧表与依赖，重启验证。清理IAM残留由IAM负责人执行；不跨仓偷改。
5. 完成联合正反例、无备份扫描、私有配置/测试资源收尾及说明更新后解除维护。任何一步失败保持维护拒绝，不重启旧鉴权。

不创建任何本次dump、快照、backup schema、改名旧表或配置.backup；现有启动器若会为本次配置自动备份，提供本次显式无备份执行路径。事务提交前失败回滚，提交后用新迁移向前修复；数据库工具固有WAL/MVCC不是用户备份，不承诺物理取证级擦除。已有无关备份、共享卷和其他项目资料不在清理范围。

## Risks / Trade-offs

- 外部数据权限未建→真实查询与企业隔离证据分开，部署说明禁止把共享连接称作多租户数据防护。
- 无备份删除不可恢复旧授权→独立空库演练、显式对象清单、短维护窗口和事务；不提供旧体系回退。
- 工作区并行溯源/SDK改动→实施前冻结diff及共享文件责任，不覆盖对方改动；合并后跑当前公开图。
- 两仓不能原子提交→单一协调发布入口和可重入步骤，失败保持受保护业务关闭；不能仅凭一仓任务全勾宣称联合完成。
