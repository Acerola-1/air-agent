# Design

## Context

动机见 `proposal.md`。本次开始时为 `dev@0b3c4bf13b26ec26b8aaa93fb06c7bb5ffb8059d`，工作区已有其他任务改动，尤其涉及观测与溯源活动规格，不纳入本变更。

已核实的实现约束：

- `publishing.py` 的 `awrap_model_call` 隐藏全部模型正文，`aafter_agent` 在 request/scope 缺失时无条件发布 `_CLARIFY_TEXT`。
- `graph.py` 用一个 DeepAgents lead 调度四专员；现有提示默认从冻结分析请求开始，没有普通对话出口。
- `state.py` 的请求/报告/分节会话由checkpoint跨轮保留；部分reducer收到None并不清空。仅修改缺少request时的分支不能解决“旧报告之后闲聊”的问题。
- `tools.py` 现有冻结输入要求完整时间；条件草稿需独立建模，不能通过伪造完整请求承载补问。冻结时可能进行授权目录查询，不应声称冻结前完全无MCP外呼。
- `OutputPublisher` 和 `publish_control_message` 已提供统一终答、输出标识、授权探测和可见消息；普通回复不需要新公共协议。
- 同聊天已核对的真实故障样本：trace `80a060392b1eb1c767e2beaaf4ffccc5`，北京时间2026-10-23 00:02:54；模型生成能力介绍，最终消息为隐藏空正文及可见的 `tracing_clarify`。该样本只证明发布错误，不作为其他流程通过的证据。

## Goals / Non-Goals

**Goals:**

- 支持本域自然的问候、能力/流程介绍、精确补问和多轮分析切换。
- 在同一次主模型首个决策中表达意图与会话计划；服务端执行安全边界不依赖模型标签正确。
- 三条路径共用终答和生命周期，保留分析报告的证据、分节、画布与回读约束。

**Non-Goals:**

- 不建设通用闲聊机器人，不开放任意站点事实、自由法规答案或无证据归因。
- 不修复本聊天前面发现的基线取数、异常统计和报告信息缺失；这些需要独立变更和真实数据验收。
- 不升级依赖、不改IAM/RAG服务、不增加公共SSE事件，不重写现有Langfuse采集。

## Decisions

### 1. 主模型提交本轮计划，服务端决定可执行路径

拟增加本域 `conversation.py`、`turn_routing.py`（具体拆分可按代码组织调整），在现有lead第一次决策时提交严格结构化 `TracingTurnPlan`，通过专用提交工具进入服务端校验。初次决策仅暴露此工具及必要结构schema，不暴露task、冻结、数据、知识、报告或画布工具；执行层同时拒绝未获本轮许可的调用，不能只靠隐藏schema。

模型计划包含 `intent=conversation|analysis`、本轮相关的槽位候选、会话动作/语气/顺序及引用ID。服务端根据校验结果形成 `route=conversation|clarify|analysis`，另有仅表示失败的受控fallback，不把模型自报的“complete”作为执行依据。混合问候与分析优先处理真实分析请求；纯解释性问题不触发分析。

不增加独立分类模型或逐轮审查模型；会话在首个决策后可结束，分析获准后继续既有lead执行。分析路径可能增加一个计划提交决策，需实测模型次数和时延，不能宣称必然零开销。模型无工具返回、结构非法或计划冲突时不无界修复，使用相关受控引导；畸形结构不得转入分析。

备选：关键词路由无法覆盖转述、混合意图和多轮省略；仅由LLM自由标签放行无法约束误判；额外分类/审查链增加成本。选择单一lead建议加执行层校验。

### 2. 普通交流采用可组合语义计划，不直接解禁任意原文

会话计划由问候、能力、使用步骤、限制、下一步引导等有类型的block构成。能力/流程/边界引用来自服务端根据业务注册、`DEFAULT_POLICY`、本图实际工具和受保护配置生成的版本化 `ConversationCapabilityCatalog`；不通过外部目录或知识请求生成。缺少运行时健康证据时只能说支持某类分析，不承诺数据当前一定可用。

LLM可选择相关条目、组织顺序、详略与已审核的自然语气变体；服务端从可信条目渲染完整中文回复。计划不接受任意 `body_markdown`、新数值或来源断言，自由原文继续保持内部不可见。问候也使用有界社交动作，避免在自由问候字段夹带事实。这样是可组合的会话回答，不是单条固定补问，也不依赖禁词匹配证明语义安全。

这一阶段自然表达的事实部分由可信短句承担；若以后允许任意自由改写，需另行明确语义审核和流式发布前验证方案，不能在本次实施中悄悄放宽。

报告解读请求可引导回到现有可核验报告/分析路径，不能把历史正文交给会话自由总结；具体法规和限值问题保持既有知识流程或明确引导到知识问答。本变更不拓宽知识工具许可。

### 3. 条件草稿与冻结请求分离

新增 `TracingRequestDraft`：目标代码/名称、行政区、污染物、时间/时区、半径、基线及每项来源用户消息/轮次。草稿为候选，不含授权；允许字段缺省，显式记录冲突和歧义。合并限于同一用户、企业、thread、graph及有效context_version；本轮明确值优先，跨上下文或用户否定后不能继承。

服务端先进行无网络的完整性/格式校验，生成 `missing_fields`、`invalid_fields`、`ambiguous_fields` 与受控补问计划。沿用现行策略：半径仍需确认且必须1–50km；不将策略默认10km静默用于执行。未提供基线沿用现行七天策略，采用默认污染物/时区时明示；用户只给一端的基线不可静默丢弃。完整性检查通过不代表站点已获授权。

用户确有分析需求且基本条件完整后，才允许现有冻结工具做授权目录解析和最终校验。同名站点保留候选并澄清，不调用数据专员；目录失败、权限失败与字段缺失分别反馈，不能全变成“请补充站点”。冻结结果真实成功后才授予本轮task/报告工具许可。

### 4. 每轮决定绑定执行身份，保留历史但不复用旧发布

新增 `TurnContext` 和 `TurnDecision`，包含服务端run/attempt、触发用户消息ID、输入摘要、可信scope、策略/目录版本以及本轮execution_epoch；这些绑定由服务端赋值，模型不创建可信ID。恢复同一attempt可复用经验证的决定，新attempt或新输入必须重判。未决草稿可跨轮继承，本轮决定不能继承。

正式分析获准后，为本轮记录新冻结请求或明确续接的修订引用，所有tool dispatch再次校验本轮许可与请求归属。历史request/report/publication_session可以保留，不靠现有reducer的None实现重置。普通交流及澄清直接走本轮发布分支，不读取旧报告作为回退；新分析建立相应修订并隔离旧findings/会话。

同一运行分析完成不能再降级为闲聊洗白其正文。旧run的迟到任务、输出及A→B→A结果仍由现有epoch、context_version和删除规则拒绝；停止意图不伪装为已取消。

### 5. 发布依据来自运行上下文，三条路径共用终答

从 `runtime.py` 提取无须analysis_id的可信运行scope解析，以run/attempt提供epoch；普通交流/澄清不伪造分析请求。所有路径在模型外呼及发布前执行现有身份、业务、台账归属、取消和墓碑检查。

修改 `TracingPublishMiddleware` 按本轮 `TurnDecision` 分流：会话/澄清计划校验、渲染完整后通过 `publish_control_message` 发布，真实标记 `single_shot`；分析保持 `publish_frozen_plan` 和 `ValidatedReport`。普通回复不创建validated_report_ref、不覆盖历史报告，也不写报告artifact。

使用既有output/message ID及attempt绑定保证幂等，复用已有持久化/终答回调；发布一次后的钩子重复执行不能创建新output。历史展示和复制仅使用最终可见消息。若失败发生在已公开片段之后，遵循现有aborted语义，不重发另一篇全文。本次没有“先发原文，再审核撤回”流程。

### 6. 与现有规格的协调

新增独立能力 `tracing-conversation-routing`，不修改其他任务未提交的活动文档。`add-intelligent-tracing-multiagent` 的“确定性结论门禁先于全部发布”“进度与现有契约保持一致”，`integrate-intelligent-tracing-into-dev` 的主图工具白名单，以及 `unify-user-visible-answer-streaming` 的报告分节与内部输出隔离是相关约束：本次新增会话计划提交工具；“只发布报告”限定于分析事实与结论；主/子代理任意草稿仍不可见。

归档时将该适用范围及新增提交工具同步到对应规格；这些能力若仍未归档，应先按实际已落地主规格协调差异，不虚构MODIFIED目标、不重复复制整份旧delta。`final-output-cleanup` 主规格仍有旧六图和原始Messages降级描述，本变更不采用该旧降级，也不顺带治理全部历史规格。公共协议仍是当前三图及统一终答契约。

### 7. 观测与验收

沿用当前attempt/run/trace，记录 `proposed_intent`、`selected_route`、`published_reply_kind`、`fallback_reason` 等有界枚举及本轮/输出ID，关联实际工具数与最终状态；仅模型生成完成不能标为已发布。不新增正文副本，不改变当前Langfuse正文采集策略。

固定验收集版本 `tracing-conversation-v1` 放在本域测试fixture中，包含原问题及改写、能力边界、只缺半径、两轮补齐、非法/歧义字段、完整分析正向控制、混合意图、历史报告后闲聊和再改半径、跨企业/epoch、伪造会话夹带归因/法规/观测、非法结构、取消删除撤权、发布重试与重开复制。按用例记录预期实际路径、允许/禁止工具、实际请求次数、可见消息与正文摘要；安全用例必须有有效正向控制。

分开记录G0 fake model/fixture，G1实际SDK+真实配置模型+自有隔离资源，G2浏览器/键盘/窄屏。G1普通交流目录/MCP/知识/专员调用必须为零；正式分析至少保留一个成功报告正向控制，不要求本变更修复源数据缺失。真实模型每个核心用例至少三次，逐次报告准确性、fallback、模型/工具调用、耗时与Token，不能把模型不可用记为通过。G2检查实时、刷新、重开、复制、停止和切换；未执行明确保留未完成，不以strict通过替代产品验收。

## Risks / Trade-offs

- [结构化意图识别仍可能误判] → 工具执行和事实发布各自独立校验，固定集包含语义改写及恶意误路由；相关回退不执行取数。
- [可信条目降低自由措辞空间] → 提供可组合条目、详略及语气变体，先保证有用交流和事实边界，后续再独立评估自由改写。
- [旧状态残留造成重发或错误继承] → 本轮执行键和显式分析引用，测试必须在持久化同thread跨多轮运行，不能只测空state。
- [新增决策影响分析时延] → 复用lead配置、不增加独立审查，分别实测会话与分析模型次数/耗时，复用当前预算而不静默上调。
- [能力描述与配置漂移] → 条目生成关联策略/图工具版本，配置变化后重新生成，不宣称不可知的源数据健康。
- [后端正确但页面丢弃或重开不同] → 使用现有协议并做原生/BFF/浏览器及历史摘要核对，不依赖trace原文证明展示成功。

## Migration Plan

1. 在当前HEAD重新冻结基线，仅实施本变更文件，保留已有观测/身份工作区改动；无数据库DDL及依赖升级。
2. 先接本轮结构、受控会话计划和分发守卫，再替换无request固定补问，接入精确澄清及既有分析路径；所有层就绪后统一启用。
3. 运行定向回归及G0/G1/G2；真实模型/浏览器未执行时保留未完成。部署、commit、push与归档分别依后续授权执行。
4. 旧checkpoint没有本轮决定时从当前输入重新识别，不发布旧report或原始AIMessage。历史已确认报告保留原版本；不批量改写旧消息或trace。
5. 回滚仅恢复本变更代码，保留已写可见消息、报告和证据；不能回退身份门禁或分析证据门禁。回滚后的旧补问缺陷需明确记录。
