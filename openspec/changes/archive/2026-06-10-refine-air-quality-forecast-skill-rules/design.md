## Context

当前空气质量数值预报工具被多个 Skill 暴露，尤其数据分析模块的 Skill 总纲普遍包含该工具。部分 detailed references 明确要求“独立调用空气质量数值预报”，部分则只在输入范围或外部数据表中泛化提到“未来趋势预判”。这种做法会导致三个问题：

- 历史复盘或主数据已覆盖全天时，仍可能触发未来预报查询；
- 预报值和已监测事实的边界不清，可能被混用于峰值、均值、等级等监测统计；
- 工具描述、系统提示词和 Skill 提示词之间责任不清，难以逐模块控制输出格式。

本变更遵循用户要求：规则必须落实到具体 Skill，不把公共系统提示词作为主要约束。

## Goals / Non-Goals

**Goals:**

- 建立逐个 Skill 的空气质量数值预报适用性审查流程。
- 将调用条件、禁止条件、使用边界和缺失降级写入需要预测输出的 Skill detailed references。
- 对不需要预测输出的 Skill，移除或弱化空气质量数值预报工具白名单和规则描述。
- 统一“监测事实优先、预报只补未来”的业务口径。
- 用静态测试防止后续新增 Skill 只把工具放进 `allowed-tools`，却不写清业务边界。

**Non-Goals:**

- 不修改 MCP 工具实现、参数 schema 或工具返回结构。
- 不把空气质量数值预报约束集中写入公共系统提示词。
- 不改变 LangGraph 图结构、Skill 发现机制或工具过滤中间件。
- 不重新设计所有 Skill 的完整业务提示词，只处理与空气质量数值预报相关的规则。

## Decisions

### 1. 以 Skill 为最小治理单元

每个命中 `mcp_city_common_get_air_quality_forecast` 的 Skill 必须被单独分类，并根据分类修改自身 `SKILL.md` 和 `references/*.md`。

分类建议：

- **必需预测类**：业务目标本身依赖未来空气质量风险，如达标可行性、目标控制、当日剩余小时研判。
- **条件预测类**：只在当日实时且主数据未覆盖未来窗口时使用，如小时播报、基础实时空气质量、趋势分析的当日尾段。
- **可选预测类**：用户明确追问未来风险时才使用，默认不主动扩展。
- **非预测类**：历史复盘、排名、日历、箱线图、空间格局、比例构成等，默认移除空气质量数值预报要求，必要时只保留气象或页面数据分析。

替代方案是写一条公共系统提示词统一约束，但这样不能解决不同 Skill 业务边界不同的问题，也不符合本次要求。

### 2. 预报只能补未来，不能覆盖监测事实

所有保留空气质量数值预报的 Skill 必须声明：

- 页面或主工具返回的监测数据优先；
- 预报数据只用于未发生或未覆盖的未来时段；
- 不得用预报值重算已监测统计项，如峰值、均值、AQI、等级、首要污染物、排名、占比；
- 最终输出必须把“已监测事实”和“预测研判”分开表达。

### 3. 当日未覆盖全天是小时播报类的关键触发条件

小时播报、实时基础查询等小时级场景只在以下条件同时满足时主动补充空气质量数值预报：

- 查询日期为当日；
- 主数据最后有效小时早于 23 时，或当前页面/主数据缺少当日剩余小时；
- 用户问题或专家模式输出结构需要后续趋势、风险或值守建议。

历史日期和已覆盖 0-23 时完整小时序列的场景不得主动调用空气质量数值预报。

### 4. 白名单和详细规则保持一致

如果某 Skill 被判定为非预测类，优先从 `allowed-tools` 中移除 `mcp_city_common_get_air_quality_forecast`；如果因为兼容或未来追问需要保留，则 detailed references 必须明确“默认不调用，仅用户明确询问未来空气质量风险时使用”。

### 5. 通过静态测试约束内容质量

新增或更新测试，检查：

- 含有空气质量数值预报工具的 Skill references 中必须出现调用条件和使用边界关键词；
- 小时播报专家规则必须包含当日、主数据未覆盖全天、不得覆盖已监测事实等约束；
- 非预测类 Skill 不应继续要求独立调用空气质量数值预报。

## Risks / Trade-offs

- **Risk: 批量修改 Skill 可能影响已有回答风格** → Mitigation: 只修改预报相关段落，不重写完整提示词；优先保留原有输出结构。
- **Risk: 误删工具导致少数未来追问能力下降** → Mitigation: 按“非预测类默认移除，可选预测类保留但限制”的分类逐个决策。
- **Risk: 数据分析模块 Skill 模板化严重，逐个判断成本高** → Mitigation: 先生成命中清单，再按业务类别分组处理，最后用测试核验覆盖面。
- **Risk: 工具真实返回字段未知** → Mitigation: 规则只约束业务语义和输出边界，不依赖具体字段名。
