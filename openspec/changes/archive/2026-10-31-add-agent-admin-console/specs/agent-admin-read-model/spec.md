# Spec Delta

## Purpose

把分散的台账、反馈和逐调用观测组织成可核对的后台读模型，为趋势、用户用量、能力性能和费用下钻提供一致窗口和范围。新读模型保护企业边界和独立原文权限，同时保持重试、恢复、回答版本与逻辑问题的计数区别。

## ADDED Requirements

### Requirement: 聚合之前授权与数据库隔离
系统 SHALL 每次实时验证IAM身份和所需统计或运营权限，在聚合前限制当前企业。请求使用非owner、非BYPASSRLS角色及事务本地上下文；平台身份、root名称及业务使用权不构成跨企业运营读取权。

#### Scenario: 连接复用与伪造筛选
- **WHEN** A/B同用户交错查询，A请求声明B企业ID或重放B游标
- **THEN** 不返回B数据；无上下文事务无数据，合法A/B各自查询为正对照

### Requirement: 逻辑计数与维度守恒
系统 SHALL 对已确认受理request去重计算提问，对attempt计算尝试，对模型逻辑调用与物理重试分别计数。Skill匹配、选中、加载和执行分列；多Skill关联的费用不能重复分摊，业务未知与未归因数据独列。

#### Scenario: 重试恢复与内部专员
- **WHEN** 一个问题有两次attempt、一次恢复、三次模型重试和四个内部专员
- **THEN** 提问量仍为1，各层数量分别显示，内部专员不成为新的独立业务或问题

### Requirement: 指标窗口覆盖与费用精度
系统 SHALL 用UTC事实时间与Asia/Shanghai半开业务日窗口，明确每项指标的队列、分子、分母、来源、版本、截止与缺失。分位数从有效明细计算，满意率不包含未评价；费用按币种和当前计费修订用十进制聚合，缺usage或价格时不补零。

#### Scenario: 混合窗口与缺失成本
- **WHEN** 七日样本包括跨日回答、撤销反馈、CNY/USD及未知价格
- **THEN** 按各自命名队列计算，可从明细复算；不同币种分开，未知和无分母比率显示null及原因

### Requirement: 原问题与回答按需受控读取
系统 SHALL 为运营读取提供同企业且具有运营与正文双权限的精确请求/回答版本访问。正文来源必须可证明、分段有界、遵守墓碑与保留期；未保存的回答应返回明确不可用状态，禁止从其他用户身份、共享Langfuse或任意checkpoint旁路补取。

#### Scenario: 他人回答版本与删除
- **WHEN** 有双权限的运营人员读取A企业他人确认回答，随后会话删除
- **THEN** 删除前仅返回该确认版本；删除后的下一读取和晚到响应不恢复正文，只有运营权限的用户始终读不到正文

### Requirement: 服务端有界查询与可核对性能
系统 SHALL 提供最多200项的稳定分页，游标绑定企业与规范化过滤；汇总不能累加客户端当前页或截断前200项后冒充完整统计。查询窗口、维度和正文大小有上限，超界明确拒绝；基准同时记录响应、SQL数量与外部等待。

#### Scenario: 高基数与查询截止
- **WHEN** 样本超过一页并含同时间戳数据，另有请求在翻页期间写入
- **THEN** 固定数据截止与稳定排序避免重复/漏页；总览覆盖全集，截断或投影延迟有明确标签

### Requirement: 查询兼容与数据依赖降级
新运营查询 SHALL 保持旧受理、状态、反馈和观测API语义，不修改业务执行热路径。单个观测或外部Trace域失败时可返回带原因的部分结果；身份故障必须整体失败关闭，不得以局部降级继续读取。

#### Scenario: 依赖故障区分
- **WHEN** Langfuse不可用而本地事实可用，随后IAM不可用
- **THEN** 前者仅影响Trace分区，后者所有受保护读取503，不使用最近一次成功权限放行
