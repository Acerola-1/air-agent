# Basic QA 会话能力运行设计

## Context

动机与范围见[proposal.md](proposal.md)。本文区分当前事实、用户已确认需求和拟实施设计；不是实现完成或上线报告。

### 当前事实与根因

- 本仓`dev`基线HEAD为`7d79526`，工作区有未提交的上一版循环实现。本计划不假定这些代码已验收，也不覆盖其他未提交工作。
- `langgraph.json`的`basic-qa`经`src/basic_qa/graph.py`进入共享`business_graph`构建器，是原生LangGraph；data-analysis也是原生图，暂时封存；intelligent-tracing使用Deep Agents。安装了deepagents包不表示Basic QA使用它的中间件。
- `basic_qa_integration.initialize`在新attempt将`bqa_active_skill`清空；`basic_qa_runtime.current_material`只接受最新HumanMessage之后的加载记录。即使同一线程材料没变，下一轮仍丢失激活资格。
- 用户实际试用的湖州→杭州、湖州→金华Trace分别出现403和409加载前置错误。上一修复只实现错误后补加载；相关测试还明确断言新轮应清空状态，因此测试通过没有证明正常连续复用。
- 图已有`call_model ⇄ execute_tools`，并单独执行`answer_model → ledger_finalize`；无需从零实现循环。现有工具工厂支持图构建后发现及动态执行，不能以静态ToolNode全量注册替代当前作用域。
- `business_registry.py`当前Basic QA登记21项，公共`IPP_APPROVED_QUERY_TOOLS`登记109项已审核查询操作。数字是代码登记量，不是实时服务可用量；部署`approved_query_tools`及连接仍参与交集。
- `capabilities.py`已有Skill简介、材料指纹、稳定工具ID与受理选择；`skill_materials.py`已有总纲＋fast/expert快照及静态缓存。router现用进程内语义索引；新增工具索引需明确持久化，不能声称现成向量库已满足跨重启增量复用。
- `context_preparation.py`已有摘要、水位、完整请求计量和超窗恢复；消息持久化与发送给模型的投影不同。不能为了跨轮复用重新拼全量历史或另造摘要算法。
- 前端与 BFF 不再维护 Skill 选择状态或接受事先指定 Skill；MCP 范围约束独立保留。

### 已确认的产品决策

1. 任意轮次都能发现、加载、组合、复用能力；支持多个Skill同时激活。
2. 优先预设Skill；一个不够先考虑其他Skill；只有仍未覆盖的需求或部分才独立寻找工具。不是“整个问题必须完全无Skill匹配”才准用工具。
3. `search_mcp`每次Top 3，由模型决定用哪个、用几个或都不用；候选不是已加载工具。
4. 工具描述在程序侧索引，模型只按需获取候选和激活工具定义；不全量塞入上下文。
5. 普通复述、寒暄不强制调用控制工具；非专业话题简短说明业务范围并引导回来。
6. 不恢复人员→Skill/MCP权限，不新增地区权限、接口回显时间／城市／指标或回答证据声明校验。
7. 本轮只生成可供他人评审的计划，不实施、不部署、不调用子代理。

## Goals / Non-Goals

**Goals:**

- 将会话能力状态与本次attempt、模型请求工具集合分开，避免“新消息”等同“未加载”。
- Skill规则、独立工具和真实执行来自同一规范化能力解析结果；正常复用不以先报错为流程。
- 复用现有原生图和运行治理，以少量能力状态／目录索引适配实现所需行为，而非继续增加逐工具特殊补丁。
- 给第三方提供可逐项反驳的技术选择、验收输入、实际观测指标及迁移边界。

**Non-Goals:**

- 不迁移Basic QA到Deep Agents或create_agent，不增加多代理、shell或任意文件工具。
- 不重建MCP连接、人员授权、知识库、摘要算法或前端正文发布协议。
- 不保证模型永远不选错；用固定真实模型评测分别暴露首次失败和恢复，不能以错误可恢复取代正确路径。
- 不把工具元数据当法规／计算业务规则，也不借工具目录扩展新增溯源报告或恢复数据分析图开发。

## Decisions

### 1. 保留外层原生图，替换能力生命周期

目标主链仍为`输入检查与受理范围 → 恢复会话能力 → prepare_model → call_model ⇄ execute_tools → answer_model → ledger_finalize`。入口不对最新一句强制分类／embedding；外部每条用户消息进入同一主链。内部循环仍按当前attempt重置工具批次、失败重试与耗时计数，**仅这些运行事实按轮重置**。

复用现有统一模型发送、数据处理及最终正文流，控制工具结果和规划草稿不作为用户正文。保留无参finish和无工具自然结束。替代方案“再改拒绝信息或强制每轮load”不解决状态根因；“整体换Deep Agents”会扩大变更面且不是用户要求。

### 2. 会话状态只持久化可信引用

新增一个有明确版本的`bqa_capabilities`结构，主要字段为：

```text
version: 2
owner_scope: 服务端tenant/user/thread/graph作用域标识
loaded_skills: skill_id -> {material_version, mode, load_ref, last_used}
active_skill_ids: [skill_id, ...]
loaded_tools: stable_tool_id -> {schema_version, load_ref, last_used}
independent_active_tool_ids: [stable_tool_id, ...]
```

`load_ref`是服务端成功加载记录引用，不是模型声明或人员许可。工具的激活来源由当前Skill映射和独立激活集合推导，不单独持久化一个容易失真的工具并集。状态不存Python对象、连接凭据、完整Skill正文或所有工具schema；新旧消息内容都不能单独成为当前执行资格。加载／激活引用用于准备模型上下文，执行只核对服务端本次实际提供的工具定义、真实模型调用、schema及当前身份／业务／连接／受理选择，不再以Skill归属或load_ref追加门槛。

原有`bqa_turn_key`仍仅关联本次attempt。新轮恢复服务端引用，对当前身份、受理范围、材料版本和模式重新解析，仍有效则保留激活；失效目标转休眠或返回明确重载状态，其他有效能力不清空。加载状态不意味着复用旧城市参数或旧数据：每次查询由当前问题决定参数。

同attempt的resume沿用原受理／版本，不在恢复中悄悄升级。不同企业、用户、线程或图的激活状态不复用；客户端及原生输入的能力字段继续拒绝注入。删除优先于晚到状态、缓存回读和恢复。

旧v1会话只允许从服务端checkpoint中有效活动记录迁移，并核对原加载调用／成功回执及登记材料；不能从自由规则字符串、模型自报“已加载”或普通观测缓存反推。无法证明时保留对话、以未加载能力进入新流程。迁移后不再要求加载发生于最新HumanMessage之后。

### 3. 统一Registry与实际模型请求投影

Skill Registry复用本地图目录和材料版本；Tool Registry复用受保护MCP发现工厂，以`mcp:<server_key>:<original_name>`区分同名服务。原始完整定义留在程序侧，schema版本取规范化名称、说明、参数结构等内容摘要；连接修订与业务策略版本单独参与解析，摘要不包含秘密。

稳定ID不直接充当供应商函数名。模型工具名使用现有工厂生成的合法别名，与稳定ID保留显式映射；两个服务的同名工具不按短名猜测绑定。search/load使用稳定ID，真实tool_call通过同一映射进入对应服务执行器。

每次实际发送，从同一解析服务得到：当前完整Skill模式规则、独立工具必要说明、休眠引用简表、去重工具定义及来源映射。经现有`prepare_model_request`统一整理／计量，记录这次实际披露的稳定工具ID和模型逻辑调用引用，随模型输出提交给执行节点；执行时再交叉检查当前范围。不能只在prepare_model拼一次提示，也不能只在schema侧过滤。

向模型提供的工具定义集合为：活动Skill映射工具 ∪ 独立激活工具 ∪ 原有通用／控制工具，再与业务、连接及受理选择相交。执行时检查本次实际提供的定义和当前真实授权，不再读取激活集合决定执行资格。独立工具不做“必须属于某Skill”的二次拒绝；同工具来自多个Skill或独立加载，只绑定一份、执行一次，观测保留多来源而不重复计费。

### 4. Skill优先是模型决策策略，不新增语义审计器

模型常见的三条路径：

- 有适用已激活Skill：直接按其规则查询，或复述已有结果；没有理由再次search／load。
- 需要预设能力：按会话语义 search_skills，选择返回候选后 load_skill；已有有效加载引用可直接复用或重新激活；可组合多个Skill。
- Skill仍未覆盖的部分：search_mcp → 选择0至3项 → load_mcp_tool → 在后续模型请求中使用；已知有效独立工具可直接重新激活。

“优先”不等于每轮强制先embedding，也不要求模型先证明所有Skill不适用。通过提示和固定用例检验完整覆盖时不绕过Skill；不新增coverage分类模型、回答声明字段或运行时语义门禁。专业通用规范（不得编造、按真实时间理解、法规引用及信息不足时澄清）放在公共提示，独立工具路径同样遵守。

自然语言明确要求某 Skill 时，将其作为发现需求搜索并选择候选；已有有效引用可复用。消息不构成事先锁定 Skill 的受理字段，旧 Skill 选择协议不再接受。遇到互斥业务指导按任务覆盖部分分别应用；同一结论仍冲突时澄清，不让后加载字符串静默覆盖前一Skill。

### 5. 幂等加载与并发更新

`load_skill(skill_id, expected_version)`读取总纲与有效模式材料，激活关联可用工具；`load_mcp_tool(tool_id, expected_schema_version)`激活登记工具及必要说明，不运行查询。再次加载相同版本已激活条目只返回简短`already_active`，休眠条目返回`activated`，新条目返回`loaded`；失败带规范原因，目标以外状态保留。正文规则不重复追加到永久ToolMessage历史，实际模型请求从Registry恢复。

沿用九Skill的非绘图必需／绘图可选要求：缺必需项不宣称完整Skill成功；缺图不拦正文；已有工具返回空结果不是加载失败。材料变更必须在下一次使用前明确刷新完整规则，不把旧版本指导与新schema混用。

加载控制批次按模型给出的调用顺序串行处理，并在批次累积状态上依次合并，最终一次提交完整会话更新和每个call_id的配对回执。不得将多个独立Command对同字段的并发写入交给最后写者覆盖，也不使用盲目list拼接制造重复引用。独立业务查询批次仍由ToolNode并行执行。

加载与尚未披露的领域调用同批时，不在模型读取新规则前执行查询；保留其他有效能力，返回配对顺序纠正结果。该异常分支不是正常加载路径，验收保留前置错误，不通过改成成功消息隐藏。已有八个工具规划批次与更紧超时／停止预算继续适用；相同控制失败最多一次纠正重试，真实身份拒绝停止。

### 6. search_mcp协议与Top 3

输入`query`是模型结合上下文形成的最小专业检索语句，初版沿用500字符上限与10秒搜索超时，作为可配置实现默认值而非用户另加业务限制。空输入、不可用索引和搜索超时分别返回规范状态，不能伪装成正常无命中。

返回`status`、`catalog_version`和最多3个去重候选，每项只含`tool_id`、名称／短用途、`schema_version`、可用状态和匹配分数。不得含完整JSON Schema、连接地址、凭据或全部目录。候选池先按当前合法范围过滤，再做语义排名；分数相同以稳定ID排序。不设置新的人为分数门禁，不跨范围凑满三项。模型可以不选、选一项或多项；search不自动load，load不自动query。

采用现有embedding通道和语义索引抽象，工具原始名作为可解释检索文本的一部分；不机械用最新用户四字，不将整段对话无差别发送给embedding。首次版本不新增重排模型或搜索供应商；召回不足先用固定工具检索集揭示，不能以“Top 3必然正确”作为假设。

### 7. 全目录不等于全量上下文

将Basic QA业务工具集合从现有21项扩展为`IPP_APPROVED_QUERY_TOOLS`当前登记清单，再与真实部署连接`approved_query_tools`和服务当前发现结果取交集；实施时冻结这份清单及内容摘要，更新业务策略版本。清单当前109项，逐项差异中显示新增的88项，不把全部在线可用当作事实。未知后续工具不自动放开。

当前业务策略版本是共享全局版本；更新它会影响其他图的在途运行。因此部署前须排空所有受该版本影响的运行并做共享回归，不能只排空Basic QA后让其他图在旧快照中继续。这里不另造逐工具人员权限或新的业务授权模型。

这些工具仍是该业务内的查询操作；不自动调用data-analysis菜单或intelligent-tracing主图／专员，不把查询结果描述成已完成正式溯源报告。所有工具都可以存在于检索目录，不要求各有Skill。只把Top 3简介和实际激活的少量定义送入模型。受理API和BFF继续使用同一合法范围，不让目录看得到而执行仍被旧21项限制错误拦截。

### 8. 索引持久化、增量更新与运行身份

初版不新建向量数据库。复用业务PostgreSQL，新增程序侧工具索引缓存表：目录代次表记录作用域、连接／业务修订、embedding模型版本和发布状态，文档表记录稳定ID、描述／schema摘要、向量及版本。向量以普通可持久化数据存储，小目录在进程中按合法ID集合计算相似度；无需新数据库扩展。

表接实施时实际迁移head，采用现有非owner运行连接、tenant作用域及FORCE RLS；凭据不入表。索引缓存不是权威工具注册，也不缓存人员许可。缓存键包含企业/业务/服务/连接修订、embedding模型及规范化文档摘要；身份和用户选择每次查询实时过滤，不将用户问题原文做共享缓存键。

目录文档按内容寻址复用未变向量，变更项增量embedding，删除／失效项不再参与查询。构建采用作用域single-flight和完整代次原子发布，避免多个worker重复构建、旧构建覆盖新目录；生成期间范围变化则丢弃迟到发布。只回收本实现的过期缓存代次，不清理共享业务数据。

实施中的固定12题检索诊断显示，纯向量Top 3会混淆站点与城市实时查询。当前排序在同一合法池内结合明确对象词和工具命名空间元数据：城市／站点／网格／气象对象匹配加固定先验，同类仍按cosine排序，稳定ID打破同分；不匹配和未分类工具仍可入选。它不改变许可、gold或Top 3数量，也不新增重排模型。分数是相关性排序值，不是概率。纯向量失败和最终冻结集结果均保留；小样本通过不代表所有自然问法召回有保证。

默认在首次已认证的search_mcp时按需构建或刷新，通过既有逐发送守卫；显式启动阶段可读取有效缓存，若部署已有受支持的可信服务身份才可后台预构建。不得为预热伪造用户或扩大IAM改造范围。没有该身份时保留冷启动成本并实测，不在图导入期或匿名后台外呼。每次启动不全量重算。

索引失败不让业务启动整体不可用；已有有效、同版本索引可用则复用，否则返回`index_unavailable`。不以失败为由把109项schema发给模型。已有效加载的能力仍可在当前范围内复用；未发现的新 Skill 不因搜索故障而获得全量目录降级。

### 9. 激活规模与上下文整理

区分会话加载引用、当前激活集合和当次模型投影，不按用户轮次或固定“只能一个Skill”清理。优先运行现有上下文整理与计量；仍超出实际容量时，使较久未用、不是本次刚加载或待执行依赖的条目休眠，保留ID、版本和简短用途。规则／schema必须一起退出，并在模型当前能力说明中反映。

新加载的必要组合不能容纳时，明确返回容量不足或请求拆分任务，不截掉规则却留下工具。模型可用已有load工具重新激活休眠条目，无需再embedding。清理历史加载正文只是发送投影优化，不删除用户历史、原始结果或真实执行记录。复用原`summary`和`summary_covered_message_id`，不新增第二套conversation_summary。

### 10. 执行与观测的统一事实

执行入口使用当次披露记录加实时业务／连接／受理范围，所有重试和动态绑定走现有MCP工厂。未激活工具拒绝作为有界纠错保留；已独立激活工具不能再因为没有所属Skill而被拒绝。保持取消、删除和逐发送身份检查，不在节点间原地改config传递权限。

沿用现有事件与Langfuse关联。计划实施时扩展所需能力来源、激活／复用事实，严格枚举字段同步事件源、Python/admin/TS校验和样本；不能先写自由字段绕过契约。普通事件只存稳定ID、版本、计数和错误类别；受控Langfuse继续按现有正文契约采集，读取它不意味着获准把私有Trace再次发送给外部模型。

分别计数search_skills、search_mcp、索引文档embedding与查询embedding、load尝试／实际新加载／幂等命中、模型请求、逻辑工具调用和网络尝试。同一工具有多个来源不能重复计费；独立工具不造Skill执行事件。用户界面红色错误与内部事件一致，不改颜色／隐藏错误来提升通过率。

### 11. 官方依据与采用范围

## Risks / Trade-offs

- [模型可能绕过Skill或误选Top 3] → 固定完整覆盖／部分覆盖／无Skill集，分别测Skill优先遵守率、工具Recall@3和实际选用准确率；不新增语义审计器承诺绝对正确。
- [扩大目录增加歧义] → 固定当前109项登记差异、参数说明和同名服务ID；只返回3项，不为填满而放宽范围。
- [首次索引与加载有延迟] → 持久化增量文档、单次构建合并及跨轮复用；分别测冷启动、暖索引、复用路径，不预设更快。
- [多个Skill规则或工具来源冲突] → 来源去重、按任务适用范围组织规则、加载控制串行；不能静默覆盖或无限并集。
- [能力跨轮保留误带旧许可] → 只保留材料／schema引用，每次披露和发送仍走现有实时范围检查，跨会话／企业不复用激活。
- [索引表迁移或共享图回归] → 自建空库与存量升级、RLS正反例；Basic QA策略独立，冻结图仅兼容回归。
- [旧测试继续奖励错误恢复] → 用A02/A03等正常复用用例要求零前置错误，恢复路径单列，不篡改旧报告。

## Skill 按需发现与请求协议

Skill 全目录只存在服务端。首次模型请求不包含目录名称、简介、触发词和材料版本；需要新的业务能力时优先 `search_skills(query)`，最多返回五个合法候选，模型选择后调用 `load_skill(skill_id, expected_version)`。没有命中或已加载 Skill 未覆盖的部分可继续使用独立工具搜索。纯交流、澄清、复述和有效能力复用不要求重复搜索。已加载但休眠的引用可携有效版本重新加载，不增加“先搜索才有权限”的执行门禁。

`agent.capability-selection.v2` 请求只包含 MCP 模式／集合及可选目录版本，不包含 Skill 选择对象。选择摘要版本为 3，规范内容为 `graph_id`、`mcp_mode`、排序去重的 `tool_ids`；提交正文摘要仍使用既有 v2，不混淆两个版本。前端、受理、原生认证、工具发现和 DeepAgents 不再消费或注入 `capability_skill_mode`、`capability_skill_id`、`capability_material_version`。旧客户端携这些字段或 `skill` 对象时明确拒绝。

新迁移保存旧 Skill 选择为只读历史材料后移除活动列，不改写历史摘要。旧选择不再允许 retry/resume，新请求和重新生成使用新协议；不能静默把旧限制解释为无约束。正式部署前需升级业务库并重新发起旧在途运行。历史事件的旧字段只保留读取兼容，新发受理事件不再包含这些字段。数据分析保留菜单策略的正常未匹配与故障失败关闭；封存图只移除共享旧选择分支，不恢复功能开发。
