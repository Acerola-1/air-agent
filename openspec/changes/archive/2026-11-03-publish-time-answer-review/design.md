# Design

## Context

见 `proposal.md - Why`。影响设计的事实：

- `OutputPublisher` 是三个业务图共用的唯一可见正文出口，生命周期为 `start → delta* → done|aborted`，且 `finish()` 要求完成正文是已发布前缀的延伸（append-only）。
- 现有知识政策有三处调用：`basic_qa/nodes.py` 的 `_planning_updates`、`data_analysis/nodes.py` 的 `call_model`、`common/output_streaming/answer.py` 的终答路径。前两处处理的是不公开草稿，第三处同时存在问题级整篇缓冲（`policy_bound`）和回答侧整篇替换。
- `citation_ids_from_messages` 只读 `knowledge_search` 回执；`web_search` 回执带 `results`（含 summary/snippet/content_excerpt）但从未进入政策视野。
- 图节点之间不共享流；任何“发布后再审核”的节点都无法撤回已发出的 delta。

## Goals / Non-Goals

**Goals:**

- 所有用户可见正文经过同一个发布前审核边界，规则可叠加、可观测、可测试。
- 判定单元降到句/段；制裁只作用于未发布单元，已发布前缀不变。
- 证据通道显式化：知识库、联网各有自己的读取与校验方式，未来可加监测。
- 移除中间节点策略调用，内部草稿保真。
- 为模型审核/审核子 Agent 留出检查接口，本次不实现。

**Non-Goals:**

- 不实现提示词注入防护、意图偏离校验或模型审核。
- 不改变联网审批、额度、编号分配和来源列表生成。
- 不恢复 `data_analysis` 的功能开发，只做共享判定兼容。
- 不改 append-only 契约，不支持撤回已发布正文。

## Decisions

### D1：审核只放在 Basic QA 终答循环

`basic_qa` 的 `compose_answer` 调用 `stream_final_answer(answer_review=True)`。审核在句子尚未 `publish` 之前替换该句。不新增图节点，不把钩子放进 `OutputPublisher.publish`。数据分析与溯源继续走原路径；`policy_bound` 仍供那些调用方使用，Basic QA 不再因问题正则进入该路径。

### D5：网页句由服务端改写，知识库句改为摘录

不靠“据…称”给模型原文分类。具体值能被某条已核验知识库原文逐字支撑时，发布该句对应的摘录，不发布模型改写。摘录只取包含该值的短句，写成普通正文加 `[[cite:<id>]]`；不贴目录 JSON、HTML 表格、整段检索原文，也不使用会渲染成斜体的引用块。同一段原文只出现一次。只有网页结果能逐字支撑时，发布服务端固定句，带上实际包含该值的 `[web:n]`，并写明未经知识库原文核验。同一标准在已核验原文里是另一个限值时，不改用网页数字。

被替换句里的数值记入本轮账本。后句再次出现该数值时，先做它自己的证据检查：知识库或该句引用的网页能够支撑就按该证据发布，否则继续替换。数字后面跟着“个/项/年”这类计数或时间后缀时，不把整句当成复述。

### D2：本次用一个审核对象，不建插件运行时

`AnswerReview` 顺序处理未知引用和具体值。检查抛错时，法规句换成“暂时无法获取”，普通句继续。超时、shadow 和版本注册表不在本次实现。

### D3：证据读取显式覆盖所有通道

新增统一的证据快照：本轮知识库引用（`verified` 仍只表示身份/快照/权限）与联网结果（按 `[web:n]` 编号索引 summary/snippet/content_excerpt）。审核只读快照，不重新调用工具。

- 备选：让模型自己判断引用是否支持。否决：不可复现，且模型会“觉得”自己刚写的对。
- 备选：只保留知识库通道并禁止联网数字。否决：违反 `basic-qa-approval-websearch` 的“自有数据缺失”场景。

### D4：触发与制裁都在回答侧、按单元

正则只标记“这一句里有具体限值、文号或条款”。制裁只替换该句。被替换的数值记入本轮账本；后句有自己的证据时不拦截。

- 备选：按问题触发。否决：问题命中但回答只给背景时误杀；且会把整次生成锁进知识库通道。
- 备选：整篇替换。否决：丢弃同篇其他有依据内容，正是本次要修的问题。

### D6：Basic QA 不再走问题级 `policy_bound`

`answer_review=True` 时，问题命中正则不再进入 `_stream_policy_bound`。该路径和 `DELIVERY_MODE_POLICY_BOUND` 保留给未打开按句审核的调用方。Basic QA 的普通句子继续逐增量发布。

### D7：规划与草稿不进入审核

删除 `basic_qa/nodes.py::_planning_updates` 中的 `apply_answer_policy`。规划消息继续 `content=""`、`ui_visible=False`；`planning_draft` 保留模型原文。不修改 `data_analysis`。

### D8：失败策略分级

知识库“未检索/检索失败/无命中”必须区分：规范性单元一律失败关闭，但用户话术不同（失败说“暂时不可得”，无命中才说“未核到”）。非规范内容不因证据缺失阻断。检查自身异常按检查声明处理，默认对规范性单元失败关闭。

- 备选：全局 fail-open。否决：会把检索故障变成放行。
- 备选：全局 fail-closed。否决：会让闲聊和背景回答因审核故障不可用。

### D9：扩展接口

检查项以注册表接入、超时、shadow 和审核子 Agent 留作后续，本次不实现。本次只有 `AnswerReview` 的固定顺序，见 D2。

## Risks / Trade-offs

- [逐句替换可被跨句复述绕过] → `blocked_claims` 账本，后续单元命中同值同样拦截。
- [单元边界依赖 `SafeTextStream` 的切分，长句可能跨单元] → 单元未闭合时不发布；`blocked_claims` 对已闭合部分生效。
- [网页证据只做到字面包含，不能证明适用范围/否定] → 规范性单元仍以知识库原文为准；网页只支撑非规范数字。
- [正则召回有漏] → 本次不扩大正则覆盖；漏召回作为已知限制记录，后续用模型分类检查补。
- [删除 `with_server_citations` 可能让回答少一个自动角标] → 该行为本身在制造未声明的出处；由模型在正文中自行引用，服务端只校验。
- [`policy_bound` 不再产生] → 契约枚举保留，前端无需改动；文档标注兼容保留。
- [data_analysis 封存图受影响] → 只删除草稿侧调用，终答仍走同一发布器；不恢复功能开发，回归测试覆盖共享判定。

## Migration Plan

1. 删除规划/草稿侧 `apply_answer_policy`，补测试确认 `planning_draft` 保真。
2. 新增审核管道与决策类型，接入 `stream_final_answer` 的单元循环和最终确认。
3. 新增证据快照（知识库 + 联网），实现引用合法性与证据支撑检查。
4. 移除问题级 `policy_bound` 与 `_stream_policy_bound`，保留枚举。
5. 更新知识政策测试与契约文档；跑定向单测和真实联网冒烟。

回滚：审核管道以开关控制，关闭时退化为现有逐句引用检查；数据库与事件契约无迁移。

## Open Questions

- 监测类工具（MCP）的数值证据是否纳入同一快照，作为后续检查项单独评估。
- 无单位裸数字（如“35”）的规范性校验范围，本次沿用现有单位覆盖集，不扩大。
