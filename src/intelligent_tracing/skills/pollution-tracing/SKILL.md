# 污染过程与来向线索分析

> 内部参考材料：`intelligent-tracing` 图不调用 `find_skill`，本文件也不登记到在线可选
> Skill 目录。业务授权只来自 IAM 业务许可与平台冻结快照；选择 Skill 不能扩大取数范围。

## 适用范围

- 阶段一：PM2.5 小时过程；24 小时滑动均值只作补充统计，不是自然日均或法规评价。
- 阶段二：PM10、O3、NO2、SO2、CO 使用各自画像、单位与评价口径；O3 保留小时过程并计算日最大 8 小时，其他污染物未定义评价口径时明确说明，不套用 PM2.5。
- 不提供轨迹/PSCF。用户要求轨迹时说明能力不可用，可改为现有证据允许的风场关联分析。
- 不确认具体企业、排口、源类、贡献率、来源概率或源距离。

## 对话与分析入口

- 问候、能力与操作说明按本轮意图回答，不要求站点/时间，不取目录或监测数据。
- 明确请求分析时，仅补问缺失、冲突或歧义项；可在相同身份/企业/线程和有效上下文内继承用户明确续接的条件。半径仍需确认，范围为1–50km；默认污染物、时区及基线为PM2.5、北京时间及分析前七天。
- 每轮先提交结构化意图与条件草稿；会话内容只组合实际配置的可信能力/流程/边界条目，不能夹带未核验观测、法规或归因。
- 普通交流/澄清共用最终回复协议与历史，标记single_shot；已有报告不会因再次问候而重发。实际分析事实与画布仍须经过证据门禁。

## 分析前必须完成

1. 站点/区域、污染物、带时区时间窗、调查半径、基线窗口和策略版本必须由服务端校验并冻结；名称不能作为唯一标识。
2. 同名多站或时间歧义时先补问；授权站点目录可用于消歧，污染观测与气象取数须等请求冻结后进行。
3. 数据委派必须使用冻结请求；子任务描述不得替代请求或授权。

## 分析分层

- 空间格局：`isolated` / `multi_station_sync` / `regional_contiguous` / `mixed` / `unknown`，只描述观测现象。
- 过程解释：`local_accumulation_consistent` / `transport_association` / `mixed` / `insufficient`。传输关联必须同时具备空间有序、上风向先升、合理滞后和风场一致性等组合证据，并讨论共同静稳等替代解释。
- 源类假设：只能放在 `source_hypotheses`，明确标记“待核查、未识别”，不得进入正式结论或提升证据等级。

## 输出要求

- 分析事实与结论只发布服务端验证后的 `ValidatedReport` 正文与画布；聊天、画布、持久化和历史回读使用同一版本与内容摘要。普通交流使用单独校验的会话计划，不生成报告引用。
- 保留有来源的完整率、同步率等百分比和“无法计算贡献率”的限制说明。
- 禁止无证据的越级归因，即使没有禁词也不能放行。
- 固定限制：`trajectory_unavailable`、`emission_inventory_missing`、`no_chemical_composition`；按实际补充覆盖、基线、风场、网格同源等问题。
- 法规超标、平台等级和统计异常分开；缺少适用阈值/版本/平均时间时只输出统计变化。
