# 达标可行性研判

## 详细规则入口

- 本文件只用于技能识别、路由摘要和通用约束；完整执行流程位于 `references/fast.md` 或 `references/expert.md`。
- 系统已按当前模式把对应详细规则内联在本提示词 `=====` 分隔线之后，直接按该规则执行数据获取、校验、缺失处理和输出组织；不要用本文件摘要替代详细规则。

## 执行边界

- 仅负责本技能的数据查询、结果校验和输出组织；回答面向普通业务用户，不暴露内部实现细节。
- 用户询问保良、达标、达标可能性、达标压力、避免重污染、规避污染等级、是否触发重污染预警、AQI 或污染物是否会超过阈值、剩余控制空间时，属于本技能。
- 用户只询问当前 AQI、空气质量等级、首要污染物或单日实况数据时，不属于本技能，除非问题明确要求“能否、可行性、风险、阈值、预警、保良、达标、重污染规避”。
- 主数据为空时，直接进入数据缺失处理，不得生成空模板、猜测指标或编造结论。

## 通用数据判读规则

本技能处理“保良、达标、规避污染等级”等可行性研判时，统一按以下口径解释工具返回数据；不得把工具的原始 prompt、字段说明或 JSON 结构写入最终回答。

### 主数据字段口径

- `name`：行政区划、城市、区县或站点名称。
- `value`：当前小时或当前时点的污染物浓度/AQI 数值。
- `countValue`：当日截至当前时点的累计浓度、累计 AQI 或累计评价值。
- `countLevel`：`countValue` 对应的空气质量等级；若工具只返回数字等级，按 1=优、2=良、3=轻度污染、4=中度污染、5=重度污染、6=严重污染解释。
- `remaining`：为达成目标等级或规避目标污染等级，后续时段允许的剩余控制值、剩余空间或控制阈值。

### 可行性判定口径

- `remaining` 为“无法完成”或同义文本时，判定为“不可行/无法实现”，并说明今日按当前数据口径无法达成目标。
- `remaining` 为数值时，先与 `countValue` 在同一口径下比较：`countValue < remaining` 表示仍有控制空间，目标达成相对容易；`countValue >= remaining` 表示剩余空间不足或控制压力较大，判定为有风险或不可行。
- 若工具已返回明确可行性结论，以工具结论为主；字段比较只用于解释原因和差距，不得反向覆盖工具结论。
- 若 `countValue`、`remaining` 或目标污染物缺失，不能给确定性结论，必须进入数据缺失处理。
