# 权限 P0 工具需求

本文档描述权限审查链路优先需要接入的两个 P0 工具：

- `get_user_profile`：获取当前用户可信权限画像。
- `resolve_region_scope`：将用户问题中的行政区解析为标准行政区对象。

## 1. get_user_profile

### 作用

获取当前用户的可信权限画像，作为权限审查的用户侧输入。权限模块不应长期依赖前端或提示词透传用户行政区，应优先使用该工具结果。

### 入参

```json
{
    "user_id": "u123"
}
```

| 字段      | 必需 | 说明                                                       |
| --------- | ---- | ---------------------------------------------------------- |
| `user_id` | 是   | 当前登录用户唯一标识。也可由调用方用登录态上下文映射得到。 |

### 出参

```json
{
    "found": true,
    "user_id": "u123",
    "bound_region": {
        "level": "district",
        "name": "西湖区"
    },
    "city": {
        "name": "杭州市"
    },
    "province": {
        "name": "浙江省"
    },
    "frequent_regions": []
}
```

| 字段                 | 必需     | 说明                                                                 |
| -------------------- | -------- | -------------------------------------------------------------------- |
| `found`              | 是       | 是否找到用户权限画像。                                               |
| `user_id`            | 是       | 用户唯一标识。                                                       |
| `bound_region`       | 是       | 用户直接绑定的行政区。`level` 取值：`province`、`city`、`district`。 |
| `bound_region.level` | 是       | 用户绑定层级。                                                       |
| `bound_region.name`  | 是       | 用户绑定行政区标准名称。                                             |
| `city`               | 条件必需 | 用户所属地市。地市级、区县级用户必须返回；省级用户可为空。           |
| `province`           | 是       | 用户所属省份。                                                       |
| `frequent_regions`   | 否       | 用户常访问区县列表。目前返回空数组。                                 |

### 层级示例

省级用户：

```json
{
    "found": true,
    "user_id": "u_province",
    "bound_region": {
        "level": "province",
        "name": "浙江省"
    },
    "city": null,
    "province": {
        "name": "浙江省"
    },
    "frequent_regions": []
}
```

地市级用户：

```json
{
    "found": true,
    "user_id": "u_city",
    "bound_region": {
        "level": "city",
        "name": "杭州市"
    },
    "city": {
        "name": "杭州市"
    },
    "province": {
        "name": "浙江省"
    },
    "frequent_regions": []
}
```

区县级用户：

```json
{
    "found": true,
    "user_id": "u_district",
    "bound_region": {
        "level": "district",
        "name": "西湖区"
    },
    "city": {
        "name": "杭州市"
    },
    "province": {
        "name": "浙江省"
    },
    "frequent_regions": []
}
```

### 异常/未命中

```json
{
    "found": false,
    "user_id": "u123",
    "error_code": "USER_PROFILE_NOT_FOUND",
    "message": "未找到用户权限画像"
}
```

建议错误码：

| 错误码                     | 说明                     |
| -------------------------- | ------------------------ |
| `USER_PROFILE_NOT_FOUND`   | 未找到用户画像。         |
| `USER_PROFILE_UNAVAILABLE` | 用户画像服务不可用。     |
| `INVALID_USER_ID`          | 用户 ID 为空或格式非法。 |

## 2. resolve_region_scope

### 作用

将用户问题中的行政区名称、简称、别名解析为唯一、标准、带层级和父级关系的行政区对象。权限模块使用该结果与用户权限画像比较，判断同省、同市、层级是否合法。

### 入参

```json
{
    "query": "西湖区",
    "city": "杭州市",
    "province": "浙江省"
}
```

| 字段          | 必需 | 说明                                                                                             |
| ------------- | ---- | ------------------------------------------------------------------------------------------------ |
| `query`       | 是   | 用户提到的行政区名称、简称、别名。示例：`西湖区`、`杭州`、`浙江`。                               |
| `city`        | 否   | 消歧上下文-地市名称，用于处理重名区县。示例：查询"金水区"时传入"郑州市"，避免匹配到其他城市的金水区。 |
| `province`    | 否   | 消歧上下文-省份名称，用于处理重名地市/区县。示例：查询"朝阳区"时传入"北京市"，避免匹配到长春市的朝阳区。 |

### 消歧参数使用建议

权限校验链路只需要解析出请求行政区本身及其父级关系，不需要查询 children。调用方应按查询层级最小化传递消歧参数：

| 查询对象 | 建议传参 |
| --- | --- |
| 省级，如“河南省” | 只传 `query`，不传 `city` |
| 地市，如“郑州市” | 可传 `province` 消歧 |
| 区县，如“金水区” | 可传 `city` 和 `province` 消歧 |

### 出参：唯一命中

```json
{
    "found": true,
    "ambiguous": false,
    "region": {
        "level": "district",
        "name": "西湖区"
    },
    "city": {
        "name": "杭州市"
    },
    "province": {
        "name": "浙江省"
    },
    "children": []
}
```

| 字段           | 必需       | 说明                                                   |
| -------------- | ---------- | ------------------------------------------------------ |
| `found`        | 是         | 是否解析成功。                                         |
| `ambiguous`    | 是         | 是否存在重名或多候选。                                 |
| `region`       | 命中时必需 | 解析出的行政区本体。                                   |
| `region.level` | 命中时必需 | 行政区层级：`province`、`city`、`district`。           |
| `region.name`  | 命中时必需 | 行政区标准名称。                                       |
| `city`         | 条件必需   | 所属地市。区县级、地市级结果必须返回；省级结果可为空。 |
| `province`     | 命中时必需 | 所属省份。                                             |
| `children`     | 否         | 下级行政区列表。权限校验链路不依赖该字段。 |

### 出参：重名/多候选

```json
{
    "found": false,
    "ambiguous": true,
    "candidates": [
        {
            "region": {
                "level": "district",
                "name": "西湖区"
            },
            "city": {
                "name": "杭州市"
            },
            "province": {
                "name": "浙江省"
            }
        },
        {
            "region": {
                "level": "district",
                "name": "西湖区"
            },
            "city": {
                "name": "南昌市"
            },
            "province": {
                "name": "江西省"
            }
        }
    ],
    "message": "存在多个同名行政区，请提供省市上下文"
}
```

### 出参：未命中

```json
{
    "found": false,
    "ambiguous": false,
    "candidates": [],
    "error_code": "REGION_NOT_FOUND",
    "message": "未找到匹配行政区"
}
```

建议错误码：

| 错误码                       | 说明                               |
| ---------------------------- | ---------------------------------- |
| `REGION_NOT_FOUND`           | 未找到行政区。                     |
| `REGION_AMBIGUOUS`           | 行政区存在多个候选，且上下文不足。 |
| `REGION_SERVICE_UNAVAILABLE` | 行政区服务不可用。                 |
| `INVALID_REGION_QUERY`       | 入参为空或格式非法。               |

## 2.1 list_region_children / 本地下级展开 helper

### 作用

集合/下钻查询需要把父级行政区展开为下级行政区列表，例如“郑州市下的区县”必须展开为郑州市下辖区县后逐项校验，不能按郑州市本级汇总继续查询。

### 入参

```json
{
    "parent_query": "郑州市",
    "parent_level": "city",
    "child_level": "district",
    "province": "河南省"
}
```

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `parent_query` | 是 | 父级行政区名称或别名。 |
| `parent_level` | 是 | 父级层级，当前至少支持 `city`。 |
| `child_level` | 是 | 目标下级层级，当前至少支持 `district`。 |
| `province` | 否 | 父级地市消歧省份。 |

### 出参

```json
{
    "found": true,
    "parent": {"name": "郑州市", "level": "city"},
    "children": [
        {"name": "中原区", "level": "district", "data_type": "detail"},
        {"name": "二七区", "level": "district", "data_type": "detail"}
    ]
}
```

验收样例：

- `郑州市下的区县PM2.5月均值分别是多少？` 应写入多个区县级 `permission_query_overrides.regions`。
- 展开失败时应返回可解释的拒绝或部分拒绝上下文，不得把 `郑州市` 本级结果当作区县明细。

## 3. 权限链路使用方式

典型流程：

1. 调 `get_user_profile(user_id)` 获取用户可信权限画像。
2. 从用户问题中抽取 `regions` 区域请求列表。单区域也使用一项列表表达；多区域、混合层级和集合父级不得压缩到单个 `city` 字段。
3. 对 `regions` 中每个实际查询区域项逐个调用 `resolve_region_scope`，传入该项自己的 `text`、`city_hint`、`province_hint` 和 `level_hint`。
4. 对每个标准区域独立构造权限事实并调用规则引擎。权限模块比较：
    - 用户 `bound_region.level` 与请求 `region.level` 是否层级允许。
    - 用户 `city.name`/`province.name` 与请求 `city.name`/`province.name` 是否同市/同省。
    - 是否命中时间豁免窗口。
5. 输出 `PermissionResult`，其中：
    - `permission_query_overrides.regions` 是后续实际查询区域列表。
    - `permission_result.region_results` 记录每个请求区域的 `requested`、`resolved`、`status`、`query_region`、`legal_time_span`、`reason` 和 `correction_text`。
    - `allowed_region` 和 `permission_query_overrides.region` 仅用于单区域兼容；存在 `regions` 时不得覆盖完整区域列表。

### regions 输入契约

```json
{
    "region_mode": "multi_explicit",
    "regions": [
        {
            "text": "郑州市",
            "level_hint": "city",
            "province_hint": "河南省",
            "city_hint": null,
            "source": "explicit",
            "role": "query",
            "child_level": null
        },
        {
            "text": "金水区",
            "level_hint": "district",
            "province_hint": "河南省",
            "city_hint": "郑州市",
            "source": "explicit",
            "role": "query",
            "child_level": null
        }
    ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `text` | 用户问题中的行政区文本或系统补全区域名称。 |
| `level_hint` | 该项层级提示：`province`、`city`、`district`。 |
| `province_hint` | 该项省份消歧上下文。 |
| `city_hint` | 该项城市消歧上下文，主要用于区县解析。 |
| `source` | 区域来源：`explicit`、`auto_fill`、`collection_parent`、`collection_child`、`permission_replacement`。 |
| `role` | 区域角色：`query`、`collection_parent`、`collection_child`。 |
| `child_level` | 集合/下钻查询的目标下级层级，普通查询为空。 |

### region_results 输出契约

```json
{
    "requested": {"text": "金水区", "source": "explicit", "level_hint": "district"},
    "resolved": {"name": "金水区", "level": "district", "data_type": "detail"},
    "status": "replaced",
    "query_region": {"name": "新郑市", "level": "district", "data_type": "detail"},
    "legal_time_span": null,
    "reason": "请求行政区超出权限范围，已替换为有权限的行政区",
    "correction_text": "因数据权限限制，已为您调整查询区域。",
    "permission_result": {"permitted": false, "fix_strategy": "replace_region"}
}
```

`status` 至少应区分：`allowed`、`replaced`、`rejected`、`time_truncated`、`auto_filled`。

## 4. 最低可用要求

P0 阶段最少必须保证：

- 用户画像能稳定返回 `bound_region`、`city`、`province`。
- 行政区解析能稳定区分同名区县。
- 行政区解析结果必须有 `region.level`。
- 对区县级结果，必须返回所属 `city` 和 `province`。
- 对地市级结果，必须返回所属 `province`。
- 工具不能确定时返回 `found=false` 或 `ambiguous=true`，不要猜。

| 类/方法                               | 用途                         |
| ------------------------------------- | ---------------------------- |
| `UserCache.getUser()`                 | 根据 userId 获取 UserWebVO   |
