# 并发压力测试执行器

流程：[Agent 性能与并发压力测试流程](pressure-testing-workflow.md)。本页定义执行器接口、验收要求和运行交接。

## 实现状态

Locust 产品适配器待实现与验收。可复用 `scripts/unified_campaign/sender.py` 的 BFF/SSE/台账关联解析，以及 `scripts/product_chat_perf/` 的资源采集和监督模块。

适配器验收通过后，在此登记实际文件路径、Locust 版本、运行命令和验收证据。真实测试使用经登记的执行器。

## 适配器要求

1. 使用 Locust 调度虚拟用户和生成统计。适配器建议路径为 `scripts/product_chat_perf/locustfile.py`。依赖通过 uv 项目和锁文件声明，选用经过协议与并发校准的版本。
2. 通过显式参数或 `PERF_PLAN_PATH` 读取计划，发送前校验字段、实际实例、环境授权、预算、输出目录和监督配置。SSO 会话从受保护引用读取，保留 IAM、租户和 RLS 校验。
3. 每个虚拟用户串行执行独立线程问答，每次提交使用唯一幂等键并保存台账关系。读取完整 SSE，记录首正文、流结束和可信确认；失败保留在对应分母。客户端应与 Locust 的协作模型兼容，实际并发由采样确认。
4. 按计划执行预热、爬坡、稳定准备、测量、排空和边界复测。请求阶段在发送时固定，完成吞吐按实际结束窗口计算；按模型、负载和 cohort 分组输出。
5. 所有阶段共用发送前原子预留的逻辑请求预算，墙钟从任务启动起计。分别记录物理模型调用、重试和 Token；硬用量限制须有对应计量和执行机制。
6. 独立资源监督先于适配器导入启动，分别采样宿主、发压器和组件。服务合计包括容器 guest 与经身份核对的宿主应用进程树；明确 VM/内核开销及共享页的计数口径。必需采集缺失时停止新增负载。
7. 从计划读取资源预算、阈值和阶段基线，验证超限停止与采集失败路径。资源紧急停止后核对未知运行；组件收尾依据启动归属，仅作用于本任务拥有的对象。
8. 逐步落盘请求、实际在途、阶段、资源和 SLO 分母，报告可由原始明细重算。输出目录必须唯一，中断后保留已采集数据。

## 受控验收

使用小型回环模拟服务及有界进程验证：

- 慢响应下持续补发、实际多路 SSE 和目标在途达成。
- 首正文排除工具/心跳事件；完整流、非空答案与可信台账确认。
- 时间和样本门槛、发送阶段归属、完成窗口吞吐、错误与未知分母。
- 全局预算无超发、资源超限停止、采集失败关闭、未知提交核对。
- 只停止自有发压进程及经确认属于本轮启动的组件。

验收结果须包含实际执行参数、明细与退出状态。通过后登记可复用运行命令，再按已授权计划调用真实服务。

## 运行准备命令

从仓库根目录检查服务状态和工具参数：

```bash
.venv/bin/python deployment/run_separated_local.py status
.venv/bin/python -m scripts.product_chat_perf.local_resources --help
.venv/bin/python -m scripts.product_chat_perf.startup_guard --help
```

实际负载命令由验收后的适配器提供。阶段计划和全局预算由执行器主动停止，资源监督独立运行，凭据从受保护引用读取。

## 执行任务模板

> 按 `docs/performance/pressure-testing-workflow.md` 执行一轮 `AGENT-CONCURRENCY-v1.0`。核对执行器的接口与验收状态；适配器缺失时，先按本页要求实现并完成受控验收。复制计划模板，填写本机实际资源、模型、题库、账号企业、SLO、授权、总预算、资源保护和保留策略。服务正常、代表题成功、监督可用后，从 C1 开始持续阶梯升压，按流程完成候选和相邻档复测。记录首正文、完整时延、成功率、成功吞吐、实际在途及资源。触发停止条件时停止新增负载、排空并核对未知运行。若发压器或宿主保护先到限，报告确认下界及测量限制。将明细和报告保存到独立时间目录，更新结果索引。

任务发起方需指定：模型、可用环境、账号企业、总时间和逻辑请求预算、资源保护配置、数据保留策略。执行器按任务的授权范围工作。
