# 富输出架构设计文档 (Rich Output Architecture)

> **文档版本**: v1.0  
> **创建日期**: 2025-07  
> **适用范围**: DeepAgent 工作流 MCP 工具输出 → 前端渲染

---

## 1. 概述与目标

### 1.1 要解决的问题

MCP 工具不只能返回文字数据，还可以返回 ECharts 图表、文件下载、图片、结构化表格等各类富内容。这些富内容需要：

- 被后端从 `ToolMessage` 中正确识别并提取
- 通过 `writer` 以结构化事件推送给前端
- 前端按类型分支渲染，不依赖后端硬编码逻辑

### 1.2 设计目标

| 目标             | 说明                                                  |
| ---------------- | ----------------------------------------------------- |
| **类型可扩展**   | 新增输出类型只需前端加一个 `case`，后端无需改动       |
| **展示模式灵活** | 由 MCP 工具或 SKILL.md 声明大画布 / 内嵌文字 / 弹窗等 |
| **多输出有序**   | 一次工具调用可产出多条富输出，保留顺序                |
| **协议自描述**   | 前端按 `output_type` 渲染，无需了解后端业务逻辑       |

### 1.3 设计原则

```
约定优于配置，配置优于代码
MCP 工具自描述 → Skills 可覆盖 → 系统默认
```

## 2. 核心概念

### 2.1 富输出 (Rich Output)

一次 MCP 工具调用可产生零条或多条**富输出**，每条是一个自描述的结构化数据包：

- **类型标识** (`output_type`)：告知前端用什么渲染器
- **展示模式** (`display_mode`)：告知前端在哪里、以何种尺寸展示
- **数据载荷** (`data`)：渲染所需的具体内容
- **元信息**：标题、来源工具、顺序号等

### 2.2 输出类型 (OutputType)

| `output_type` | 说明         | 典型渲染方式              |
| ------------- | ------------ | ------------------------- |
| `chart`       | ECharts 图表 | `echarts.setOption(data)` |
| `file`        | 文件下载     | 下载按钮 / 链接           |
| `image`       | 图片展示     | `<img>` 或图片查看器      |
| `table`       | 结构化表格   | 富文本表格组件            |
| `map`         | 地图可视化   | 高德 / Leaflet            |
| `iframe`      | 嵌入页面     | `<iframe>`                |
| `html`        | 富 HTML 片段 | `innerHTML`（需沙箱）     |

> 新增类型时：MCP 工具返回对应 `output_type`，前端增加渲染分支，**后端提取逻辑无需修改**。

### 2.3 展示模式 (DisplayMode)

| `display_mode` | 说明                 | 适用场景                  |
| -------------- | -------------------- | ------------------------- |
| `canvas`       | 大画布，全宽独占一行 | 复杂图表、地图、完整表格  |
| `inline`       | 嵌入在消息气泡内     | 小图、缩略图、下载按钮    |
| `modal`        | 点击触发弹窗         | 大图预览、完整报告        |
| `sidebar`      | 右侧浮动侧边栏       | 辅助数据、对比图          |
| `float`        | 悬浮卡片             | 实时监控小卡片            |
| `none`         | 不产生富输出         | 纯数据工具，仅供 LLM 使用 |

## 3. 整体数据流

```
用户提问
    │
    ▼
DeepAgent 调用 MCP 工具
    │
    ▼
MCP 服务器返回 JSON（含 rich_outputs[]）
    │
    ▼
ToolMessage 进入流
    │
    ▼
_extract_rich_outputs_from_message()
    ┌────────────────────────────────────────────┐
    │ 优先级1: rich_outputs[]（MCP 工具自声明）   │
    │ 优先级2: SKILL.md output-hints（补全缺省）  │
    └────────────────────────────────────────────┘
    │
    ▼
规范化 RichOutput 列表
    │
    ▼
LLM 生成文字（流式 writer message）
    │
    ▼
富输出批量推送（writer rich_output）
    │
    ▼
前端按 output_type 分支渲染
```

## 4. MCP 工具返回格式规范

### 4.1 标准格式

所有 MCP 工具统一使用以下顶层结构：

```json
{
  "code": 200,
  "success": true,
  "data": {
    "llm_data": { ...业务数据，交给 LLM 生成文字分析... },
    "rich_outputs": [ ...富输出列表，交给前端渲染... ]
```

- `llm_data`：LLM 可读的业务数据，不含渲染逻辑

## 5. SKILL.md 配置规范

SKILL.md 可通过 `output-hints` 为特定工具声明输出偏好，**优先级低于 MCP 响应中的 `rich_outputs`**：当 MCP 已声明某字段时，hints 不覆盖；当 MCP 未声明时，hints 补全缺省值。

### 5.1 头部字段扩展

在 SKILL.md 的 YAML front matter 中新增 `output-hints`：

```yaml
---
name: broadcast-hour
description: 小时播报数据分析查询
version: 1.0.0
allowed-tools: broadcastHour get_beijing_time

output-hints:
    broadcastHour:
        display_mode: canvas # 覆盖展示模式
        chart_subtype: line # 覆盖图表子类型（output_type=chart 时生效）
        title_template: "{city}小时播报趋势" # 标题模板（{} 为占位符，预留）
    get_beijing_time:
        display_mode: none # 明确声明：该工具不产生富输出
---
```

### 5.2 output-hints 字段说明

| 字段             | 类型   | 说明                                                  |
| ---------------- | ------ | ----------------------------------------------------- |
| `display_mode`   | string | 覆盖展示模式；`none` 表示忽略该工具的所有富输出       |
| `chart_subtype`  | string | 图表子类型，仅 `output_type=chart` 时生效             |
| `title_template` | string | 标题模板，`{}` 内为变量占位符（当前预留，未实现替换） |

### 5.3 完整示例

```yaml
---
name: integrated-index-ratio
description: 综合指数排名分析
version: 1.0.0
allowed-tools: getIntegratedIndexRatio generateIndexReport get_beijing_time

output-hints:
    getIntegratedIndexRatio:
        display_mode: canvas
        chart_subtype: bar
        title_template: "{region}综合指数排名"
    generateIndexReport:
        display_mode: inline
    get_beijing_time:
        display_mode: none
---
```

## 6. 系统处理流程

### 6.1 提取优先级

```
ToolMessage 解析
       │
       ▼
 ┌─────────────────────────────────────────────────────┐
 │ 1. SKILL.md output-hints 声明 display_mode: none？  │
 │    YES → 直接跳过，无富输出                          │
 │    NO  → 继续 ↓                                     │
 └──────────────────────────┬──────────────────────────┘
                            │
                            ▼
 ┌─────────────────────────────────────────────────────┐
 │ 2. MCP 响应中存在 rich_outputs[] 且非空？            │
 │    YES → 使用 rich_outputs，以 output-hints 补全     │
 │            缺省字段（display_mode / chart_subtype）  │
 │    NO  → 无富输出，仅 llm_data 流向 LLM              │
 └─────────────────────────────────────────────────────┘
```

### 6.2 output-hints 覆盖规则

| 场景                                      | 行为                                  |
| ----------------------------------------- | ------------------------------------- |
| MCP 已声明 `display_mode`，hints 也有配置 | **MCP 优先**，hints 不覆盖            |
| MCP 未声明 `display_mode`，hints 有配置   | **hints 补全**                        |
| hints `display_mode: none`                | 无论 MCP 返回什么，该工具**跳过**     |
| MCP 未返回 `rich_outputs`                 | **无富输出**，仅 llm_data 供 LLM 使用 |

### 6.3 推送时序

```
① progress  → "正在调用 'broadcastHour'"
② [工具执行完成，ToolMessage 入库]
③ message   → LLM 文字分析（流式逐 token）
④ rich_output → 图表、文件等（批量，按 sequence 顺序）
⑤ expanded_questions → 扩展问题
```

> **文字先于富输出推送**：文字中可能有对图表的引用（"如下图所示…"），前端先渲染文字，再追加富输出到对应位置，顺序自然。

## 8. 前端接收规范

### 8.1 事件分发

```typescript
function onStreamEvent(event: StreamEvent) {
    switch (event.type) {
        case "progress":
            showProgressIndicator(event.message);
            break;

        case "message":
            appendToChat(event.message); // 流式追加文字
            break;

        case "rich_output":
            handleRichOutput(event); // 富输出分发渲染
            break;

        case "expanded_questions":
            renderExpandedQuestions(event.message);
            break;

        case "permission_error":
            showPermissionError(event.message);
            break;
    }
}
```

### 8.2 富输出渲染分发

```typescript
function handleRichOutput(event: RichOutputEvent) {
    const {
        output_type,
        display_mode,
        sequence,
        title,
        chart_subtype,
        message,
    } = event;
    const container = resolveContainer(display_mode, sequence);

    switch (output_type) {
        case "chart":
            renderECharts({ container, option: message, title, chart_subtype });
            break;

        case "file":
            renderFileDownload({ container, title, ...message });
            break;

        case "image":
            renderImage({ container, title, ...message });
            break;

        case "table":
            renderTable({ container, title, ...message });
            break;

        case "map":
            renderMap({ container, title, ...message });
            break;

        case "iframe":
            renderIframe({ container, title, ...message });
            break;

        case "html":
            renderHtml({ container, title, ...message }); // 注意 XSS 沙箱
            break;

        default:
            console.warn(
                `[RichOutput] 未知类型: ${output_type}，原始数据:`,
                message,
            );
    }
}
```

### 8.3 display_mode 容器映射

| `display_mode` | 容器位置             | 尺寸建议                       |
| -------------- | -------------------- | ------------------------------ |
| `canvas`       | 消息气泡下方独占区域 | 全宽，高 400px（图表）/ 自适应 |
| `inline`       | 嵌入消息气泡末尾     | 宽 ≤ 200px，行内块             |
| `modal`        | 点击触发全屏弹窗     | 视口 90%                       |
| `sidebar`      | 右侧浮动侧边栏       | 宽 360px，全高                 |
| `float`        | 右下角悬浮卡片       | 固定 300×200px                 |

### 8.4 多输出排序

前端按 `sequence` 字段升序排列。同一 `display_mode` 区域内的多条富输出依次堆叠渲染。

## 9. 代码实现指引

### 9.1 `_extract_rich_outputs_from_message`

替换 `deepagent_integration.py` 中现有的 `_extract_chart_data_from_message`：

```python
def _extract_rich_outputs_from_message(
    self,
    msg: Any,
    rich_output_list: List[Dict[str, Any]],
    skill_output_hints: Optional[Dict[str, Any]] = None,
) -> None:
    """从 ToolMessage 中提取富输出列表.

    流程：output-hints none 检查 → rich_outputs[] 提取 → 否则无富输出

    Args:
        msg: ToolMessage 对象
        rich_output_list: 富输出累积列表（就地追加）
        skill_output_hints: 当前 Skill 的 output-hints 配置
    """
    import json

    tool_name: str = getattr(msg, "name", "") or ""
    content = getattr(msg, "content", "")

    # 统一内容为字符串
    if isinstance(content, list):
        content = "".join(
            b.get("text", "")
            for b in content
            if isinstance(b, dict) and b.get("type") == "text"
        )

    if not content or not isinstance(content, str):
        return

    # 读取该工具的 output-hints
    hints: Dict[str, Any] = (skill_output_hints or {}).get(tool_name, {})

    # output-hints 明确声明 none → 跳过
    if hints.get("display_mode") == "none":
        return

    # 解析 JSON
    try:
        parsed = json.loads(content)
    except (json.JSONDecodeError, TypeError):
        return

    if not isinstance(parsed, dict):
        return
    if not (parsed.get("success") is True and parsed.get("code") == 200):
        return

    raw_data = parsed.get("data", {})
    if not isinstance(raw_data, dict):
        return

    # ── rich_outputs[]（MCP 工具自声明）──────────────────────────────
    if "rich_outputs" in raw_data and isinstance(raw_data["rich_outputs"], list):
        base_seq = len(rich_output_list) + 1
        for i, item in enumerate(raw_data["rich_outputs"]):
            if not isinstance(item, dict):
                continue
            # hints 仅补全 MCP 未声明的字段，不覆盖已声明的
            rich_output_list.append({
                "output_type":   item.get("output_type", "chart"),
                "display_mode":  item.get("display_mode") or hints.get("display_mode", "canvas"),
                "chart_subtype": item.get("chart_subtype") or hints.get("chart_subtype", "line"),
                "title":         item.get("title") or hints.get("title_template", tool_name),
                "tool_name":     tool_name,
                "sequence":      base_seq + i,
                "data":          item.get("data"),
            })
        return
    # rich_outputs 不存在或为空 → 无富输出，llm_data 单独流向 LLM
```

### 9.3 读取 SKILL.md output-hints

```python
def _get_current_skill_hints(self, state: Dict[str, Any]) -> Dict[str, Any]:
    """读取当前激活 Skill 的 output-hints 配置.

    Args:
        state: 当前状态（含 intent_name、chat_mode）

    Returns:
        output-hints 字典，键为工具名，值为配置项
    """
    import yaml
    from pathlib import Path

    skill_name = state.get("intent_name", "")
    if not skill_name:
        return {}

    skill_file = (
        Path(__file__).parent
        / "skills"
        / f"skills_{state.get('chat_mode', 'fast')}"
        / skill_name
        / "SKILL.md"
    )
    if not skill_file.exists():
        return {}

    try:
        content = skill_file.read_text(encoding="utf-8")
        if content.startswith("---"):
            end = content.find("---", 3)
            if end != -1:
                front_matter = yaml.safe_load(content[3:end])
                return front_matter.get("output-hints", {})
    except Exception:
        pass

    return {}
```

### 11.2 通过 SKILL.md 覆盖展示模式

某 Skill 希望将图表以小图内嵌（而非大画布），且使用饼图：

```yaml
---
name: specific-date-city-aqi
description: 特定日期城市 AQI 查询
version: 1.0.0
allowed-tools: getCityAQI get_beijing_time

output-hints:
    getCityAQI:
        display_mode: inline # 小图内嵌，而非默认 canvas
        chart_subtype: pie # 饼图展示污染物构成
        title_template: "{city}污染物构成"
    get_beijing_time:
        display_mode: none # 纯工具，不产生富输出
---
```

即使 MCP 工具 `getCityAQI` 的 `rich_outputs` 中未声明 `display_mode`，系统也会从 `output-hints` 补全为 `inline`，图表将以小图嵌入文字而非独占大画布。

## 12. 设计决策记录

| 决策点                        | 选择                              | 原因                                                   |
| ----------------------------- | --------------------------------- | ------------------------------------------------------ |
| 唯一协议                      | `rich_outputs[]`，无其他入口      | 协议干净，无歧义；工具必须自描述，不依赖外部推断       |
| 两级覆盖                      | MCP 响应 > SKILL.md output-hints  | 工具最了解数据形态；Skill 最了解业务场景，两层各司其职 |
| `none` 检查优先于数据解析     | 先 none 检查，再解析 rich_outputs | 尽早短路，避免不必要的 JSON 解析和迭代                 |
| 文字先于富输出推送            | 先 message，后 rich_output        | 文字可引用图表，渲染顺序自然；前端追加式插入 DOM       |
| `sequence` 从 1 计            | 整数，同次工具调用内递增          | 支持多输出有序插入，前端直接排序                       |
| `display_mode: none` 显式声明 | 显式跳过，而非隐式忽略            | 对纯数据工具（如 `get_beijing_time`）明确表达意图      |
| hints 不覆盖 MCP 已声明字段   | MCP 字段优先，hints 仅补全缺省    | 工具最了解自身输出格式，hints 是辅助而非强制           |
