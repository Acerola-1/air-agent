# 附件系统重构设计文档

> **文档版本**: v1.1  
> **创建日期**: 2026-05-13  
> **适用范围**: MCP 服务端富输出协议 → 前端渲染协议

---

## 1. 目标与边界

附件系统用于承载 ECharts 图表、文件下载、图片、结构化表格、地图、HTML 片段等富内容。本文只约束 MCP 服务端和前端：

- MCP 服务端：负责生成自描述附件数据。
- 前端：负责按附件类型和展示模式渲染。

核心原则：

```text
MCP 服务端自描述输出
前端按协议渲染
```

---

## 2. 核心概念

### 2.1 附件输出

一次 MCP 工具调用可以产生零条或多条附件输出。每条附件输出必须是独立、完整、可自描述的数据对象。

每条附件输出包含：

- `output_type`：附件类型，决定前端使用哪个渲染器。
- `display_mode`：展示模式，决定前端放在哪里、以什么尺寸展示。
- `title`：用户可见标题。
- `data`：渲染所需载荷。
- `sequence`：同次响应内的排序号。

### 2.2 附件类型

| `output_type` | 说明         | 前端渲染方式                 |
| ------------- | ------------ | ---------------------------- |
| `chart`       | ECharts 图表 | `echarts.setOption(data)`    |
| `file`        | 文件下载     | 下载按钮、文件卡片           |
| `image`       | 图片         | `<img>`、图片预览器          |
| `table`       | 结构化表格   | 表格组件                     |
| `map`         | 地图         | 高德、Leaflet 或项目地图组件 |
| `iframe`      | 嵌入页面     | `<iframe>`                   |
| `html`        | HTML 片段    | 沙箱容器渲染                 |

### 2.3 展示模式

| `display_mode` | 说明                 | 典型场景                 |
| -------------- | -------------------- | ------------------------ |
| `canvas`       | 大画布，全宽独占区域 | 复杂图表、地图、大表格   |
| `inline`       | 嵌入消息或结果区域   | 小图、下载按钮、摘要卡片 |
| `modal`        | 点击后弹窗展示       | 大图预览、报告预览       |
| `sidebar`      | 侧边栏展示           | 辅助图表、对比结果       |
| `float`        | 悬浮卡片展示         | 实时小组件               |
| `none`         | 不展示附件           | 附件生成失败或无需展示   |

## 3. MCP 服务端返回协议

### 3.1 标准响应结构

所有支持附件的 MCP 工具应返回统一结构：

```json
{
    "code": 200,
    "success": true,
    "message": "success",
    "data": {
        "rich_outputs": [
            {
                "output_type": "chart",
                "display_mode": "canvas",
                "sequence": 1,
                "title": "小时 AQI 趋势",
                "chart_subtype": "line",
                "data": {
                    "xAxis": { "type": "category", "data": ["01:00", "02:00"] },
                    "yAxis": { "type": "value", "name": "AQI" },
                    "series": [
                        { "type": "line", "name": "AQI", "data": [45, 52] }
                    ]
                }
            }
        ]
    }
}
```

字段要求：

- `data`：响应载荷对象。
- `data.rich_outputs`：附件列表，只包含附件数据；无附件时返回空数组。
- 不定义 `llm_data` 字段；附件工具返回的大体积渲染数据由中间层旁路推送给前端，不作为 LLM 上下文数据资源。
- `data.rich_outputs[].data`：只放当前附件渲染需要的数据。
- `sequence`：同次响应内从 1 开始递增，前端按升序渲染。

### 3.2 图表附件

`chart` 类型的 `data` 必须是完整 ECharts option，前端可以直接传给 `setOption`。

```json
{
    "output_type": "chart",
    "display_mode": "canvas",
    "sequence": 1,
    "title": "绍兴市小时 AQI 趋势",
    "chart_subtype": "line",
    "data": {
        "tooltip": { "trigger": "axis" },
        "xAxis": { "type": "category", "data": ["01:00", "02:00", "03:00"] },
        "yAxis": { "type": "value", "name": "AQI" },
        "series": [{ "type": "line", "name": "AQI", "data": [45, 42, 38] }]
    }
}
```

`chart_subtype` 建议值：

- `line`
- `bar`
- `pie`
- `scatter`
- `heatmap`
- `radar`
- `gauge`
- `map`

### 3.3 文件附件

`file` 类型必须返回可下载地址，不应直接把文件二进制内容塞进响应。

```json
{
    "output_type": "file",
    "display_mode": "inline",
    "sequence": 2,
    "title": "完整数据报告",
    "data": {
        "filename": "aqi_report_20260513.xlsx",
        "download_url": "https://files.example.com/aqi_report_20260513.xlsx",
        "mime_type": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
        "size_bytes": 204800,
        "expires_at": "2026-05-14T00:00:00+08:00"
    }
}
```

文件要求：

- `download_url` 必须是有权限控制的临时地址或受控下载地址。
- `filename` 应使用用户可理解的业务名称。
- `mime_type` 和 `size_bytes` 应尽量提供，便于前端展示。
- `expires_at` 推荐提供，便于前端提示链接有效期。

### 3.4 图片附件

```json
{
    "output_type": "image",
    "display_mode": "modal",
    "sequence": 1,
    "title": "污染热力图",
    "data": {
        "url": "https://files.example.com/heatmap.png",
        "alt": "污染热力图",
        "width": 1920,
        "height": 1080,
        "mime_type": "image/png"
    }
}
```

### 3.5 表格附件

```json
{
    "output_type": "table",
    "display_mode": "canvas",
    "sequence": 1,
    "title": "城市 AQI 汇总表",
    "data": {
        "columns": [
            { "key": "city", "label": "城市", "width": 120 },
            { "key": "aqi", "label": "AQI", "width": 80, "sortable": true }
        ],
        "rows": [
            { "city": "北京", "aqi": 85 },
            { "city": "上海", "aqi": 62 }
        ],
        "total": 2
    }
}
```

### 3.6 地图附件

```json
{
    "output_type": "map",
    "display_mode": "canvas",
    "sequence": 1,
    "title": "全国 AQI 分布",
    "data": {
        "map_type": "china",
        "center": [116.4, 39.9],
        "zoom": 5,
        "layers": [
            {
                "type": "heatmap",
                "points": [{ "lat": 39.9, "lng": 116.4, "value": 85 }]
            }
        ]
    }
}
```

### 3.7 HTML 与 iframe 附件

HTML 和 iframe 类型必须遵守安全约束：

- HTML 片段不得包含未审核脚本。
- iframe URL 必须来自可信域名白名单。
- 前端必须使用沙箱策略渲染。

```json
{
    "output_type": "iframe",
    "display_mode": "canvas",
    "sequence": 1,
    "title": "外部报告预览",
    "data": {
        "url": "https://trusted.example.com/report/123",
        "height": 600
    }
}
```

## 4. MCP 服务端校验要求

MCP 服务端生成附件时应完成基础校验：

- `output_type` 必须属于前端支持的类型。
- `display_mode` 必须属于约定范围。
- `sequence` 不得重复。
- `title` 不得为空。
- 文件和图片必须返回 URL，不得返回大体积 base64。
- 图表必须返回合法 ECharts option。
- HTML 和 iframe 必须通过安全白名单。

错误响应示例：

```json
{
    "code": 500,
    "success": false,
    "message": "附件生成失败",
    "data": {
        "rich_outputs": []
    }
}
```

## 5. 前端事件协议

前端接收到的附件事件建议统一为：

```json
{
    "type": "rich_output",
    "output_type": "chart",
    "display_mode": "canvas",
    "sequence": 1,
    "title": "小时 AQI 趋势",
    "chart_subtype": "line",
    "message": {
        "xAxis": { "type": "category", "data": ["01:00", "02:00"] },
        "yAxis": { "type": "value", "name": "AQI" },
        "series": [{ "type": "line", "name": "AQI", "data": [45, 52] }]
    }
}
```

字段映射：

| MCP 字段                            | 前端事件字段    |
| ----------------------------------- | --------------- |
| `data.rich_outputs[].output_type`   | `output_type`   |
| `data.rich_outputs[].display_mode`  | `display_mode`  |
| `data.rich_outputs[].sequence`      | `sequence`      |
| `data.rich_outputs[].title`         | `title`         |
| `data.rich_outputs[].chart_subtype` | `chart_subtype` |
| `data.rich_outputs[].data`          | `message`       |

## 6. 前端渲染设计

### 6.1 事件分发

```typescript
function onStreamEvent(event: StreamEvent) {
    switch (event.type) {
        case "message":
            appendMessage(event.message);
            break;
        case "rich_output":
            renderRichOutput(event);
            break;
        case "progress":
            renderProgress(event.message);
            break;
        default:
            console.warn("未知事件类型", event);
    }
}
```

### 6.2 附件渲染分发

```typescript
function renderRichOutput(event: RichOutputEvent) {
    const container = resolveContainer(event.display_mode, event.sequence);

    switch (event.output_type) {
        case "chart":
            renderECharts(container, event.message, {
                title: event.title,
                subtype: event.chart_subtype,
            });
            break;
        case "file":
            renderFileCard(container, event.message, event.title);
            break;
        case "image":
            renderImage(container, event.message, event.title);
            break;
        case "table":
            renderTable(container, event.message, event.title);
            break;
        case "map":
            renderMap(container, event.message, event.title);
            break;
        case "iframe":
            renderSandboxedIframe(container, event.message, event.title);
            break;
        case "html":
            renderSandboxedHtml(container, event.message, event.title);
            break;
        default:
            renderUnsupportedAttachment(container, event);
    }
}
```

### 6.3 容器映射

| `display_mode` | 前端容器            | 尺寸建议              |
| -------------- | ------------------- | --------------------- |
| `canvas`       | 消息下方独立区域    | 宽 100%，高 360-520px |
| `inline`       | 消息内联区域        | 自适应内容宽度        |
| `modal`        | 弹窗入口 + 弹窗内容 | 最大 90vw / 90vh      |
| `sidebar`      | 右侧面板            | 宽 360-480px          |
| `float`        | 悬浮卡片            | 300x200px 起          |
| `none`         | 不渲染              | 无                    |

### 6.4 多附件排序

同一次响应的 `data.rich_outputs` 包含多条附件时，前端必须按 `sequence` 升序渲染。若缺失 `sequence`，按接收顺序追加。

### 6.5 降级策略

前端遇到未知 `output_type` 时，不应中断页面渲染，应展示通用附件卡片：

```text
暂不支持预览该附件
标题：{title}
类型：{output_type}
```

---

## 7. 前端安全要求

- `html` 类型必须经过沙箱渲染，不得直接注入主页面 DOM。
- `iframe` 必须校验 URL 白名单。
- `file.download_url` 下载前应走权限校验或签名 URL。
- 图片、文件链接过期时应给出明确提示。
- 图表 option 不得执行动态脚本。

## 9. 当前实现方案

### 9.1 中间件架构

项目已实现 `RichOutputMiddleware` 中间件（`src/common/middleware/rich_output_middleware.py`），作为 LangChain AgentMiddleware 拦截 MCP 工具调用结果：

```
MCP Tool → ToolMessage → RichOutputMiddleware → 前端事件流 + 精简 ToolMessage
```

核心职责：

1. **解析 MCP 响应**：将 MCP 返回的 `ToolMessage.content` 解析为 JSON
2. **提取富输出**：从 `data.rich_outputs[]` 提取附件数据
3. **推送前端事件**：通过 `runtime.stream_writer` 发送 `rich_output` 事件
4. **精简上下文**：将大体积附件数据替换为简洁摘要，避免污染 LLM 上下文

### 9.2 事件流格式

中间件推送的前端事件结构：

```json
{
    "node": "deepagent_executor",
    "type": "rich_output",
    "output_type": "chart",
    "display_mode": "canvas",
    "chart_subtype": "line",
    "title": "绍兴市昨日小时 AQI 趋势",
    "tool_name": "generate_hour_aqi_chart",
    "sequence": 1,
    "message": {
        "xAxis": { "type": "category", "data": ["01:00"] },
        "series": [{ "type": "line", "data": [45] }]
    }
}
```

字段映射规则：

- `data.rich_outputs[].data` → `message`（渲染载荷）
- `data.rich_outputs[].output_type` → `output_type`
- `data.rich_outputs[].display_mode` → `display_mode`
- `data.rich_outputs[].sequence` → `sequence`（缺失时按数组索引从 1 递增）
- `data.rich_outputs[].title` → `title`（缺失时回退到 `tool_name`）

### 9.3 上下文精简策略

原始 ToolMessage 被替换为：

```json
{
    "code": 200,
    "success": true,
    "message": "工具已生成 1 个附件：绍兴市昨日小时 AQI 趋势。附件已发送给前端渲染，附件内容不进入对话上下文。"
}
```

精简规则：

- 多附件时标题最多显示 5 个，超过则追加"等"
- `display_mode: "none"` 的附件不计入精简消息
- 非 `rich_outputs` 格式的响应保持原样

### 9.4 兼容性处理

中间件支持的 MCP 响应格式：

1. **标准格式**（推荐）：

    ```json
    {"code": 200, "success": true, "data": {"rich_outputs": [...]}}
    ```

2. **MCP 文本包装**：

    ```json
    [{ "type": "text", "text": "{\"code\": 200, ...}" }]
    ```

    中间件自动提取 `text` 字段并解析 JSON。

3. **非附件响应**：
   不含 `rich_outputs` 或 `rich_outputs` 为空的响应原样返回，不做处理。

### 9.5 测试覆盖

单元测试（`tests/unit_tests/test_rich_output_middleware.py`）覆盖：

| 测试场景                                                       | 验证点                                 |
| -------------------------------------------------------------- | -------------------------------------- |
| `test_rich_outputs_are_streamed_and_tool_message_is_compacted` | 附件事件正确推送、ToolMessage 被精简   |
| `test_non_attachment_tool_message_is_preserved`                | 非附件响应保持原样                     |
| `test_chart_data_tool_message_is_preserved`                    | 旧版 `chart_data` 格式不触发中间件处理 |

### 9.6 配置扩展点

中间件支持 `output_hints_cache` 参数，可为特定工具预设默认值：

```python
middleware = RichOutputMiddleware(
    output_hints_cache={
        "generate_hour_aqi_chart": {
            "display_mode": "canvas",
            "chart_subtype": "line",
            "title_template": "AQI 趋势图",
        }
    }
)
```

当 MCP 响应缺失字段时，从 hints 中回退取值。

## 10. 兼容与演进

兼容要求：

- `data.rich_outputs` 为空数组或缺失时，视为无附件。
- 新增 `output_type` 时，MCP 服务端可先返回，前端未支持时走降级卡片。

演进原则：

- MCP 服务端负责声明附件类型、展示方式和数据结构。
- 前端负责渲染分发和安全隔离。
- 中间层不应硬编码业务图表规则。
