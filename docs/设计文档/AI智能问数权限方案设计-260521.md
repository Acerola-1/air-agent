## 2. 总体设计原则

- **安全优先**：在原始权限模型之上做谨慎放宽，严禁越权泄露明细数据。
- **体验优先**：对高频短期查询放宽限制，自动修正时尽量保留用户语义（优先时间截断，其次行政区适配）。
- **粒度区分**：
  - 高细粒度（小时/日/周/累计）享受**7天宽免**。
  - 月粒度（`month`/`month_count`）享受**近两月宽免**。
  - 年粒度（`year`/`year_count`）享受**近两年宽免**。
- **透明告知**：任何自动修正必须在回答中明确告知原因及结果。



### 2.1 适用范围

本方案仅适用于 **AI 智能问数的实时查询场景**。以下场景不享受时间豁免规则，严格按基础行政区权限执行：
- 历史数据补查（查询时间范围超过当前日期前 1 年）；
- 批量数据导出（单次导出 > 1000 条记录）；
- 报表定时推送、离线数据同步等非交互式场景；
- 单次查询涉及超过 365 个时间点（如小时数据超过 8760 条、日数据超过 365 条）的大数据量导出场景。

## 3. 核心权限模型

### 3.1 基础行政区权限（无时间豁免时）

| 用户关联城市级别 | 可访问数据范围                                               | 禁止访问范围                               |
| :--------------- | :----------------------------------------------------------- | :----------------------------------------- |
| 省               | 本省所有地市**汇总**数据 + 全国各省**省级汇总**数据          | 本省所有区县数据 + 外省任何地市 / 区县数据 |
| 地市             | 本市所有区县**明细**数据 + 本省所有地市**汇总**数据 + 本省**省级汇总**数据 | 外省任何层级数据 + 本省其他地市的区县数据  |
| 区县             | 本区县**明细**数据 + 本市所有区县**明细**数据 + 本市**汇总**数据 | 外市 / 外省任何层级数据 + 本省省级汇总数据 |

> 关键修正说明：
>
> 省级用户**不能访问任何区县级数据**（包括本省区县），只能看到地市及以上层级的汇总数据
>
> 地市用户**只能访问本市的区县明细**，不能访问本省其他地市的区县数据
>
> 区县用户**不能访问省级汇总数据**，只能看到本市及以下层级的数据
>
> "汇总数据" 指仅包含指标合计值，无下钻维度；"明细数据" 指可下钻至区县 / 门店等细粒度维度。数据在存储上每个行政区层级均有一条记录（如省级一条、地市级一条、区县级一条），此处的“汇总/明细”描述的是用户可访问的维度深度，而非存储粒度



### 3.2 时间粒度豁免规则

| 时间类型      | 时间分类          | 时间格式                  | 豁免窗口      | 豁免判定                                                  | 窗口计算规则（当前时间：2026-05-20）      |
| :------------ | :---------------- | :------------------------ | :------------ | :-------------------------------------------------------- | :---------------------------------------- |
| `hourly`      | 单一时间          | `yyyy-MM-dd hh24:00:00`   | **最近 7 天** | 时间点在窗口内→完全豁免；否则→基础权限                    | 2026-05-14 00:00:00 ~ 2026-05-20 23:59:59 |
| `daily_count` | 单一时间          | `yyyy-MM-dd hh24:00:00`   | **最近 7 天** | 同上                                                      | 2026-05-14 00:00:00 ~ 2026-05-20 23:59:59 |
| `daily`       | 单一时间          | `yyyy-MM-dd`              | **最近 7 天** | 日期在窗口内→完全豁免；否则→基础权限                      | 2026-05-14 ~ 2026-05-20                   |
| `week`        | 单一时间→转时间段 | 转换为自然周起止日期      | **最近 7 天** | 转换后按 `other` 规则处理                                 | start = 当前日期 - 6天; end = 当前日期    |
| `month`       | 单一时间          | `yyyy-MM-01`              | **近两月**    | 月份在窗口内→完全豁免；否则→基础权限                      | 2026-04 ~ 2026-05                         |
| `month_count` | 单一时间          | `yyyy-MM-dd`              | **近两月**    | 日期在窗口内→完全豁免；否则→基础权限                      | 2026-04-01 ~ 2026-05-31                   |
| `year`        | 单一时间          | `yyyy-01-01`              | **近两年**    | 年份在窗口内→完全豁免；否则→基础权限                      | 2025 ~ 2026                               |
| `year_count`  | 单一时间          | `yyyy-MM-dd`              | **近两年**    | 日期在窗口内→完全豁免；否则→基础权限                      | 2025-01-01 ~ 2026-12-31                   |
| `other`       | 时间段            | `yyyy-MM-dd ~ yyyy-MM-dd` | **最近 7 天** | 完全在窗口内→完全豁免；部分交集→时间截断；无交集→基础权限 | 2026-05-14 ~ 2026-05-20                   |

**关键修正说明：**

1. **`week`类型特殊处理**：`week` 为单一时间（周标识），内部将其转换为该自然周的起止日期，作为 `other` 类型处理（时间段）。豁免判定遵循 `other` 的规则。
2. **累计型数据（`\*_count`）的窗口对齐**：
   - `daily_count`（小时级累计）与`hourly`共享 7 天窗口，因为两者都是小时级数据
   - `month_count`（日级月累计）与`month`共享近两月窗口，因为两者都服务于月度统计需求
   - `year_count`（日级年累计）与`year`共享近两年窗口，因为两者都服务于年度统计需求
3. **`other`类型明确为日级自定义范围**：唯一的时间段类型，支持日期范围查询。豁免窗口与 `daily` 一致（最近7天）。完全在窗口内时完全豁免；部分交集时触发时间截断；无交集时回退至基础权限。



#### 3.2.1 时间类型分类说明

根据查询时间表达方式，将九种时间类型分为**单一时间**和**时间段**两类，二者的豁免判定逻辑和修正策略有本质区别。

| 分类                     | 时间类型      | 时间格式                                                     | 说明                                              |
| ------------------------ | ------------- | ------------------------------------------------------------ | ------------------------------------------------- |
| **单一时间**             | `hourly`      | `yyyy-MM-dd hh24:00:00`                                      | 精确到小时的时间点                                |
|                          | `daily_count` | `yyyy-MM-dd hh24:00:00`                                      | 精确到小时的日累计时间点                          |
|                          | `daily`       | `yyyy-MM-dd`                                                 | 精确到天的日期                                    |
|                          | `month`       | `yyyy-MM-01`                                                 | 精确到月的月份标识                                |
|                          | `month_count` | `yyyy-MM-dd`                                                 | 精确到天的月累计日期                              |
|                          | `year`        | `yyyy-01-01`                                                 | 精确到年的年份标识                                |
|                          | `year_count`  | `yyyy-MM-dd`                                                 | 精确到天的年累计日期                              |
| **单一时间（转时间段）** | `week`        | 转换为自然周起止日期，格式同 `other`（`yyyy-MM-dd ~ yyyy-MM-dd`） | 按自然周起止日期转换为时间段，按 `other` 规则处理 |
| **时间段**               | `other`       | `yyyy-MM-dd ~ yyyy-MM-dd`                                    | 自定义日期范围                                    |

**关键区别**：

1. **单一时间**：查询的是一个具体时间点（某一小时、某一天、某一月、某一年）。豁免判定仅需判断该时间点是否落在豁免窗口内：
   - **在窗口内** → 完全豁免，可查任意行政区数据；
   - **不在窗口内** → 回退至基础行政区权限检查。
   - **不存在“部分交集”或“时间截断”**——单一时间点要么在窗口内，要么不在。

2. **时间段**（`other` 及转换后的 `week`）：查询的是一个日期范围。豁免判定需计算该范围与豁免窗口的交集：
   - **完全在窗口内** → 完全豁免；
   - **部分交集** → 触发时间截断，将范围缩短至交集部分；
   - **无交集** → 回退至基础行政区权限检查。

3. **`week` 的特殊处理**：`week` 虽然是单一时间（如“第21周”），但内部会将其转换为该自然周的起止日期（如 2026-05-18 ~ 2026-05-24），然后按 `other` 类型的规则处理。

   

### 3.3 宽免规则细节

- **完全豁免**：查询时间范围100%落在对应豁免窗口内，且粒度为可豁免类型，则**不受基础行政区权限限制**，可查任意行政区的对应数据（完全豁免同时覆盖站点、网格数据的跨行政区访问权限）。
- **部分豁免**：时间范围与豁免窗口有交集（但未完全覆盖），处理上**优先将时间截断至交集部分**，保留用户原行政区；仅在无法截断时（如月粒度查询的多个月份全部在窗口外）才进行行政区修正。
- **无豁免**：时间范围完全在豁免窗口外，严格按基础行政区权限执行。



### 3.4 站点与网格数据权限适配

当查询对象为**站点数据**或**网格数据**时，行政区权限规则做如下补充：

- **站点数据（如国控点、省控点）**：每个站点关联一个行政区（地市或区县）代码。站点数据的访问权限**继承该站点所属行政区的权限**。若用户有权访问该行政区，即可查看该站点数据；否则按行政区修正规则处理。
- **网格数据（如 1km×1km 网格）**：每个网格数据已标记所属区县，因此其访问权限**继承该网格所属区县的权限**（与站点数据规则相同）。若用户有权访问该区县，即可查看该网格数据；否则在豁免窗口外时按行政区修正规则处理。豁免窗口内不受行政区限制。
- 上述规则同样遵循时间粒度宽免机制：在豁免窗口内，站点/网格数据不受行政区限制，可跨区域查询。

**反馈模板**：
- 站点数据部分越权：“根据权限，仅展示您可访问的 {count} 个站点数据。如需查看其他区域站点，可查询最近7天数据。”
- 网格数据空间裁剪：“查询范围部分超出您的权限区域，已自动裁剪至可用范围，展示 {count} 个网格数据。”

**站点/网格数据关联层级与权限匹配**：

- **站点数据**：每个站点关联一个行政区代码，可能为地市级或区县级。关联地市的站点视为该地市的**汇总数据**，地市级及以上用户可访问；关联区县的站点视为该区县的**明细数据**，仅地市级和区县级用户可访问（地市可看本市所有区县，区县可看本市所有区县）。
- **网格数据**：每个网格已标记所属区县，视为区县级明细数据，权限规则与关联区县的站点相同。
- **用户关联城市**：可能是地市或区县，权限判定时：
  - 若用户关联地市，且站点/网格关联的区县属于该地市，则有权查看；
  - 若用户关联区县，且站点/网格关联的区县属于同一地市（或就是该区县），则有权查看；
  - 站点关联地市时，用户关联区县则无权访问该地市级站点（因区县用户只能看区县明细，不能看地市汇总）。

**缺失数据降级策略**：
- 若站点/网格数据缺少行政区代码或代码无效，无法确定归属，则视为数据不可用，向用户提示“该数据暂不可用”。
- 不再做向上归属省级的兜底处理。

## 4. 权限审查逻辑（伪代码）

权限审查是 AI 智能问数的安全控制核心。它接收由上游意图识别和槽位补全得到的标准化参数（用户信息、时间粒度、时间范围、目标行政区），根据最新的粒度豁免规则与基础行政区权限模型，输出是否允许查询及必要的修正策略。审查采用“**按粒度选择豁免窗口 → 交集判定 → 回退基础权限**”的串行流程，以确保在安全前提下最大化用户体验。

### 4.0 PermissionResult 数据结构定义

所有权限审查函数统一返回以下结构对象：

```python
@dataclass
class PermissionResult:
    permitted: bool = True            # 是否允许直接执行查询
    exemption: str = ""               # "full_window" | "normal" | ""
    exemption_window: tuple = None    # 触发豁免的时间窗口 (start, end)，用于日志
    fix_strategy: str = ""            # "truncate_time" | "replace_region" | ""
    legal_time_span: tuple = None     # 修正后的合法时间范围
    allowed_region: dict = None       # 仅在层级不允许时由 get_default_allowed_region 填充；其他越权场景为 None，由 Corrector Agent 计算
    reason: str = ""                  # 修正原因描述
    original_time_span: tuple = None  # 原始请求的时间范围
    rule_version: str = "V2.3"  # 当前规则版本号，每次规则调整后递增
```



### 4.1 权限审查主函数 `check_permission`

**函数说明**：
该函数是权限审查的统一入口。它首先根据请求的时间粒度（`time_granularity`）选择对应的豁免窗口：`hourly/daily_count/daily/week/other` 使用最近 7 天窗口，`month/month_count` 使用近两月窗口，`year/year_count` 使用近两年窗口。
然后根据时间类型分类处理：

- **单一时间**：判断时间点是否在豁免窗口内，在则返回完全豁免，不在则回退至基础权限检查。
- **时间段**（`other` 及 `week` 转换后）：计算时间范围与豁免窗口的交集。完全包含则完全豁免；无交集则基础权限；部分交集则触发时间截断策略，将范围缩短至豁免窗口内。

```python
def check_permission(user, slots):
    gran = slots["time_granularity"]  # 严格匹配8种类型
    time_range = slots["time_range"]  # 不同粒度的时间范围格式不同
    admin = slots["admin_region"]
    
    # 1. 按精确时间类型选择豁免窗口
    exemption_window = get_exemption_window_by_granularity(gran)
    
    # 2. 计算时间交集（根据粒度类型采用不同的交集算法）
    intersection = calculate_time_intersection(gran, time_range, exemption_window)
    
    if intersection is None:
        # 完全在窗口外 → 基础权限
        return check_base_region_permission(user, admin, time_intersection=None)

    # 单一时间类型：只要有交集即完全豁免（因为查询的就是一个时间点）
    if gran in ("hourly", "daily_count", "daily", "month", "month_count", "year", "year_count"):
        return PermissionResult(
            permitted=True,
            exemption="full_window",
            exemption_window=exemption_window,
            reason=f"{gran}类型数据在{exemption_window}内无行政区限制"
        )

    # 时间段类型（other, week）：进一步判断是否完全包含
    if is_fully_contained(gran, time_range, exemption_window):
        return PermissionResult(
            permitted=True,
            exemption="full_window",
            exemption_window=exemption_window,
            reason=f"{gran}类型数据在{exemption_window}内无行政区限制"
        )
    else:
        # 部分交集 → 时间截断，行政区保留原样
        return PermissionResult(
            permitted=False,
            fix_strategy="truncate_time",
            legal_time_span=intersection,
            reason=f"查询时间超出{gran}类型的豁免窗口，已自动缩短至可用范围",
            original_time_span=time_range
        )
```

> **注**：入参 `time_granularity` 不含 `week`（`week` 已在 SlotFilling 阶段转为 `other`），实际参与判定的为 8 种类型：`hourly`、`daily_count`、`daily`、`month`、`month_count`、`year`、`year_count`、`other`。



### 4.2 按粒度生成豁免窗口函数 `get_exemption_window_by_granularity`

**函数说明**：
本函数是豁免窗口生成的唯一入口，内部根据粒度调用对应的计算逻辑。

**基准时间与边界适配规则**：
- 所有窗口计算统一以 `datetime.now()` 为基准，时区固定为 **UTC+8（Asia/Shanghai）**。
- 月末窗口自动适配：如 `month` 窗口为近两月，当月为 2026-03 时，上月为 2026-02，窗口结束日自动适配为 2026-02-28（非闰年）或 2026-02-29（闰年）。
- 年末窗口同理：`year` 窗口结束日固定为当年 12-31，不受闰年影响。

```python
def get_exemption_window_by_granularity(gran):
    """根据精确时间类型生成对应的豁免窗口"""
    now = datetime.now()
    
    if gran in ("hourly", "daily_count"):
        # 小时级数据：最近7天（精确到小时）
        start = now - timedelta(days=6)
        start = start.replace(hour=0, minute=0, second=0, microsecond=0)
        end = now.replace(hour=23, minute=59, second=59, microsecond=999999)
        return (start, end)
    
    elif gran in ("daily", "other"):
        # 日级数据：最近7天（精确到天）
        start = now.date() - timedelta(days=6)
        end = now.date()
        return (start, end)
    
    elif gran == "week":
        # 周级数据：使用与 daily 相同的7天窗口，后续按日粒度计算交集
        start = now.date() - timedelta(days=6)
        end = now.date()
        return (start, end)
    
    elif gran in ("month", "month_count"):
        # 月级/月累计数据：近两月（上月1日至本月最后一天）
        first_of_this_month = now.replace(day=1, hour=0, minute=0, second=0, microsecond=0)
        first_of_last_month = first_of_this_month - relativedelta(months=1)
        last_of_this_month = first_of_this_month + relativedelta(months=1) - timedelta(seconds=1)
        return (first_of_last_month, last_of_this_month)
    
    elif gran in ("year", "year_count"):
        # 年级/年累计数据：近两年（前年1月1日至本年最后一天）
        first_of_this_year = now.replace(month=1, day=1, hour=0, minute=0, second=0, microsecond=0)
        first_of_last_year = first_of_this_year - relativedelta(years=1)
        last_of_this_year = first_of_this_year + relativedelta(years=1) - timedelta(seconds=1)
        return (first_of_last_year, last_of_this_year)
    
    else:
        # 未知粒度，记录错误并触发告警
        # log.error(f"未知时间粒度: {gran}，用户ID: {user.get('user_id', 'unknown')}")
        # alarm_service.trigger_if_needed("unknown_granularity", gran, user.get("user_id"))
        start = now.date() - timedelta(days=6)
        end = now.date()
        return (start, end)
```



### 4.3 基础行政区权限检查 `check_base_region_permission`

**函数说明**：
当时间豁免不适用（如粒度未知）或查询时间完全在豁免窗口之外时，调用本函数执行严格的行政区权限校验。
校验分为两层：

1. 调用 `is_region_level_allowed` 检查用户是否有权访问请求的行政区**层级**（例如省级用户不可查询区县级明细）。
2. 调用 `get_allowed_regions` 获取该层级下用户允许访问的具体行政区代码列表，并核对请求的目标行政区是否在其中。
    任一条件不满足，则返回修正策略 `replace_region`；层级越权时由 `get_default_allowed_region` 生成安全兜底区域，具体行政区越权时 `allowed_region` 设为 `None`。返回后，由 Corrector Agent（6.2(4)节）依据 5.3.1 修正策略矩阵执行行政区替换，其内部优先级为：常访问区域 > 用户关联区域 > 默认区县。

```python
def check_base_region_permission(user, admin, time_intersection=None):
    # 第一道：层级合法性
    if not is_region_level_allowed(user["region_level"], admin["level"]):
        # 层级不允许，但具体修正策略交由 Corrector Agent 根据原始请求区域决定
        return PermissionResult(
            permitted=False,
            fix_strategy="replace_region",
            allowed_region=None,   # 不预设替代区域，由 Corrector 按5.3.1策略修正
            reason=f"您无权查看{admin['level']}级数据",
            legal_time_span=time_intersection
        )

    # 第二道：具体行政区合法性
    allowed_regions = get_allowed_regions(user, admin["level"], admin.get("data_type"))
    if admin["code"] in allowed_regions["codes"]:
        return PermissionResult(permitted=True, exemption="normal")
    else:
        # 行政区越权，但不生成替代区域，完全交给 Corrector Agent
        return PermissionResult(
            permitted=False,
            fix_strategy="replace_region",
            allowed_region=None,   # Corrector 会自行计算
            reason="行政区越权",
            legal_time_span=time_intersection
        )
```



### 4.4 关键辅助函数

#### 4.4.1 行政区层级白名单校验 `is_region_level_allowed`

**函数说明：**
定义不同用户层级能够访问的行政区层级白名单，是防止越级查询的第一道屏障。

- 省级用户仅可访问 `province` 和 `city` 两级（不可查区县明细）。
- 地市级用户可访问 `province`、`city` 和 `district` 三级（新增省级汇总查看权限）。
- 区县级用户仅可访问 `city` 和 `district` 两级（不可查省级汇总）。

> 术语对应：`province` 层级对应省级汇总数据，`city` 层级对应地市级汇总数据，`district` 层级对应区县级明细数据。

```python
def is_region_level_allowed(user_level, requested_level):
    allowed_levels = {
        "province": ["province", "city"],
        "city": ["province", "city", "district"],
        "district": ["city", "district"]
    }
    return requested_level in allowed_levels[user_level]
```



#### 4.4.2 获取允许访问的行政区列表 `get_allowed_regions`

**函数说明：**
根据用户身份（层级、关联城市代码）、目标行政区层级及数据类型，动态生成当前可访问的行政区代码集合。

- 省级用户查省级 → 全国所有省代码，汇总数据；
- 省级用户查地市 → 本省下辖所有地市代码，汇总数据；
- 地市用户查省级 → 本省代码，汇总数据；
- 地市用户查地市 → 本省下辖所有地市代码，汇总数据；
- 地市用户查区县 → 本市下辖所有区县代码，明细数据；
- 区县用户查市 → 本市代码，汇总数据；
- 区县用户查区县 → 本市下辖所有区县代码，明细数据。

此函数是基础权限判断的核心依据。

```python
def get_allowed_regions(user, target_level, data_type):
    user_level = user["region_level"]
    user_code = user["region_code"]
    allowed = {"codes": [], "level": target_level, "data_type": data_type}

    if user_level == "province":
        if target_level == "province":
            allowed["codes"] = get_all_province_codes()
            allowed["data_type"] = "summary"
        elif target_level == "city":
            allowed["codes"] = get_province_city_codes(user_code)
            allowed["data_type"] = "summary"

    elif user_level == "city":
        province_code = get_province_code_by_city(user_code)
        if target_level == "province":
            allowed["codes"] = [province_code]
            allowed["data_type"] = "summary"
        elif target_level == "city":
            allowed["codes"] = get_province_city_codes(province_code)
            allowed["data_type"] = "summary"
        elif target_level == "district":
            allowed["codes"] = get_city_district_codes(user_code)
            allowed["data_type"] = "detail"

    elif user_level == "district":
        city_code = get_city_code_by_district(user_code)
        if target_level == "city":
            allowed["codes"] = [city_code]
            allowed["data_type"] = "summary"
        elif target_level == "district":
            allowed["codes"] = get_city_district_codes(city_code)
            allowed["data_type"] = "detail"

    # 兜底：若允许列表为空，返回用户关联区域代码
    if not allowed["codes"]:
        allowed["codes"] = [user_code]
        log.warning(f"允许列表为空，回退至用户关联区域: user={user_code}")
        
    return allowed
```



#### 4.4.3 时间交集判定与替代行政区选择

- `calculate_time_intersection(gran, query_range, window_range)`：计算时间交集，若不相交则返回 `None`。
- `is_fully_contained(range, window)`：判断 `range` 是否完全被 `window` 包含。
- `get_default_allowed_region(user, admin)`：当用户无权访问请求的行政区层级时，返回一个安全默认的行政区（通常为用户关联城市或上卷一级）。
- 替代行政区选择：原 `select_best_replacement` 已废弃，替代逻辑统一由 Corrector Agent 的 `get_replacement_region` 实现（见 6.2(4) 节 Corrector Agent）。

这些工具函数共同支撑权限审查的完整决策逻辑。



### 4.5 工具函数

#### 4.5.1 时间交集判定函数 `calculate_time_intersection`

**函数说明：**
计算两个时间范围 `range` 和 `window` 的重叠部分。每个范围均由 `(start_datetime, end_datetime)` 表示，若两者不相交则返回 `None`，否则返回交集元组。

```python
def calculate_time_intersection(gran, query_range, window_range):
    # 对于单一时间点，query_range 应为单个 datetime/date，若意外传入元组则防御失败
    # 防御：时间格式校验（仅对时间段类型强校验）
    if query_range is None:
        return None
    if gran in ("other", "week") or (gran in ("hourly", "daily_count", "month_count", "year_count") and isinstance(query_range, tuple)):
        # 时间段或误传为元组的情况，校验长度
        if len(query_range) != 2 or query_range[0] > query_range[1]:
            log.warning(f"非法时间范围: {query_range}")
            return None
    
    """根据不同时间类型采用不同的交集计算逻辑"""
    if gran in ("hourly", "daily_count", "month_count", "year_count"):
        # 单一时间点：精确时间点判定
        if window_range[0] <= query_range <= window_range[1]:
            return (query_range, query_range)  # 单一时间点，start=end
        else:
            return None
    
    elif gran == "daily":
        # 单一时间点：query_range 是单个日期，判断是否在窗口内
        if window_range[0] <= query_range <= window_range[1]:
            return (query_range, query_range)  # 单一时间点，start=end
        else:
            return None
    
    elif gran == "week":
        # 转换为日期范围后按 other 处理
        week_days = get_days_in_week_range(query_range)
        week_start, week_end = week_days[0], week_days[-1]
        start = max(week_start, window_range[0])
        end = min(week_end, window_range[1])
        if start <= end:
            return (start, end)
        else:
            return None
    
    elif gran == "month":
        # 单一时间点：query_range 是单个月份元组 (year, month)，判断是否在窗口月份列表中
        window_months = set(get_months_in_range(window_range))
        if query_range in window_months:
            return (query_range, query_range)  # 单一时间点，start=end
        else:
            return None
    
    elif gran == "year":
        # 单一时间点：query_range 是单个年份，判断是否在窗口年份范围内
        window_years = set(get_years_in_range(window_range))
        if query_range in window_years:
            return (query_range, query_range)  # 单一时间点，start=end
        else:
            return None
    
    elif gran == "other":
        # 时间段：按天计算交集，返回连续日期范围的起止
        query_start, query_end = query_range
        window_start, window_end = window_range
        start = max(query_start, window_start)
        end = min(query_end, window_end)
        if start <= end:
            return (start, end)
        else:
            return None
```



#### 4.5.2 完全包含判定函数 `is_fully_contained`

**函数说明：**
此函数只处理时间段时间。

```python
def is_fully_contained(gran, query_range, window_range):

#### 4.5.3 默认允许行政区获取 `get_default_allowed_region`

**函数说明：**

当用户请求的行政区**层级**不被允许时（例如省级用户查询区县），此函数返回一个安全的默认行政区，供修正模块直接替换。
策略为：

- 省级用户 → 返回其关联省份（层级 `province`，本省汇总）
- 地市级用户 → 返回其关联城市（层级 `city`，本市汇总）
- 区县级用户 → 返回其关联区县（层级 `district`，本区县明细）

```python
def get_default_allowed_region(user, requested_admin):
    """
    user: 用户信息，含 region_level, region_code, region_name
    requested_admin: 原始请求的行政区对象，至少含 level
    返回默认行政区对象，包含 code, name, level, data_type
    """
    user_level = user["region_level"]
    if user_level == "province":
        return {
            "code": user["region_code"],
            "name": user.get("region_name", "未知省份"),
            "level": "province",
            "data_type": "summary"
        }
    elif user_level == "city":
        return {
            "code": user["region_code"],
            "name": user.get("region_name", "未知城市"),
            "level": "city",
            "data_type": "summary"
        }
    elif user_level == "district":
        return {
            "code": user["region_code"],
            "name": user.get("region_name", "未知区县"),
            "level": "district",
            "data_type": "detail"
        }
```

#### 4.5.5 获取周的时间段函数 `get_days_in_week_range`

**函数说明**：返回指定周开始及结束时间。

```python
def get_days_in_week_range(week_range):
    """将周范围展开为日期列表，如 (2026-W21) → [2026-05-18, ..., 2026-05-24]"""
    start_date, end_date = week_range  # week_range 实际存储为 (week_start_date, week_end_date)

#### 4.5.6 行政区名称查询 `get_region_name_by_code`

**函数说明**：通过行政区代码获取行政区名称。优先从本地缓存查询，缓存未命中时返回代码本身作为兜底。

```python
def get_region_name_by_code(code: str) -> str:
    """通过行政区代码获取名称，兜底返回代码"""
    # 优先从缓存查询
    name = region_cache.get(code)
    if name:
        return name
    # 缓存未命中时尝试从数据库加载
    try:
        name = region_service.query_name_by_code(code)
        region_cache[code] = name
        return name
    except Exception:
        log.warning(f"无法获取行政区名称: code={code}")
        return code  # 兜底返回代码本身
```

> `region_cache` 为全局 LRU 缓存，`region_service` 为行政区划数据服务（见 8.1 节依赖数据源）。



#### 4.5.7 通用时间工具函数 `get_days_in_range`、`get_months_in_range`、`get_years_in_range`、`date_range`

**函数说明**：以下函数用于将时间范围展开为离散的日期、月份或年份列表，均由标准库 `datetime` 实现。

```python
def get_days_in_range(range_tuple):
    """返回 start_date 到 end_date 之间的所有日期列表（含两端）"""
    start, end = range_tuple
    return [start + timedelta(days=i) for i in range((end - start).days + 1)]

def get_months_in_range(range_tuple):
    """返回窗口内的所有年月元组，如 [(2026,4),(2026,5)]"""
    from dateutil.relativedelta import relativedelta
    months = []
    current = range_tuple[0].replace(day=1)
    while current <= range_tuple[1]:
        months.append((current.year, current.month))
        current += relativedelta(months=1)
    return months

def get_years_in_range(range_tuple):
    """返回窗口内的年份列表，如 [2025,2026]"""
    return list(range(range_tuple[0].year, range_tuple[1].year + 1))

def date_range(start, end):
    """等同于 get_days_in_range，返回 start 到 end 的所有日期列表（含两端）"""
    return [start + timedelta(days=i) for i in range((end - start).days + 1)]
```

### 4.6 总结

本章通过**分层审查 + 动态窗口**的机制，将时间粒度豁免与行政区权限有机统一。

- 对于单一时间类型（`hourly`/`daily_count`/`daily`/`month`/`month_count`/`year`/`year_count`），豁免窗口提供了时间点级别的跨行政区宽免。
- 对于时间段类型（`other` 及 `week` 转换后），豁免窗口支持日期范围的交集判定和时间截断。
- 对于 `month/month_count` 数据，**近两月**的窗口让上月、本月等常见查询直接豁免行政区限制。
- 对于 `year/year_count` 数据，**近两年**的窗口覆盖了去年、今年的查询需求。
- 当豁免窗口不满足时，严格回退至基础的**行政区层级→具体代码**两层校验，并智能生成替代行政区或时间截断策略，确保数据安全无越权。

整个权限审查模块的设计具有清晰的输入输出边界，各辅助函数职责单一，易于单元测试与规则调整，为多 Agent 架构中的 Permission Agent 提供了坚实可靠的核心技能。

## 5. 问题修正策略

### 5.1 修正优先级

1. **时间截断**（仅适用于时间段类型：`other` 及 `week` 转换后的查询，当部分交集时触发）
2. **行政区修正**（单一时间不在豁免窗口内时，或时间段查询完全无交集时）



### 5.2 时间截断策略

将查询时间窗口替换为与豁免窗口的交集，行政区不变。
对于月粒度，截断后可能只保留近两月内的月份；对于年粒度，只保留近两年内的年份。

#### 5.2.1 分时间类型的时间截断策略

| 时间类型                    | 部分交集时的截断规则         | 示例（当前时间：2026-05-20）                                 |
| :-------------------------- | :--------------------------- | :----------------------------------------------------------- |
| `other`（含 `week` 转换后） | 保留与豁免窗口交集的所有日期 | 查询 "2026-05-10 ~ 2026-05-20" → 截断为 "2026-05-14 ~ 2026-05-20"；查询 "2026年第20-21周" → 仅保留窗口内日期 |

> **说明**：单一时间类型（`hourly`/`daily_count`/`daily`/`month`/`month_count`/`year`/`year_count`）不存在部分交集，因此不涉及时间截断。月/年粒度仅支持单一时间点查询，不存在时间段截断；若用户以 `other` 类型跨月/跨年查询，则按 `other` 行规则截断。`week` 内部转换为 `other` 后按本表规则处理。



#### 5.2.2 分时间类型的修正说明模板

| 时间类型                    | 修正说明模板                                                 |
| :-------------------------- | :----------------------------------------------------------- |
| `other`（含 `week` 转换后） | "因查询日期范围部分超出豁免窗口，已为您截断至 {交集日期范围} 的 {原行政区}{指标} 数据：{value}。" |

**模板层级适配**：

- 省级用户：仅说明修正原因和结果，省略权限细节。例：“已为您展示XX省汇总数据：{value}。”
- 地市用户：简要说明权限限制。例：“您无法查看其他地市区县数据，已替换为XX市数据：{value}。”
- 区县用户：详细说明权限边界，提供替代方案引导。例：“区县用户暂不支持查看省级数据。已为您展示本区县数据：{value}。可尝试查询近7天数据获取省级汇总。”



### 5.2.3 截断效果评估与备选提示

本机制仅适用于时间段类型（`other` 及 `week` 转换后）。单一时间类型不涉及截断。

当时间截断导致剩余数据量显著减少时，系统应主动提供备选方案，以平衡权限安全与用户体验。

**评估指标**：截断后的数据天数（或记录数）与原请求的比值，记为 `ratio`。  
**阈值**：配置项 `correction.time_truncation_min_ratio`（默认 0.5）。  
**触发条件**：`ratio < time_truncation_min_ratio`。

**处理逻辑**（在 Corrector Agent 截断后执行）：

1. 计算 `ratio`。
2. 若 `ratio` 低于阈值，`change_log` 中追加备选提示，文案模板为：“当前仅能展示 {legal_days} 天数据，是否查看您有权限的 {替代区域} 近 {original_days} 天数据？”由前端渲染为可点击按钮；用户选择“否”则仅展示当前截断结果，不执行替换查询。
3. 备选提示写入 `change_log`，由 Response Agent 以建议形式追加到回复末尾，不改变当前截断结果。

**示例**：用户请求“近30天杭州市PM2.5”，截断后仅剩最近7天，`ratio ≈ 0.23 < 0.5`，触发备选提示：“如需更多历史数据，可为您展示宁波市（您的关联城市）的近30天数据。”

**实现伪代码**：

```python
original_days = (original_time_range[1] - original_time_range[0]).days
legal_days = (legal_time_span[1] - legal_time_span[0]).days
if original_days > 0 and (legal_days / original_days) < config.correction.time_truncation_min_ratio:
    alt_region = get_default_allowed_region(user, slots["admin_region"])  # 使用用户默认安全区域
    change_log.append(f"备选：可查看 {alt_region['name']} 的同期完整数据")
```

## 6. 多 Agent 架构实现

### 6.1 总体工作流

```markdown
用户输入 → Supervisor Agent
                ├── Intent Agent (意图识别与实体提取)
                ├── SlotFilling Agent (槽位补全 + 时间粒度推断)
                ├── Permission Agent (权限审查，含粒度判定)
                ├── Corrector Agent (根据审查结果修正查询参数)
                ├── Data Query Skill (执行数据查询)
                └── Response Agent (生成回答，含修正说明)
```

**统一职责**：

- 权限审查`Permission Agent`只回答 **“是否越权”**，不回答 **“换成什么”**。
- 具体替换成什么区域，全部由`Corrector Agent` 根据修正策略矩阵（第5.3.1节）决定。



### 6.2 Agent 详细设计

#### (1) Intent Agent

- **职责**：解析用户自然语言，输出标准化意图和实体槽位。

- **技能工具**：`intent_extraction(text) → IntentSlots`

- **输出槽位示例**：

  ```json
  {
    "metrics": ["pm2.5"],
    "time_range": {"type": "relative", "value": "last_30_days"},
    "admin_region": {"name": "杭州市", "code": "330100", "level": "city"},
    "filters": {}
  }
  ```

  **Slots 完整字段定义**：
  
  | 字段               | 类型         | 必填 | 说明                                                         |
  | ------------------ | ------------ | ---- | ------------------------------------------------------------ |
  | `metrics`          | `List[str]`  | 是   | 指标列表，如 `["pm2.5", "o3"]`                               |
  | `time_granularity` | `str`        | 是   | 时间粒度，枚举值见 3.2 节                                    |
  | `time_range`       | `随类型变化` | 是   | 单一时间类型：`hourly`/`daily_count` 为单个 `datetime`；`daily` 为单个 `date`；`month` 为单个 `(year, month)` 元组；`month_count`/`year_count` 为单个 `date`；`year` 为单个年份整数。时间段类型：`other` 及 `week` 转换后，为 `(start_date, end_date)` 元组。具体由上游 SlotFilling 生成 |
  | `admin_region`     | `dict`       | 是   | 行政区对象 `{code, name, level, data_type}`。`level` 取值：`province/city/district`；`data_type` 取值：`summary/detail` |
  | `filters`          | `dict`       | 否   | 其他维度筛选条件，如 `{"station_type": "国控"}`              |

#### (2) SlotFilling Agent

- **职责**：补全缺失槽位，并推断时间粒度。

- **技能工具**：
  - `get_user_profile(user_id)` → 返回关联城市、常访问区域。
  - `resolve_region_alias(name)` → 行政区标准化。
  - **`infer_time_granularity(intent, metrics, time_expression)`** → 推断`time_granularity`。

- **粒度推断规则**：

  | 用户查询表述                                                 | 推断的时间粒度 | 时间范围示例                        |
  | ------------------------------------------------------------ | -------------- | ----------------------------------- |
  | "今天 14 时"、"昨天 20 时"、"每小时"                         | `hourly`       | 2026-05-20 14:00 ~ 2026-05-20 14:59 |
  | "今日"、"今天"、"今日累计"、"昨天累计"、"日累计"             | `daily_count`  | 2026-05-20 00:00 ~ 2026-05-20 14:30 |
  | "昨日"、"昨天"、"5 月 20 日"                                 | `daily`        | 2026-05-20 ~ 2026-05-20             |
  | "本周"、"上周"、"5 月第一周"                                 | `week`         | 2026 年第 21 周（5.18-5.24）        |
  | "上月"、"3 月"、"按月统计"                                   | `month`        | 2026-05 ~ 2026-05                   |
  | "本月"、"本月累计"、"上月累计"、"月累计"                     | `month_count`  | 2026-05-01 ~ 2026-05-20             |
  | "去年"、"2025 年"、"按年统计"                                | `year`         | 2026 ~ 2026                         |
  | "今年"、"今年累计"、"去年累计"、"年累计"                     | `year_count`   | 2026-01-01 ~ 2026-05-20             |
  | "5 月 2 日至 5 月 5 日"、"近 7 天"、"近 30 天"、"2026 年第一季度" | `other`        | 2026-05-02 ~ 2026-05-05             |

  **关键补充规则：**

  1. 当用户同时提到 "累计" 和时间粒度时，优先推断为`*_count`类型：
     - "本月累计" → `month_count`（而非`month`）
     - "今年累计" → `year_count`（而非`year`）
     - "当日累计" → `daily_count`（而非`daily`）
  2. 当用户查询 "近 X 天" ，推断为 `other`（时间段）；开始时间：今日 - X，结束时间：今日 - 1；
        注意：即使 X≤7，也推断为 `other` 而非 `daily`，因为 `daily` 是单一时间点，无法表达日期范围。
  3. 当用户查询 "近 X 个月" ，推断为`month`；开始时间：今日所在月- X，结束时间：今日所在月 - 1；
  4. 当用户查询 "近 X 年" ，推断为`year`；开始时间：今日所在年- X，结束时间：今日所在年 - 1；
  5. 今日：由于当日还没有产生日均数据，实际使用日累计数据；
  6. 本月：由于当月还没有产生月统计数据，实际使用月累计数据；
  7. 今年，由于今年还没有产生年统计数据，实际使用年累计数据。

- **默认补全**：

  - 时间缺失 → 默认`daily`，范围最近7天。
  - 行政区缺失 → 使用用户关联城市（地市级为用户关联地市，区县级为关联区县，省级为关联省份）。
  - **日级数据可用性约束**：对于 `daily` 类型，若用户未指定具体结束时间，则默认结束时间为 `today - 1`（因为日数据产生存在延迟）。若用户明确要求“今日”，则推断为 `daily_count`（规则已在上表列出）。



#### (3) Permission Agent

- **职责**：基于用户、时间粒度、时间范围、行政区进行权限判定。
- **技能工具**：
  - `region_level_validation(user_level, requested_level)` → 第一道防线。
  - `permission_check_v3(user, slots)` → 主逻辑，实现第4节伪代码。
- **输出**：`PermissionResult` 包含是否允许、豁免类型、越权原因、合法时间窗口、允许的行政区列表及修正策略。



#### (4) Corrector Agent

- **职责**：根据`PermissionResult`的`fix_strategy`执行修正。

- **技能工具**：

  - `truncate_time(slots, legal_time_span) → new_slots`
  - `correct_region(region, user, time_permission) → corrected_region, correction_log`
  - `evaluate_truncation_impact(original_time_span, legal_time_span, user, slots) → None`：计算截断后数据占比，若低于阈值则生成备选提示写入 `change_log`。具体逻辑见 5.2.3 节。

- **辅助函数 `get_replacement_region` 逻辑**：

  ```python
  def get_replacement_region(user, requested_region):
      """
      根据用户层级和越权的请求区域，按照5.3.1修正策略矩阵返回替代行政区。
      返回替代区域 dict 以及修正原因字符串。
      """
      user_level = user["region_level"]
      region = requested_region
  
      # 省级用户
      if user_level == "province":
          if region["level"] == "district":
              city = get_city_by_district(region["code"])
              if city["province_code"] == user["region_code"]:
                  return city, f"将本省区县{region['name']}上卷至所属地市{city['name']}"
              else:
                  province = get_province_by_code(region["province_code"])
                  return province, f"将外省区县{region['name']}直接上卷至所属省份{province['name']}"
          elif region["level"] == "city" and region["province_code"] != user["region_code"]:
              province = get_province_by_code(region["province_code"])
              return province, f"将外省地市{region['name']}上卷至所属省份{province['name']}"
          else:
              return region, None
  
      # 地市级用户
      elif user_level == "city":
          if region["level"] == "district" and region["city_code"] != user["region_code"]:
              freq = get_user_frequent_district(user["user_id"])
              if freq is None:
                  freq = get_default_district_for_city(user["region_code"])
              return freq, f"将其他市区县{region['name']}替换为本市常访问区县{freq['name']}"
          elif region["province_code"] != get_province_code_by_city(user["region_code"]):
              city = get_city_by_code(user["region_code"])
              return city, f"将外省区域{region['name']}替换为用户所在城市{city['name']}"
          else:
              return region, None
  
      # 区县级用户
      elif user_level == "district":
          if region["level"] == "province":
              district = get_district_by_code(user["region_code"])
              return district, f"将省级汇总{region['name']}替换为用户所在区县{district['name']}"
          elif region["city_code"] != get_city_code_by_district(user["region_code"]):
              district = get_district_by_code(user["region_code"])
              return district, f"将外市区域{region['name']}替换为用户所在区县{district['name']}"
          else:
              return region, None
  
      return region, None
  ```
  
-  **修正函数 `correct_region` 逻辑**（关键修正点）：

  ```python
  def correct_region(region, user, time_permission):
      if time_permission == "full":  # 完全豁免
          return region, None
      # 使用统一的修正策略函数
      return get_replacement_region(user, region)
  ```
  
  
  

#### (5) Data Query Skill

- **类型**：工具函数，非独立Agent。
- **输入**：修正后的`slots`。
- **输出**：查询结果集。



#### (6) Response Agent

- **职责**：整合数据与修正日志，生成自然语言回答。

- **技能工具**：`generate_response(original_query, corrected_slots, data, change_log)`

- **提示文案数据结构**：

    ```python
      @dataclass
      class CorrectionPrompt:
          template_id: str           # 模板唯一标识
          content: str               # 文案模板（含占位符）
          params: dict               # 需替换的参数，如 {"原行政区":"杭州","替代区域":"宁波"}

- **要求**：严格使用修正说明模板，前端展示修正提示。

  

#### 6.2.1 Corrector Agent 接口约定

| 项目         | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| **输入**     | `PermissionResult`（含 `fix_strategy`、`legal_time_span`）、`user_profile`（含 `region_level`、`region_code`、`frequent_regions`）、原始 `slots` |
| **输出**     | 修正后的 `slots`（含修正后的 `admin_region` 和 `time_range`）及 `change_log` 列表 |
| **超时**     | 500ms                                                        |
| **失败兜底** | 调用 `get_default_allowed_region` 返回用户关联行政区，`change_log` 写入“系统自动匹配至您有权限的区域” |



#### 6.2.2 接口调用规范

| 调用链路                           | 方式                 | 超时   | 重试策略     |
| ---------------------------------- | -------------------- | ------ | ------------ |
| Intent → SlotFilling               | 同步函数调用         | -      | -            |
| SlotFilling → Permission Agent     | 同步函数调用         | -      | -            |
| Permission Agent → Corrector Agent | 同步函数调用（内部） | 500ms  | 失败直接兜底 |
| Corrector Agent → Data Query       | 异步任务             | 5000ms | 1次重试      |
| 整体工作流                         | LangGraph 同步编排   | 10s    | 异常兜底回答 |



### 6.3 框架实现建议

**Agent 共享状态定义** (`AgentState`)：

```python
from typing import TypedDict, List, Optional

class AgentState(TypedDict):
    user_id: str                       # 用户唯一标识
    user_profile: dict                 # 用户画像（region_level, region_code, region_name, frequent_regions）
    original_query: str                # 原始自然语言问题
    intent: dict                       # Intent Agent 输出的意图
    slots: dict                        # SlotFilling Agent 补全后的槽位对象
    permission_result: Optional[dict]  # PermissionResult 序列化后对象
    corrected_slots: Optional[dict]    # Corrector Agent 修正后的槽位
    change_log: Optional[List[str]]    # 修正日志列表
    query_result: Optional[dict]       # Data Query 返回的结果
    final_response: Optional[str]      # Response Agent 生成的最终回答
```

- 使用 `LangGraph` 的 `StateGraph` 编排工作流，各 Agent 作为节点，通过 `State` 传递上下文。
- 各 `skill` 定义为无状态函数工具，挂载到对应 Agent 上。
- 监控与日志：记录每次越权修正事件及 State 关键字段，便于事后审计。

## 7. 验证用例（当前时间2026年05月20日）

### 用例 1：省级用户查询本省区县年度数据（时间在豁免窗口外）
- **用户**：广东省省级用户
- **查询**：“2024年广州市天河区PM2.5平均浓度？”
- **粒度**：`year`（年份 2024）
- **审查**：2024 年不在近两年豁免窗口（2025-2026）内，无豁免；省级用户无权查看区县明细，触发行政区修正。
- **修正**：天河区 → 广州市（汇总）
- **反馈**：“因数据权限限制，省级用户无法查看区县明细数据，已为您展示天河区所属广州市的汇总数据：2024年广州市PM2.5平均浓度为32μg/m³。如需查看区县明细，可查询近两年内的数据。”

### 用例 2：省级用户查询外省区县时间段数据（时间全在 7 天内）
- **用户**：广东省省级用户
- **查询**：“近7天南京市玄武区PM2.5平均浓度？”
- **粒度**：`other`（时间段，日期范围完全在最近 7 天内）
- **审查**：时间完全在 7 天豁免窗口内 → 完全豁免。
- **修正**：无
- **反馈**：“近7天南京市玄武区PM2.5平均浓度为28μg/m³。”

### 用例 3：地市用户查询本省其他市区县年度数据（时间在豁免窗口外）
- **用户**：宁波市地市级用户
- **查询**：“2024年杭州市西湖区PM2.5平均浓度？”
- **粒度**：`year`（年份 2024）
- **审查**：2024 年不在近两年豁免窗口（2025-2026）内，无豁免；地市用户无权查看其他市区县明细，触发行政区修正。
- **修正**：替换为宁波市鄞州区（常访问区县）
- **反馈**：“因数据权限限制，地市用户无法查看其他市区县数据，已为您展示您所在宁波市的鄞州区数据：2024年宁波市鄞州区PM2.5平均浓度为30μg/m³。如需查看其他市区县明细，可查询近两年内的数据。”

### 用例 4：地市用户查询上月全国数据（月粒度完全豁免）

- **用户**：宁波市地市级用户
- **查询**：“上月全国PM2.5月均值是多少？”
- **粒度**：`month`（月份 2026-04）
- **审查**：时间在近两月豁免窗口内 → 完全豁免，可查询任意行政区数据（包括全国）。
- **修正**：无
- **反馈**：“上月全国PM2.5月均值为 XX μg/m³。”

### 用例 5：区县用户查询省级时间段数据（时间部分在 7 天内）
- **用户**：杭州市西湖区区县用户
- **查询**：“近30天浙江省PM2.5日均值？”
- **粒度**：`other`（时间段，日期范围与 7 天窗口部分交集）
- **审查**：时间段部分交集（最近7天+前23天），区县用户查省级虽超出基础权限，但部分交集触发时间截断策略。
- **修正**：时间截断至最近 7 天，行政区保留“浙江省”
- **反馈**：“因查询日期范围部分超出豁免窗口，已为您截断至最近7天的浙江省PM2.5日均值数据：……”

### 用例 6：地市用户查询月粒度数据（时间在近两月内豁免）
- **用户**：宁波市地市级用户
- **查询**：“上月杭州市PM2.5月均值？”（当前时间 2026-05，上月 = 4 月）
- **粒度**：`month`（月份 2026-04）
- **审查**：时间完全在近两月豁免窗口（2026-04 ~ 2026-05）内 → 完全豁免，即使地市用户通常不能查看其他地市数据，也可直接查询。
- **修正**：无
- **反馈**：“上月杭州市PM2.5月均值为 28 μg/m³。”

### 用例 7：地市用户查询月粒度数据（时间超出近两月）
- **用户**：宁波市地市级用户
- **查询**：“2026年3月杭州市PM2.5月均值？”
- **粒度**：`month`（月份 2026-03）
- **审查**：2026-03 不在近两月窗口（2026-04 ~ 2026-05）内，无豁免；地市用户无权查看其他地市数据 → 行政区修正。
- **修正**：替换为宁波市
- **反馈**：“因查询月份超出近两月豁免范围，且您无权查看其他地市数据，已为您展示宁波市2026年3月PM2.5月均值：29 μg/m³。”

### 用例 8：区县用户查询年粒度数据（时间在近两年内豁免）
- **用户**：杭州市西湖区区县用户
- **查询**：“去年全国PM2.5年均值？”（当前时间 2026-05，去年 = 2025 年）
- **粒度**：`year`（年份 2025）
- **审查**：2025 年在近两年豁免窗口（2025-2026）内 → 完全豁免，即使区县用户通常不能查看全国数据，也可直接查询。
- **修正**：无
- **反馈**：“去年全国PM2.5年均值为 35 μg/m³。”

### 用例 9：区县用户查询年粒度数据（时间超出近两年）
- **用户**：杭州市西湖区区县用户
- **查询**：“2024年全国PM2.5年均值？”
- **粒度**：`year`（年份 2024）
- **审查**：2024 年不在近两年窗口（2025-2026）内，无豁免；区县用户无权查看省级汇总 → 行政区修正。
- **修正**：替换为所在区县（杭州市西湖区）
- **反馈**：“因查询年份超出近两年豁免范围，且您无权查看全国数据，已为您展示所在区县2024年PM2.5年均值：30 μg/m³。”

### 8.2 异常处理细则

| 异常场景                   | 判定条件                                                   | 处理策略                                                    | 用户提示                                   |
| -------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------ |
| 豁免窗口计算失败           | `get_exemption_window_by_granularity` 抛出异常或返回非法值 | 关闭宽免通道，按基础行政区权限执行                          | 无额外提示（正常展示权限内数据）           |
| 行政区修正无法找到替代区域 | `get_replacement_region` 抛出异常或返回区域代码无效        | 回退至用户关联城市（地市/区县）；若关联城市也无效，拒绝查询 | “暂无您可访问的数据，请尝试更换查询区域。” |
| 数据查询服务超时           | 查询耗时超过 5s                                            | 不自动修正查询参数，直接返回超时错误                        | “查询超时，请稍后重试或缩小查询范围。”     |
| 数据查询返回空结果         | 查询无异常但结果集为空                                     | 正常返回，不做额外修正                                      | “当前条件下暂无数据。”                     |
| 整体流程未知异常           | 任意 Agent 抛出未捕获异常                                  | 记录完整堆栈与用户请求上下文，返回安全兜底回复              | “系统繁忙，请稍后重试。”                   |

所有异常均需记录包含 `user_id`、`original_query`、`slots`、`stacktrace` 的结构化日志。

## 9. 总结

本方案面向 AI 智能问数场景，在严格遵循原始数据行级权限的基础上，通过引入**基于时间粒度的动态宽免机制**与**多 Agent 协同架构**，实现了安全性与用户体验的精巧平衡。

### 方案核心

- **三层权限体系**：
  - **基础行政区权限**：明确定义了省、地市、区县三级用户在不同数据粒度下的可访问范围，并严格区分“汇总”与“明细”数据，杜绝越级泄密。
  - **时间粒度宽免**：将数据按时间粒度划分为高频明细（小时/日/周/自定义日范围）、月统计、年统计三类，分别匹配“最近7天”、“近两月”、“近两年”的跨行政区宽免窗口，精准覆盖了日常查询中最常见的“今日、昨日、上周、上月、去年”等场景。
  - **豁免窗口逐级回退**：当查询时间完全位于宽免窗口内时，行政区限制被完全解除；部分交集时优先截断时间以保留用户关注的区域；完全无交集时则回退至基础权限审查，确保远期数据绝不越权。
- **智能修正策略**：
  - 修正遵循“时间优先、行政区其次”的原则，最大程度保留用户原始意图。
  - 行政区修正时，根据用户层级实施差异化的上卷（如省级用户的外省区县直接上卷至省份）或替换（如地市用户的本省其他区县替换为常访问区县）逻辑，并生成透明、友好的反馈说明。
- **多 Agent 工程落地**：
  方案基于 Deep Agents 框架，将意图识别、槽位补全（含粒度推断）、权限审查、问题修正、数据查询及回应生成拆分为独立的 Subagent 或 Skill，各司其职、松耦合、可测试。权限审查 Agent 内部通过分层函数与纯工具函数实现清晰的决策流，易于后续规则调整与灰度发布。

### 关键优势

- **安全可控**：所有宽免规则均基于时间窗口动态计算，不修改底层权限表，且对远期明细数据的保护没有丝毫削弱。
- **体验自然**：用户高频使用的短期查询可以无缝跨行政区对比，而无法满足的查询也会自动给予最合理的近似结果，避免生硬的“无权限”阻断。
- **可解释性强**：任何自动修正都会在最终回答中清晰说明原因及替代逻辑，符合企业级 AI 应用的合规要求。
- **扩展性佳**：新增时间粒度或调整宽免窗口只需修改对应的窗口生成函数与粒度映射，不影响其他模块；同样，行政区权限模型的升级可被隔离在基础权限函数内部。

### 后续演进建议

- **用户行为学习**：可基于用户的实际修正接受率，动态调整常访问区域或默认替代策略。
- **多维度宽免**：未来可考虑将宽免机制扩展至其他维度（如普通用户、VIP用户），但需审慎评估风险。
- **效果监控**：在生产环境中持续收集宽免触发率、行政区修正率、用户反馈等指标，以数据驱动规则的持续优化。
