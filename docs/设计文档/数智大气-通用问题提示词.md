# 一、总体原则

1. 将**工具调用控制权**上移到 Skill 层，让提示词专注于**数据呈现和分析**；

2. 获取数据流程：`MCP` > `text2sql`，即先尝试从 MCP 接口获取数据，未获取成功改为从 text2sql 接口获取数据；

3. 自动重试：若首次调用 MCP 接口失败，自动重试 1 次，间隔 2 秒；

4. 工具降级：若重试仍失败，尝试调用 `text2sql` 查询数据仓库。若 `text2sql` 有结果，则返回数据；

5. **数据来源标记**：Skill 层在返回数据时必须附带 `source` 字段（取值为 `MCP` / `text2sql` / `none`），供提示词识别数据来源；

6. 最终兜底：若所有数据源均无结果，立即终止专属提示词调用，**完整跳转至专家提示词**；

7. 系统 AI 对话提供快速/专家两种模式，AI 对话默认快速模式；

8. 数智大气产品 AI 问数功能权限：

   - 游客：只提供 5 个固定话题问答，禁止触发任何专属 / 专家模式回答（快速/专家模式、输入框回车键、智能分析、智能交互等增加权限标记）；
   - 普通会员：在游客权限基础上，提供快速模式回答，专家模式、智能分析等功能锁定（专家模式、智能分析、智能交互等增加权限标记）；
   - VIP 会员：在普通会员权限基础上，智能分析只提供综合占比分析，专家模式、其余智能分析等功能锁定（专家模式、其余智能分析功能、智能交互等增加权限标记）；
   - SVIP 会员（产品后续考虑扩展）：提供所有功能；
   - 公司内部会员：提供所有功能；
   - 权限标记说明：快速模式无需标记，智能分析综合占比分析标记 VIP，专家模式、其余智能分析功能（含浓度排名、小时播报等）、智能交互等增加 SVIP 标记；
   - **权限标记适用范围**：通用问题快速模式（专属提示词）对所有有权限的会员（普通及以上）开放，不标记。智能分析只有综合占比分析的快速模式对VIP用户开放使用。通用问题专家模式（专家提示词）及智能分析栏目下的专家模式、综合占比分析、浓度排名、小时播报等功能，按上表权限分别标记 VIP/SVIP。标记仅用于前端 UI 展示，不影响 Skill 层路由决策。

9. 智能分析栏目快速模式使用基础快速版提示词（专属提示词），专家模式使用专业补强版提示词（专家提示词）；

10. 通用问题快速模式使用专属提示词，专家模式使用专家提示词；

11. 通用问题快速模式下，优先调用专属提示词，在部分场景下会触发专家提示词（如出现深度分析需求、边界模糊、数据异常时）；

12. **术语约定**：

    - 专属提示词：智能分析栏目快速模式所用的 “基础快速版提示词”，亦用于通用问题快速模式，核心为 “事实陈述 + 数据呈现”，无深度成因 / 管控分析；
    - 专家提示词：智能分析栏目专家模式所用的 “专业补强版提示词”，亦用于通用问题专家模式，核心为 “深度分析 + 成因溯源 + 实操建议”；
    - Skill 层：介于用户输入与提示词之间的中间层，负责统一调用 MCP /text2sql 接口、数据合并、来源标记（source）、气象数据补充及降级重试（本文档不涉及内部实现，仅定义输出格式）。

13. **通用约定**：

    - 所有提示词输出需遵循《环境空气质量标准》（GB 3095-2016）、《环境空气质量评价技术规范》（HJ 663-2026）；
    - 核心结论前置：所有回答需将关键结果 / 结论放在开头（≤30 字），适配移动端 / 语音播报场景；
    - 数据单位规范：PM2.5/PM10/NO2/SO2/O3-8h 用 “微克 / 立方米”，CO 用 “毫克 / 立方米”，禁止符号缩写；
    - 日期格式规范：单日 / 实时为 “YYYY 年 MM 月 DD 日 HH 时”，时段范围为 “YYYY 年 MM 月 DD 日 - YYYY 年 MM 月 DD 日”；
    - 同比计算规则：同比变化幅度 =（本期值 - 去年同期值）/ 去年同期值 × 100%，保留 1 位小数，下降标注 “同比下降 X.X%”，上升标注 “同比上升 X.X%”。

# 三、气象数据接入规范

空气质量与气象条件高度耦合，尤其在臭氧超标、颗粒物污染过程、区域传输等场景下，不结合气象的分析会显得单薄且缺乏说服力，所以在通用问题的部分场景下增加气象数据分析。实现方式：优先在 Skill 层并行获取气象数据（温度、湿度、风速、风向、降水、边界层高度等），然后注入到提示词中，提示词负责将气象数据与分析结论结合展示。

## 3.1 气象数据与通用问题的映射

## 3.2 气象数据来源优先级（Skill 层执行）

1. **最优**：产品气象站实时数据API（MCP接口，**当前未就绪，规划中**）

2. **次优**：产品天气预报数据API > 产品数值预报数据API（MCP接口）

3. **兜底**：国家气象信息中心 API、中国气象数据网等（通过 Skill 层网络请求获取）

3. 输出格式完全统一，无割裂感。

# 九、专属提示词 - 专家提示词触发规则执行刚性校验清单（系统配置必查）

1. 专属提示词**绝对不输出超边界内容**，任何情况下不输出成因、建议、管控、溯源等内容，仅输出客观数据与标准化结论。
2. 专家提示词**不重复输出基础数据**，所有分析必须基于专属提示词已输出的核心数据，不重复罗列已明确的监测数值。
3. 触发优先级严格执行：**原文精准匹配 > 核心要素匹配 > 模糊语义匹配 > 兜底跳转**，低优先级触发不能覆盖高优先级匹配结果。
4. 多轮对话必须**锁定上下文主体**，禁止出现主体错乱。
5. 异常数据/无数据场景，**必须触发兜底跳转**，禁止输出空白、错误、无依据的内容。

# 十一、边缘场景异常处理提示词在 Skill 层的使用说明

## 1. 设计目的

边缘场景异常处理提示词（以下简称“边缘提示词”）**不直接面向用户输出**，而是作为 Skill 层内部的 **异常捕获与降级路由规则**。当 Skill 层在数据获取、参数解析、结果校验等环节识别到特定异常模式时，**自动触发对应边缘提示词模板**，生成标准化的用户提示信息，避免空白输出或错误回答。



## 2. 各边缘场景的具体使用规则

| 边缘场景编号 | 触发条件（Skill 层检测逻辑）                           | 调用方式                                                     | 输出内容示例（直接返回用户）                                 |
| :----------- | :----------------------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| 1            | MCP 与 text2sql 均返回空数据，且查询主体/时间/因子明确 | 直接调用边缘场景1提示词模板，填充 `{城市}` `{时段}` `{因子}` | “暂无【洛阳市】【2026-04-09】【PM2.5】监测数据，无法完成查询。建议确认：① 城市名称是否准确；② 统计时段是否在监测覆盖范围；③ 目标因子是否为常规监测项。” |
| 2            | 用户查询涉及“XX城市在XX大区排名”，但无该区域排名数据   | 直接调用边缘场景2提示词模板，填充 `{大区}` `{时段}` `{因子}` | “暂无【华东地区】【今日】【PM2.5】排名数据，可提供替代查询：① 该城市在本省的排名；② 华东地区核心城市PM2.5浓度对比。” |
| 3            | 用户输入的城市名称不在标准城市列表中（如“洛市”）       | Skill 层调用模糊匹配算法（编辑距离/拼音），若唯一匹配则自动纠正并附加边缘场景3提示；若多匹配则直接输出提示 | “推测您查询的是‘洛阳市’，今日截至16时洛阳市空气质量等级为良，AQI为74；若为其他城市（如洛宁县），请补充完整名称后重新查询。” |
| 4            | 气象数据不完整（如只有温度，无湿度、风速）             | 在调用需气象的专属提示词或专家提示词前，检测 weather 对象字段，缺失必填项则附加边缘场景4提示 | “气象数据不完整（缺失湿度、风速），分析可能不全面，建议补充完整气象数据后重新研判。” |

**优先级逻辑**：城市名称错误会导致后续所有查询失败，故最高（场景3）；无数据次之（场景1）；跨区域排名无数据（场景2）和气象不完整（场景4）影响范围较小，优先级较低。若同时触发多个边缘场景，按 **场景3 > 场景1 > 场景2 > 场景4** 仅输出优先级最高的一个。

### 4. Skill 层代码示例（伪代码）

```python
def handle_edge_scenarios(query, data_result, weather_result):
    # 场景3：城市名不规范（最高优先级）
    if not is_standard_city(query.city):
        matched_city = fuzzy_match_city(query.city)
        if matched_city and match_score > 0.8:
            query.city = matched_city
            return {"type": "edge_scenario_3", "city": matched_city, "original": query.original_city}
        else:
            return render_edge_prompt(3, city=query.original_city)
    
    # 场景1：无数据
    if data_result.source == "none":
        return render_edge_prompt(1, city=query.city, period=query.period, factor=query.factor)
    
    # 场景2：跨区域无排名
    if query.is_cross_region_rank and not has_region_rank_data(data_result):
        return render_edge_prompt(2, region=query.region, period=query.period, factor=query.factor)
    
    # 场景4：气象数据不完整（需要气象的场景）
    if query.requires_weather and not is_weather_complete(weather_result):
        return {"type": "edge_scenario_4", "missing_fields": missing_weather_fields(weather_result)}
    
    return None  # 无边缘场景，正常继续
```

**重要**：边缘提示词的输出 **直接返回给用户**，**不再调用专属提示词或专家提示词**。
