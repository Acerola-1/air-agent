| 项 | 观测结果 |

## 缺失材料（保持任务 7.6 未完成的具体原因）

1. **生产认证协议**：平台如何接受企业凭据（Bearer/签名/其他）、在哪个传输位置、挑战流程——完全未提供，且当前匿名通道不暴露任何要求。
2. **企业/成员 → 外部授权主体的映射规则**：外部主体 ID 的格式、签发方、成员覆盖语义——未提供。
3. **A/B 两套授权测试身份与凭据**：未提供。
4. **可区分的授权数据样本**：用于证明“同一工具在 A/B 凭据下返回不同数据范围”——未提供。
5. `tools/call` 的真实调用鉴权行为：无凭据场景下故意不执行（对业务数据平台的写/查副作用不可证明安全），因此调用级认证仍未核验。

## 对实现决策的影响（与设计 §6 对应）

- 外部平台目前只有一个匿名可达通道，**不存在可信企业认证**。按设计：“若外部平台没有可信认证，就保持企业 MCP 禁用，说明生产授权契约缺失；不声称已实现企业隔离”。
- 因此本 change 的实现：
  - `CredentialProvider`/绑定/注入逻辑按“协议未核验 → 默认禁用”实现：`protocol_version='unverified'` 或缺绑定/缺凭据时，MCP 调用在发送前被拒绝；
  - 全部并发/隔离/撤销验证使用**受控本地 MCP fixture**（`tests/mcp_fixture/`，明确标记为模拟证据）；
  - 任务 7.6（真实平台 A/B 核验）保持未完成，等待上表缺失材料。
- 主体参数注入（7.2）：当前 109 个工具 schema 不含主体字段，因此**无可注入的字段**——这正是“未核验协议默认禁用”的直接证据；将来平台提供授权 schema 后，注入字段清单必须取自显式 schema 映射而非模糊名称匹配。
