## 逐项结论与原因

### D1：普通说明生成中途因具体条款校验被打断——已复现并修复交付行为

旧实现只在生成前按问题文本判断是否需要完整证据校验；普通问题的模型答案一旦自发出现具体标准或限值，片段校验直接发 aborted。因此安全防护虽阻止断言泄漏，用户却只能得到半截答案。

修复：普通说明继续按安全片段流式发布；遇到尚未公开的具体断言，停止并有界关闭上游，使用原有 `apply_answer_policy` 生成可信原文引用或明确的缺依据拒答，再结束**受限答复**。不展示模型的未核验断言，不回撤前缀，不将拒答解释成业务问题已解决。`policy_limited` 留在最终消息；未知引用、实际异常、取消、撤权及最终公开内容冲突继续中断。明确要求具体标准的问题仍走原有 policy-bound 路径。

回归覆盖：缺依据不泄漏具体数值；可信依据只展示原文；上游确实关闭；普通长文首段早于生成完成；引用、序号、hash、异常和授权反例仍保留。旧测试由“必须硬中断”调整为“必须不泄漏 + 明确受限答复 + 协议一致”，对应新增规格场景，未删除安全反例。

**边界：**未复跑原 6 道真实模型失败题，不能宣称本轮真实模型成功率提高到某个数值，也不保证缺知识库时仍能回答具体条款。

### D2：工具可见但执行被拒绝——已确认并修复

存在两处不一致：

- `ScopedMCPToolFactory.tools_for` 返回服务全部工具，执行层却按业务和部署双白名单拒绝部分工具。
- `prepare_model` 在 config 就地写入 authorized_tool_ids，而下一节点不保留该修改。已用当前安装的 LangGraph 编译两节点图实际验证（`config-propagation.json`）。缺这份临时 ID 集合时，旧披露逻辑仅按服务筛选，混入同服务其它业务工具。

修复：每次模型绑定工具都按服务端业务码、可信企业身份和当前受保护连接双白名单过滤，不依赖准备节点的就地修改；工厂返回的工具也取同一交集。显式 MCP 空集/选择收窄保持有效，执行侧逐发送复查不变，没有扩大 basic-qa 或 root 权限。

真实受控 MCP 测试：有合法 Bearer 正向调用；不允许工具的服务端调用计数为 0；允许工具实际调用后计数为 1。见 `mcp-network-tests.log`。

### D3：参数失败与反复尝试——修复可修正反馈和无界重试风险，原始参数根因尚未逐次查明

本地 Pydantic 参数错误原先被通用兜底归为 500，丢失了可修正字段信息。现返回 422、字段路径与类型，不回传输入值/异常原文；参数错误不作网络故障自动重试。

增加当前用户轮的确定性失败预算：授权拒绝不重试；同工具连续参数拒绝允许修正一次，之后从 schema 移除，并在执行层阻止继续发送；成功修正和下一用户轮会重置相应计数。工具规划最多 8 轮，达到后转入基于已有数据的回答。知识车道、基础问答、数据分析均接线；预算拒绝也记录为零网络观测。提示词明确以当前 schema 为准，不调用 Skill 文本中提及但未提供的工具。

**尚未证实：**原报告 87 次 validation_rejected 的逐次具体参数原因，现有公开调用 bundle 不含参数，不能据此编造某字段错误。本轮验证的是框架侧错误反馈和止损，并非真实 MCP 首次参数成功率。外部工具 schema/数据范围仍需真实配置小样本复跑。

### D4：数据分析 UI 缺菜单入口——已确认并补齐

新增 `AnalysisMenuSelector` 原生选择器，菜单值与 `data_analysis/menu_skill_mapping.py` 保持契约校验；正常发送将值写入 `configurable.menu_name`，沿现有 BFF 受理路径传递。运行中及停止待确认时锁定；切项目重置显式技能；能力列表只展示对应菜单技能。未允许显式 Skill 绕过后端确定性映射。

### D5：只有 metrics 权限被整个运营外壳拦住——已确认并修复

`SessionProvider.can(a,b)` 是 AND，运营 layout 却把它当成 OR。修为显式 `can(metrics) || can(operations)`；需要双权限的用户用量页、运营明细及后端鉴权保留。实际组件测试包含无权限、单 metrics、单 operations、双权限四组。

### D6：可见“新会话”搜不到——已确认一处确定性原因并修复

无标题会话显示“新会话”，搜索却比较空字符串。现共用 `threadTitle`，补清空搜索按钮，切图/企业清除旧搜索词。实际组件浏览器已验证搜索回退标题、清除后恢复其它会话。搜索范围仍为已加载的最多 50 条，未实现全历史全文检索；不能把本修复扩大解释成原报告所有命名标题异常均已复现。

### D7：运营跨用户正文 404——本轮未复现为运营接口缺陷，不放宽权限

自建空 PG 执行迁移到当前 head，使用非 owner、非 BYPASSRLS 的 `air_agent_runtime` 调用实际 console content 服务。合成可信身份用于隔离本项 SQL/RLS 行为，不是 Java IAM 正常登录验收。

- 本人：200；同企业“运营 + 正文”其他用户：200。
- 跨企业：404；仅 metrics 或仅 operations：403。
- 同对象删除后：404。
- 旧个人台账正文服务读取其他用户：404，这是现有个人作用域。

见 `console-rls.json`。原报告没有记录 D7 请求 URL，无法断定其是否误用了旧个人入口，因此不改接口权限、不把原报告的根因猜测写成确定事实。
