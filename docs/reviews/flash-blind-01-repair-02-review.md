## 匿名输入与独立发现

补修前将关键交付文件哈希写入 `evidence/flash-01-repair-02/anonymous-input.json`，另在本地临时目录保留源文件快照。原作者报告 `tenant-identity-access-repair-02.md` 不改写。以下三项在匿名输入上执行实际路径，新增断言先失败再修复：

| 问题 | 影响及证据 | 接管修复 |
|---|---|---|
| JSON 迁移中断后重跑误报账号冲突 | 第一阶段提交后，平台更新 503；再次预检把自己已导入账号视为同名冲突。`json-resume-before.txt` | 仅信任同来源/同指纹/同目标 UUID 的 applied 台账；阶段标记持久化，后续只补未完成平台更新 |
| SDK 在外层守卫内部自行重试 | 首次 HTTP 500 后撤销身份，真实 ChatOpenAI/OpenAI SDK 仍发第二次请求。`sdk-retry-before.txt` | SDK retries=0，显式重试逐次授权；模型及异步向量传输在每次发送前核对当前可信运行上下文，包括框架辅助摘要 |
| 停止把上一条回答当本次提交终态 | 当前 run_id 延迟时，列表旧 succeeded 运行被误认已停止。`stop-race-before.txt` | 不用旧完成运行确认本次停止；保留 pendingStopRun 与 stopPending，等待真实关联/终态，阻止新提交和切换 |

同时补齐代码审阅发现的边界：迁移续跑不得重新授予已撤销角色或覆盖用户随后修改的偏好；历史计算记录同步作用域；同外部主体的不同成员/凭据覆盖不能共用发现对象；归档自定义 HTTP 必须同时验证实时会话、作用域和已确认归属，迁移票据无归档访问权。平台 Auth 异常转换为明确的 HTTP 拒绝响应。

浏览器企业切换改为现有共享 Dialog，聚焦取消按钮；运行未确认停止时保持原企业。隔离恢复脚本重新实现为随机新库演练，不在共享业务库执行 downgrade，不记录口令。
