## 索引启动与刷新

图导入及匿名启动不发送Embedding或MCP预热请求。首次已认证`search_mcp`读取当前受保护发现，按内容摘要补齐缺少向量并原子发布完整代次；相同目录重启复用已有向量。定义变化只更新变化项，Embedding模型／端点变化使用独立model_key。查询本身仍需一次query embedding。

目录包含部署批准且当前身份／业务／选择允许的工具，不保证冻结109项全部在线。发现或索引不可用返回明确状态，不以全量schema入模降级。Skill简介直接加载和有效能力复用不依赖工具检索成功。

无需手动写向量表或删除全部缓存来刷新；下一次合法搜索发现定义变化即增量处理。`PostgresIndexStore.prune(catalog, days=30)`只接受当前可信目录，使用运行身份限定当前租户回收过期缓存，不能由前端指定任意企业。不要在正式共享库执行清空或降级操作。

## 整体回退

1. 停止新受理、排空新版和全部受策略影响的运行，保存故障证据；不把同attempt静默转交旧节点。
2. 整体恢复上一已验证代码、提示和业务策略；事件消费者保持对已产生记录的兼容。索引表是缓存，可保留，旧代码不读取；无必要为回退代码删除迁移或用户数据。
3. 保留v2 checkpoint与用户历史，旧代码不能将v2引用伪装为v1加载证明。旧代码恢复原有能力选择流程；不宣称回退后仍有v2跨轮复用能力。需要继续业务时按旧版新建合法提交，不重放结果不确定的请求。
4. 在隔离资源完成相同操作和正反例后再评估正式回退；演练证据和未覆盖项单独记录。没有实际演练不能勾选任务8.1。
