# Basic QA 多轮 Skill 循环固定验收集

版本 `bqa-conversation-loop-v1`；[机器可读清单](data/basic-qa-conversation-loop.v1.json)与[报告模板](templates/basic-qa-conversation-loop-report.md)。这是**输入、预期和判分标准**，不是已执行或通过的验收。实施目标及七组场景来自 [设计](../../openspec/changes/add-basic-qa-conversational-skill-loop/design.md)；具体 case 的输入、干预、目标对象/时间、许可与禁止行为、计数范围、依据和正向对照均以 JSON 为准。

## 数据与覆盖

- 冻结时钟为 `2026-05-08T16:00:00+08:00`、`Asia/Shanghai`。只有隔离测试环境可以注入；真实环境不修改系统时钟。执行日不是参考日时，真实环境的“今天”分支记未验收，不能和固定时钟结果直接比较。
- 沿用 `bqa-reference-202605-v1` 原题及 `bqa-fixture-202605-v1` 合成数据。`R-BQA-*` 每题独立新线程、自动 Skill/MCP，原题和答案检查项逐字引用；每个 Skill 分别在服务端 fast 和 expert 模式执行，共 18 个。模式由服务端配置而非模型输入覆盖，实际版本和模式材料要记录。九题以原集的 011、015、016、018、019、020、021、023、025 为准。`BQA-019` 属于固定今日分支。原集的单位、精度、范围、工具可用性冲突及今日分支限制仍适用；参见[原题库](basic-qa-reference-questions.md)。
- 湖州/杭州数据是本集独立新增合成样本，2026-05-08 截至15时 AQI 分别为75、95、等级良、首要污染物 PM2.5；杭州风速及风向仅是气象描述，并非来源证据。城市名称真实，数字并非监测实测。原集无这些数据，不得在未核对来源时替换原样本。
- C01–C05 是核心连续语义链；C06–C10 是选择与恢复；C11–C16、C29 是搜索、依赖和预算；C17–C22 是执行反例；C23 是真实计数服务正控，C24–C28 是干预后的零外呼反例。C01–C04 的复述、寒暄、澄清或概念追问必须逐轮另计业务外呼为0，不能以整条链累计范围掩盖第二轮多发请求。
- 样本是领域语义数据，不是实际 MCP 响应 schema。执行前须按**当时实际**工具 schema 显式适配自有计数服务，记录工具稳定 ID、连接、过滤/参数映射、样本与材料摘要；不得通过用户提示或历史把合成答案直接注入模型冒充工具结果。工具映射或历史装载不可行时标 BLOCKED，不擅自扩大白名单或放松预期。用户已确定：非 chart 工具均为必需依赖，chart 工具为可选依赖；缺图表不阻断 Skill 加载和正文。C14 移除基础查询的主数据必需工具，C15 移除可选 chart 并保留所有必需工具；分类已确定，但真实动态工具可用性及服务映射尚须单独验证。若无法构造可信隔离服务映射或接通必需依赖，相关运行标 BLOCKED，不能仅凭名称假定可用。

## 执行和计数

1. 冻结代码基线、题库和两份数据的摘要、材料版本、时钟、配置、身份、已受理选择、缓存与工具依赖；每次使用新的隔离资源和证据目录。保留用户原文及实际历史，不把追问改写成完整新问题。自建测试服务记录每次真实请求、参数及返回；不在正式库造数，也不把 HTTP 200 当业务成功。
2. 同一输入分别用于旧基线和新版本；旧版缺少新控制工具或门禁是应记录的差异，不为使旧版符合目标修改题目。分别记录加载是否存在、新增往返及有效数据请求，不以新版本目标范围强行重判旧版性能。真实模型的每条核心语义链至少独立执行三次，保存每次原始输出和失败，不挑最好一次；九 Skill 两种模式逐项人工核验，报告实际重复次数。
3. 七组中受控模型按 JSON 的干预和计数范围精确判定；范围含端点，`null` 表示未设上限而非零。范围对一个 case 全部轮次累计；按干预时刻或指定轮次的零外呼约束单独判断。八批次上限按**每用户轮**核验；清单里的范围是具体受控脚本约束，不是普遍延迟或容量承诺。搜索次数与 embedding 实际尝试分别计数，模型发送、load 尝试、业务服务真实请求分别计数，重试不可隐去。技能 loaded 与业务 executed 以实际记录为准；直接加载不得制造 matched 事件。
4. 检查目标城市、时间、指标、范围、Skill 与材料模式、工具实参、证据及正文的一致性；错误城市或无依据数值是硬失败。复述只用已有有来源事实，不新增业务计算；原因解释不指认排放源，不能自动启动 tracing。原参考集小数计算允许其原有 `0.05` 容差；城市、日期、单位、名单、排名须准确。
5. C17–C22 与 C24–C28 必须看受控干预**之后**计数服务新增真实请求为0，不能仅凭隐藏 schema、mock 或用户看到拒绝。C23 应在相同服务、身份/连接允许条件下独立成功；失败或不可运行则反例为 BLOCKED。删除/取消后的终态和实际已发请求分开记录，不把停止意图等同成功取消。身份失效后停止后续模型、embedding 和工具发送。
6. C07/C08/C10 需要实际摘要或自建持久化/SDK、材料变更证据；缺少相应能力标 BLOCKED，不以单元测试替代。分别列受控模型、真实配置模型、实际 SDK/checkpointer、真实服务与真实浏览器。真实只读服务数值若不同，以实际数据为依据单列结果，不能改写合成 gold 或直接作等值性能比较。
7. 完成后逐条记录 PASS / FAIL / BLOCKED / NOT RUN 与证据；关键范围反例须全通过、核心语义链不得有未解释失败。分别披露首正文和总延迟、可得 usage/费用及新增 load 成本；未采集标未知，不记零。小样本不支持容量结论。仅清理本任务自建资源，不覆盖旧报告。
