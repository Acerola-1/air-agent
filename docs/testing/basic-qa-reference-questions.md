# basic QA 固定参考题库与执行流程

版本：`bqa-reference-202605-v1`；制定日期：2026-10-20；Graph：`basic-qa`；默认模式：`fast`。

以后测试者使用这里的固定题目，不自行换题。40 道主问题覆盖 9 个现有 Skill、知识问答和多轮延续；另有 8 组数据异常变体。每题的完整历史、预期数值和检查点以[机器可读题库](data/basic-qa-reference-cases.v1.json)为准，输入数据以[固定合成数据](data/basic-qa-reference-fixtures.v1.json)为准。

**预期答案来自合成数据与当前 Skill 的业务规则，不是已经测得的 Agent 回答。**本轮已进行离线试检，结果见[首轮检查汇总](../reviews/basic-qa-reference/20261020-reference-v1-review.md)；真实模型回答、MCP 执行、浏览器与并发性能是否通过，必须看对应实测报告。

## 1. 固定入口与不能改动的内容

- 题库 Q1/Q2/Q3/Q4 各 10 题，权重各 25%，顺序按 BQA-001—040；重复轮次按同一顺序，不增删简单题，也不跳过已知失败。
- Q1 是概念知识，不要求匹配业务 Skill；Q2 是明确查询；Q3 是多数据/计算/分析；Q4 有固定 5 轮上下文，测量末轮提问。类别指测试负载形态，不表示已证明实际只调用一次工具。
- 默认自动选择 Skill、MCP 自动模式；不能显式指定正确 Skill 来冒充自动路由正确。显式选择可另开诊断组，不与自动组混算。
- `expected_skills` 表示最终应使用的业务规则；记录自动候选、首选、实际 loaded/executed。候选包含正确项不等于最终执行正确。
- 月份/日期/城市/范围/因子均照原题，不随日期改成“昨天”。数字、单位和统计范围逐题核验，文字不要求逐字一致。
- 原题不追加暗示答案、工具名或正确 Skill；不把 fixture/gold 作为用户提示词。主数据必须经隔离测试服务返回，真实 E 层必须核对实际来源。只给模型一段合成答案让它复述不算查询测试。
- 题库版本、fixture 版本、源码摘要、时钟/身份、模式、入口、缓存、重试、依赖及负载都写入报告。第一次生成答案后冻结证据，不把模型输出反过来当 gold。
- 数值以表中精度四舍五入：同比/占比/均值 1 位小数，浓度/计数按 fixture 原值；数值容差 0.05 仅用于该 1 位小数的算术核验，城市/日期/单位/名单/名次必须准确。百分比与百分点不混用。
- 本题库修订了[并发规范](basic-qa-performance-regression.md)中“约 4,000 字历史”的草案设定：Q4 改为 JSON 内固定的 5 轮自然历史，按文件记录实际长度，不任意填充。长上下文压力以后单独建版本，不悄悄改变这套输入。

Skill 文件存在不代表工具已接通。特别注意以下现存接缝，执行者不能自选有利规则消除失败：

1. `comparison-composition` 与 `integrated-index-ratio` 都包含“六因子占比”。本套同比题明确用前者；日范围“综合指数占比分析”题明确用后者。若模型最后切换 Skill，保留实际过程及是否完成任务，不只比较第一候选。
2. 同日两城 AQI 对比是基础查询；省内第几名是排名；月度综指优劣是区域对标。BQA-013/015/027/040 就用来区分这三条路径。
3. `station-extreme` 的 allowed-tools 已列出站点数据工具，但正文仍说“未配置专用工具”，fast 流程也存在“无上游主数据即缺失”与后续主动取数的冲突。既不能把“目录有工具”当已可查询，也不能把所有站点题直接缺失算成功。
4. 基础、同比、区域、趋势规则中要求的部分图表工具未列入各自 allowed-tools。先核对当前运行时可见与执行策略，记录实际失败，不能为了通过绕开工具白名单。
5. 一些 Skill 的快速规则一处说“无预测”，另一处允许当日/未来预报。历史题统一禁止主动拉未来预报、禁止混入已监测统计；今日分支单独冻结条件，不自行编造法规解释。
6. 所有等级边界同时核对[领域参考](../domain/air-quality-level-reference.md)。该参考保留历史约定且不完整，本套不测试未确认法规端点，不从合成浓度重新推导未说明的 AQI。

## 3. 固定数据与时间

- 这是**合成测试数据**，城市使用真实名称帮助解析，数值、测试站点、3 城参评集合都不代表实际监测结果，也不代表全省全量。
- 普通日数据：2026-05-07。洛阳市 AQI80、良、PM2.5；郑州市 AQI60、良、PM2.5。洛阳六因子为 50/80/10/30/0.8/100（PM2.5/PM10/SO2/NO2/CO/O3-8h）。
- 月数据：洛阳 2026-04 综合指数3.2、PM2.5为40、优良24天；2025-04 对应4.0/50/20。郑州 2026-04 综合指数2.8。月 CO 和臭氧保留 CO-95per、O3-8h-90per。
- 综指贡献：洛阳六分指数 1.5/1.0/0.5/0.5/0.25/1.25，总和5.0；郑州为1.0/1.0/0.5/0.5/0.25/1.75。单位是分指数，不是浓度。
- 多日序列：2026-05-01—07，洛阳 PM2.5 为30/40/50/60/50/40/50，郑州20/25/30/35/30/25/35；均值45.7和28.6。
- 小时序列：2026-05-07 共24点。洛阳15时80、03时20；郑州15时45；全部点见 fixture，峰谷不能根据这段摘要猜测。
- 站点：测试国控甲 AQI60、国控乙120、省控丙150；对应良/轻度污染/轻度污染，必须保留类型过滤。
- 河南省测试集合仅洛阳/郑州/平顶山。PM2.5排序为35/50/65，PM10排序为60/70/80；排名均从低到高。臭氧筛选另表为100/90/170，用题目明确阈值≤160，不跨表串值。
- 今日分支参考时钟为北京时间2026-05-08 16:00，监测截止15时、更新15:10。洛阳累计PM2.5为50、当前45、总体剩余控制值70，明确研判“大概率可实现”；郑州剩余为“无法完成”，明确结论“无法实现”。不得伪造未来2/3/4小时控制值。
- **BQA-014/019/030/038 属于固定今日分支。**只有具备隔离时钟注入的 P 层才能重复相同今日分支。真实 E 层不能改系统时钟或谎报北京时间：执行日不等于参考日时标“今日分支未验收”，可另做历史支持检查，但不得与 P 层或原今日基线比较。
- E 层历史业务数值与 synthetic gold 不同时，不判模型数值错误：先核对真实主数据，再单独出真实来源结果。该轮不与合成 fixture 基线比较，不能改 JSON 覆盖 gold。

### Q1：简单知识

| 编号 | 原题 | 期望 Skill | 必查答案要点 |
| --- | --- | --- | --- |
| BQA-001 | 什么是AQI？它和污染物浓度有什么区别？ | 知识车道，无业务 Skill | AQI是空气质量指数；浓度是污染物的测量值；两者不能直接互换。 |
| BQA-002 | PM2.5和PM10有什么区别？ | 知识车道，无业务 Skill | 按空气动力学当量直径区分；PM2.5属于PM10粒径范围的一部分；不编造本地监测值。 |
| BQA-003 | 什么是首要污染物？它和排放量最大的污染物是一回事吗？ | 知识车道，无业务 Skill | 首要污染物与空气质量评价相关；不等同于排放量最大的污染物，不能据此确定排放源。 |
| BQA-004 | 什么是空气质量综合指数？它和AQI有什么区别？ | 知识车道，无业务 Skill | 两者统计用途和口径不同；不能直接互换或用AQI代替综合指数。 |
| BQA-005 | 解释PM2.5和CO浓度的单位区别。 | 知识车道，无业务 Skill | PM2.5通常用微克/立方米；CO通常用毫克/立方米；单位换算相差1000倍。 |
| BQA-006 | 什么是O3-8h？它和臭氧瞬时浓度有什么区别？ | 知识车道，无业务 Skill | 明确8小时滑动平均统计口径；不将瞬时值或单个小时值冒充O3-8h。 |
| BQA-007 | 解释空气质量统计中同比和环比的区别。 | 知识车道，无业务 Skill | 同比比较上年同期，环比比较相邻周期；不得混用分母。 |
| BQA-008 | 如何计算某个因子在六因子分指数中的贡献占比？ | 知识车道，无业务 Skill | 单因子分指数除以六因子分指数之和再乘100%；不直接用显示综合指数替代分母。 |
| BQA-009 | 解释监测数据和空气质量数值预报的区别。 | 知识车道，无业务 Skill | 监测描述已发生事实；预报是未来估计，不能覆盖或替代已监测事实。 |
| BQA-010 | 为什么不能仅凭污染物浓度升高就确定具体企业是污染来源？ | 知识车道，无业务 Skill | 相关变化不构成排放源因果证据；需要来源及气象等独立证据，不指认企业。 |

## 7. 每次固定执行流程

1. **冻结**：记录版本、源码/Skill/数据摘要、实际入口及运行来源；读取正式环境保护清单。新建本轮隔离空资源和测试主体，不使用正式库造数。未经该次任务授权，不修改独立 IAM 或知识库仓库。
2. **离线试检**：执行下面命令，检查40题结构、当前真实意图规则、9 Skill 的fast/expert装载和答案算术；结果失败也保留报告，不改预期迁就代码。
3. **接通主数据**：将语义 fixture 按当前真实 MCP schema 显式适配到自有测试服务，保留工具参数/实际请求数；验证城市/日期/范围/站点类型过滤与失败注入。文件存在不等于测试服务已实现。
4. **单请求试跑**：自动 Skill、fast、40题顺序逐题执行，每题独立对话，Q4先装载自己的历史。记录候选/实际执行、查询参数、正文、终态与评分。先定位失败，后测性能；不得默默跳过失败题。
5. **正反例**：跑8异常变体及有效正向控制；跨用户/跨企业隔离另按并发规范执行。
6. **重复与发压**：同问题集3轮；达到冒烟条件后，按并发规范 R/F 档执行。所有题均参与，实际失败保留分母。诊断时显式 Skill 跑一组，用于区分路由问题和执行问题，诊断结果不覆盖自动组。
7. **报告并回收**：每题保留结果和证据，生成[报告模板](templates/basic-qa-performance-report.md)中的指标与限制；排空、确认终态、只回收本轮资源。

离线试检命令（`<新目录>`须替换，每次不同；不会进行模型/工具网络调用）：

```bash
.venv/bin/python tests/check_basic_qa_reference.py --out docs/reviews/basic-qa-reference/<新目录>
```

退出0仅说明本离线检查通过；退出1表示存在检查失败，具体见输出目录的 `report.md`/`checks.json`。它不执行真实模型、Embedding、MCP、IAM、数据库或浏览器，也不生成并发能力结论。完整 BFF 发压/模型回答执行器尚未随本题库实现，后续执行 Agent 需接通并按上述流程实际运行，不得把此命令当全套性能测试。

## 8. 每题固定记录和失败归类

每题结果至少包含：run_id、case_id、题库/fixture版本、时钟/模式、身份别名、原文/历史摘要、可信request/submission/attempt/run/answer关联、候选与实际Skill、真实工具参数脱敏摘要、数据来源/版本、首正文/完成时间及来源、模型/工具次数/usage/费用覆盖、最终状态、每项答案断言、证据引用。

| 失败层 | 举例 | 处理 |
| --- | --- | --- |
| 环境/采集 | fixture未适配、无隔离IAM、不能装载固定历史 | BLOCKED，不能造成功结果 |
| 意图/路由 | 概念题误入数据流程；同日对比误走排名 | 保留原题、预期、实际与调用证据；定位规则/模型环节 |
| 数据获取 | 时间/城市/范围错误、工具业务失败 | 不用正确拒答掩盖普通业务未完成 |
| 算术/表达 | 同比反向、CO单位错误、名单遗漏 | 即使HTTP200和正文完成，也不算业务正确 |
| 证据污染 | 历史用预报重算、复制别题/别主体结果 | 保留失败并检查作用域/缓存 |
| 性能 | 功能正确但延迟/吞吐越过冻结门禁 | 按并发规范回归，不能改答案长度或删题来通过 |

预期路由是业务判据，不是声称现有路由已通过。当前已知失败见首轮汇总，后续修复用新目录复跑。增加题目、改输入/历史/数值/口径时升数据集版本，保留原文件或其可回溯版本与证据，旧报告不可覆盖。
