## 已交付的基础层

- `src/common/skill_tool_scope.py`：控制/通用/证据处理/领域工具分类；基于受保护名称绑定及稳定 ID 收窄工具目录，拒绝跨服务短名猜测、分类冲突和非绘图可选项。仅计算范围，不授予人员权限。
- `src/common/business_graph/skill_materials.py`：完整总纲和模式快照、严格材料版本、静态材料缓存及调用方重新计算工具范围。该服务不代表已在图中激活 Skill。
- `src/common/business_graph/skill_search.py`：身份/业务/受理范围内的简介目录与可选搜索工厂，最大五候选；没有自动 top1 加载。实际图接线与真实 embedding 尚须独立验收。
- `src/common/skill_router.py`：删除明文查询匹配缓存与普通查询日志，同步和异步 embedding 客户端均使用逐发送守卫；严格检索故障与无命中区分，身份错误即使被 SDK 包装也传播，不作为普通检索失败降级。
- 目录和管理 API 受理层统一将必需工具短名映射为业务登记的稳定 ID，避免与已受理 MCP 选择使用不同标识比较。
- [材料审计](material-audit.md)、[固定用例说明](../basic-qa-conversation-loop.md)与[旧版节点基线](baseline.md)分别记录事实和测试边界。

## 用户试用发现的第二轮误拒绝（2026-10-28）

实际 Trace 显示第一轮成功加载基础查询 Skill，第二轮初始化清空活动状态，但模型沿用历史工具名直接查询杭州。原入口将“本轮没加载”统一返回403，失败止损随后把目标工具视为授权拒绝而移除，未形成可恢复循环。此前受控测试只证明未加载会阻止外呼，未覆盖阻止后补加载并继续的完整路径，不能代表真实追问已通过。

修复明确本轮加载状态、将历史加载回执仅在模型投影中标为历史、区分可恢复的加载前置条件错误与真实身份/业务拒绝。新增编译图覆盖湖州查询后杭州追问漏加载、补加载、成功调用及历史保持不变；真实授权拒绝仍耗尽工具，身份/业务异常不改写为加载提示。验证结果见[第二轮恢复记录](followup-load-recovery-20261028.md)。
