# Skill 创建规范

## 概述

本文件定义了本项目 Skill 的创建规范。所有新建 Skill 必须严格遵循此规范，确保风格统一、格式一致、模型可正确解析。

本项目使用 DeepAgents + LangGraph 架构，Skill 是业务知识的载体，通过渐进式披露机制加载：SKILL.md 负责路由识别和通用约束，references/fast.md 和 references/expert.md 负责完整执行流程。

## 目录结构

每个 Skill 是 `skills/` 目录下的一个子目录，结构如下：

```text
skills/<skill-name>/
  SKILL.md              # 技能元数据、路由描述、通用约束
  references/
    fast.md             # 快速模式完整执行规则
    expert.md           # 专家模式完整执行规则
```

- `<skill-name>` 使用小写字母和连字符，例如 `air-quality-basic-query`、`broadcast-hour`。
- 三个文件缺一不可。

## SKILL.md 编写规范

### YAML Frontmatter

SKILL.md 必须以 YAML frontmatter 开头，包含三个字段：

```yaml
---
name: <skill-name>
description: |
    <一句话概述本技能的业务用途>
    触发关键词：
    - <关键词1>
    - <关键词2>

    <场景类别1>：
    - <典型问法1>？
    - <典型问法2>？

    <场景类别2>：
    - <典型问法3>？
    - <典型问法4>？

allowed-tools: <tool1> <tool2> <tool3> ...
---
```

**各字段要求：**

- **name**：与目录名一致，小写连字符格式。
- **description**：第一行是一句话业务概述；然后是触发关键词列表和按场景分组的典型问法。触发关键词和典型问法用于语义路由匹配，应覆盖用户可能的表述方式。不同场景用空行分隔。
- **allowed-tools**：空格分隔的工具名列表。只列出执行时必须用到的工具，不加仅为文档目的的工具。`helper_get_latest_time` 是几乎所有 Skill 都需要的。

### SKILL.md 正文

正文包含以下固定章节：

```markdown
# <技能中文名>

## 详细规则入口

- 本文件只用于技能识别、路由摘要和通用约束；完整执行流程位于 `references/fast.md` 或 `references/expert.md`。
- 命中本技能后，下一步先按 `<runtime_context>` 的 `mode` 读取一个详细规则文件：`fast` 读取 `references/fast.md`，`expert` 读取 `references/expert.md`，缺失或非法时读取 `references/fast.md`。
- 读取详细规则文件后，按该文件继续执行数据获取、校验、缺失处理和输出组织；不要用本文件摘要替代详细规则。

## 执行边界

- 仅负责本技能的数据查询、结果校验和输出组织。
- <列出属于本技能的场景范围>
- <列出不属于本技能的场景范围，明确边界>
- 主数据为空时，直接进入数据缺失处理，不得生成空模板、猜测指标或编造结论。

## 通用数据范围

<列出本技能处理的数据对象和字段，包括必选和可选>

## 通用质量校验

1. <列出数据一致性校验规则>
```

```

<一句话定义本技能在快速模式下的角色>
```

### 3. 合规依据（如适用）

```markdown

<列出本技能遵循的国家标准和技术规范>
```

### 4. 输入数据范围（如适用）

### 5. 数据获取流程（核心章节）

**这是最关键的章节，必须严格遵循并行/串行标注格式：**

```markdown
# 数据获取流程

#### Step 1 [串行] — 获取时间基准

基于已注入的真实北京时间，使用 `helper_get_latest_time` 获取仓库数据的最新时间，并解析<本技能需要的参数>。

#### Step 2 [并行组] — 数据获取（以下调用互不依赖，必须并行发出）

- 调用 `<tool_name>` 获取<数据描述>；工具调用失败时，自动重试 1 次，间隔 2 秒。
- 调用气象工具获取气象数据：历史日期的日级数据调用 `mcp_weather_forecast_daily_history`，历史日期的小时级数据调用 `mcp_weather_forecast_hourly_history`，当日或未来日级数据调用 `mcp_weather_forecast_daily`，当日或未来小时级数据调用 `mcp_weather_forecast_hourly`。<失败处理说明>。
- 调用 `mcp_city_common_get_air_quality_forecast` 获取空气质量数值预报数据；<调用条件>。工具调用失败时，自动重试不超过 1 次；重试仍失败则基于已有数据降级回答，不得提及工具、接口或错误细节。

#### Step 3 [串行] — 校验主数据（依赖 Step 2 主数据结果）

校验主数据是否包含<必选字段列表>；主数据为空时，直接进入数据缺失处理，不得继续生成模板答案。

#### Step 4 [串行] — 生成图表（依赖 Step 2 主数据结果）

主数据获取成功后，必须调用 `<chart_tool>` 获取图表数据；如果图表数据失败，等待 2 秒后自动重试 1 次；重试仍失败则不影响组织结论。

#### Step 5 [串行] — 组织输出

<输出范围说明>
```

**格式规则：**

1. **步骤标题格式**：`#### Step N [串行|并行组] — 标题`，标题简短明确。
2. **串行步骤**：有数据依赖的步骤，在标题后用括号标注依赖来源，如 `（依赖 Step 2 主数据结果）`。
3. **并行组**：互不依赖的步骤放在同一个 `[并行组]` 中。并行组标题固定为 `数据获取（以下调用互不依赖，必须并行发出）`。
4. **并行组内的列表项**：统一用 `- 调用 xxx 获取...` 格式，不加角色标注（如"主数据:"），不写嵌套子规则块。
5. **预报工具**：如果 Skill 需要预报数据，预报调用作为并行组的一个普通列表项，调用条件和降级规则写进同一项。预报的使用约束（如"不得覆盖已监测事实"）放在独立的"预报数据使用约束"章节，不混在数据获取流程中。
6. **气象工具路由**：统一写法为"历史日期的日级数据调用 `mcp_weather_forecast_daily_history`，历史日期的小时级数据调用 `mcp_weather_forecast_hourly_history`，当日或未来日级数据调用 `mcp_weather_forecast_daily`，当日或未来小时级数据调用 `mcp_weather_forecast_hourly`"。
7. **重试规则**：统一写法为"工具调用失败时，自动重试 1 次，间隔 2 秒"。
8. **严格串行的 Skill**（如 ranking-assessment、regional-benchmark）：所有步骤都标 `[串行]`，不设并行组。格式仍然统一为 `Step N [串行]`。

## references/expert.md 编写规范

专家模式文件结构与 fast.md 类似，但有以下区别：

1. **角色定位更高**：专家角色比值守人员更高阶，如"大气环保领域 xxx 专家"。
2. **核心补强要求替代核心总结要求**：专家模式需要专业补强分析，不只是快速总结。
3. **输出结构更丰富**：专家模式通常包含"注意事项"板块。
4. **可能有刚性约束**：某些 Skill（如 broadcast-hour、integrated-index-ratio）有"严禁开展具体企业排放判定"等刚性约束。
5. **气象数据获取方式不同**：快速模式可能"仅在用户要求时"获取气象数据，专家模式则"必须获取"。
6. **预报调用条件可能不同**：快速模式可能"默认不调用"，专家模式可能"条件性调用"。

## 常见工具路由规则

### 气象工具

根据查询日期选择：

| 查询日期 | 日级数据 | 小时级数据 |
|----------|---------|-----------|
| 历史日期 | `mcp_weather_forecast_daily_history` | `mcp_weather_forecast_hourly_history` |
| 当日或未来 | `mcp_weather_forecast_daily` | `mcp_weather_forecast_hourly` |

### 空气质量预报

- 工具：`mcp_city_common_get_air_quality_forecast`
- 通常仅当日 + 主数据未覆盖未来时段时调用
- 历史日期和当日已覆盖全天时不得调用

### 实时数据补充

- 工具：`mcp_city_common_get_air_quality_realtime_stat`
- 在多个 Skill 中用作数据补充

### 时间基准

- 工具：`helper_get_latest_time`
- 几乎所有 Skill 的 Step 1，用于解析相对时间

## 并行性判断方法

创建新 Skill 时，按以下步骤判断哪些步骤可以并行：

1. 画出所有工具调用的依赖关系：每个工具的输入参数依赖哪些前置步骤的输出？
2. `helper_get_latest_time` 的输出（时间信息）是几乎所有后续步骤的依赖，所以 Step 1 必然串行。
3. Step 1 完成后，检查哪些工具调用**仅依赖 Step 1 的时间信息，不依赖其他工具的输出数据**。这些工具可以放入 `[并行组]`。
4. 典型可并行的组合：主数据查询 + 气象数据查询 + 预报数据查询（三者互不依赖）。
5. 典型必须串行的步骤：数据校验（依赖主数据结果）、图表生成（依赖主数据结果）、输出组织（依赖所有数据）。

## 禁止事项

1. **不要在并行组内写嵌套子规则块**（如嵌套的"调用条件/用途/双向规则/降级规则"），保持列表项扁平。
2. **不要在列表项上加角色标注**（如"主数据:"、"补充数据:"），统一用"- 调用 xxx 获取..."。
3. **不要在并行组内的列表项加括号注释重复说明并行性**（如"（独立步骤）"、"（必须并行发出）"），并行组标题已经说明。
4. **不要把使用约束混在数据获取流程中**，约束规则放独立章节。
5. **不要在 description 中写执行规则**，description 只用于路由匹配。
6. **不要在 allowed-tools 中加仅为文档目的的工具**，这是执行白名单。
7. **不要在输出中暴露内部实现细节**（工具名、字段名、模式名、源码路径）。

## 完整示例

以下是一个新 Skill 的完整文件示例：

### SKILL.md

```markdown
---
name: pollution-source-trace
description: |
    追踪城市或区域污染来源方向，分析污染传输路径和局地排放贡献
    触发关键词：
    - 污染来源
    - 污染传输
    - 区域传输
    - 局地排放
    - 污染来源方向

    污染来源方向追踪：
    - 今日某市PM2.5污染来源是什么方向？
    - 昨天某市污染是本地还是外来的？
    - 某市当前污染传输路径？

allowed-tools: helper_get_latest_time mcp_city_common_get_air_quality_realtime_stat mcp_weather_forecast_hourly mcp_weather_forecast_hourly_history
---

# 污染来源方向追踪

## 详细规则入口

- 本文件只用于技能识别、路由摘要和通用约束；完整执行流程位于 `references/fast.md` 或 `references/expert.md`。
- 命中本技能后，下一步先按 `<runtime_context>` 的 `mode` 读取一个详细规则文件：`fast` 读取 `references/fast.md`，`expert` 读取 `references/expert.md`，缺失或非法时读取 `references/fast.md`。
- 读取详细规则文件后，按该文件继续执行数据获取、校验、缺失处理和输出组织；不要用本文件摘要替代详细规则。

## 执行边界

- 仅负责污染来源方向追踪、传输路径分析和局地排放贡献判断。
- 用户询问污染来源方向、传输路径、本地还是外来污染时，属于本技能。
- 用户询问具体企业排放、精确减排量测算、深度源解析时，不属于本技能。
- 主数据为空时，直接进入数据缺失处理，不得生成空模板、猜测来源或编造传输路径。

## 通用数据范围

- 实时空气质量数据：AQI、首要污染物、六因子浓度。
- 气象数据：风速、风向、边界层高度。
- 数据来源字段 `source`：仅供内部判断，不得原样输出给用户。

## 通用质量校验

1. 若风向与传输方向逻辑不一致，追加"【数据告警】气象数据与传输判断不一致，建议核对原始数据。"
```

### references/fast.md

```markdown
## 快速模式规则

# 角色定位

生态环境部门污染来源方向快速研判值守人员

# 数据获取流程

#### Step 1 [串行] — 获取时间基准

基于已注入的真实北京时间，使用 `helper_get_latest_time` 获取仓库数据的最新时间，并解析目标城市、日期和查询时段。

#### Step 2 [并行组] — 数据获取（以下调用互不依赖，必须并行发出）

- 调用 `mcp_city_common_get_air_quality_realtime_stat` 获取指定城市的实时空气质量数据；工具调用失败时，自动重试 1 次，间隔 2 秒。
- 调用小时级气象工具获取气象数据：历史日期调用 `mcp_weather_forecast_hourly_history`，当日或未来时段调用 `mcp_weather_forecast_hourly`。气象数据获取失败或为空时，在答案末尾标注："缺失气象数据，无法判断传输方向"。

#### Step 3 [串行] — 校验主数据（依赖 Step 2 数据结果）

校验主数据是否包含目标城市、首要污染物、风速和风向；主数据为空时，直接进入数据缺失处理，不得继续生成模板答案。

#### Step 4 [串行] — 组织输出

快速模式只基于主数据和气象数据输出污染来源方向、传输路径和局地排放贡献判断。

# 核心总结要求

1. 核心结论前置（≤30字）：来源方向+主要贡献
2. 数据完整呈现（风向+风速+浓度变化）
3. 无深度源解析、无具体企业排放判定

# 输出规范

固定输出结构：【核心结论】→【来源方向分析】→【数据说明（必要时）】

# 刚性规则

1. 污染来源仅限定于"不利气象/局地排放/区域传输/生物质焚烧"四大类方向。
2. 不得进行具体企业排放判定或深度源解析。
3. PM2.5、PM10、SO2、NO2、O3 使用"微克/立方米"，CO 使用"毫克/立方米"。
4. 若主数据为空，直接进入数据缺失处理。

# 数据缺失处理

无数据时输出：暂无【{city}】【{date}】污染来源追踪数据，无法完成分析。
```
