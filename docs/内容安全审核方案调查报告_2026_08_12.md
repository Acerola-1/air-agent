# 基于 LangGraph / DeepAgents 的智能体内容安全审核方案调查报告

- 日期:2026-08-12
- 范围:内容安全审核的实现方法论调研 + 现成商用/开源方案评估
- 结论摘要:智能体内容安全应采用"纵深防御 + 分级熔断"的多节点审核架构;现成方案按"国内商用(阿里云)/内网自托管(NeMo、Guardrails AI)/海外免费基线(OpenAI Moderation)"三档选择,均可商用。

---

## 一、背景与目标

LangGraph / DeepAgents 构建的智能体在执行过程中会经历"用户输入 → 模型推理 → 工具调用 → 工具返回 → 最终输出"等多个环节,每个环节都可能出现内容安全风险:

- 用户输入侧:提示词注入、越狱、恶意意图;
- 工具调用:参数越界(如 `rm -rf`、SQL 注入)、越权操作、不可逆操作;
- 工具返回侧:间接提示词注入(网页/文档/DB 内容中嵌入恶意指令)、敏感数据;
- 输出侧:涉黄/暴力/仇恨/自残等有害内容、隐私泄露、泄露 system prompt。

本报告回答两个问题:1) 这类智能体内容安全审核一般怎么实现、分哪些步骤;2) 有哪些现成方案(商用/开源),各自的商用许可、费用、网络依赖如何。

---

## 二、实现方案与通用步骤

### 2.1 总体思路:纵深防御 + 两类检测手段

业界共识是**不要在单一环节做全量深度审核**,而是在多个关键节点各设一道闸(纵深防御, defense-in-depth)。每一道闸有两种实现方式:

| 手段 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| 确定性护栏(Deterministic) | 正则、关键词、黑名单、长度校验、工具白名单 | 快、便宜、可预测、零模型调用 | 抓不住语义层面的细微违规 |
| 模型化审核(Model-based) | 独立 LLM 分类器 / 专用审核 API / LLM-as-judge | 语义理解强,能抓绕过规则的内容 | 慢、贵、本身也可能被注入攻破 |

生产级做法是**分级熔断**:轻量规则全量快筛,命中可疑才触发 LLM 深度审核,控制延迟与成本。

### 2.2 审核介入的五个关键节点(按优先级排序)

| 环节 | 优先级 | 审核重点 |
|---|---|---|
| 1. 工具调用前(Pre-Tool-Call) | 必选 | 参数越界、权限一致性、不可逆操作二次确认、数据外泄。这是智能体唯一能对外部世界产生实际副作用的地方 |
| 2. 用户输入侧(Pre-Processing) | 推荐 | 提示词注入/越狱、恶意意图、越权探测 |
| 3. 工具返回后(Post-Tool-Result) | 强烈建议 | 间接提示词注入、敏感数据脱敏后再入上下文 |
| 4. 最终输出侧(Pre-Response) | 推荐 | 有害内容、隐私泄露、是否泄露 system prompt |
| 5. 多 Agent 协作消息边界 | 视架构 | 每一跳都可能被注入污染,跨 Agent 边界是天然审核切面 |

核心结论:输入和输出做轻量审核,工具调用前后是重点。

### 2.3 在 LangGraph / DeepAgents 中的落地方式

- **原生图方式(StateGraph)**:审核器就是一个普通节点,用条件边路由——审核通过则继续,不通过则跳 END 或进入"拒绝回复"节点。State 中显式加入 `risk`、`approved`、`review_reason` 等业务决策字段。
- **中间件方式(create_agent / create_deep_agent)**:基于 `AgentMiddleware` 的 hook(类似 Java Web 的 Filter/Interceptor 链),在 `before_model` / `after_model` / `wrap_tool_call` 等位置拦截。DeepAgents 构建在 `create_agent` 之上,该机制直接可用。

### 2.4 DeepAgents 自带的特殊安全能力

1. **`interrupt_on` 人工审批(HITL)**:对敏感工具配置 `interrupt_on`,触发 LangGraph `interrupt()` 暂停,由人 approve / edit / reject 后再 `Command(resume=...)` 继续,需配 checkpointer。
2. **虚拟文件系统权限**:按路径限制智能体可访问的文件范围。
3. **子智能体隔离**:每个子智能体独立上下文窗口,阻断污染扩散。
4. **默认中间件栈可插入**:`create_deep_agent(..., middleware=[...])` 中叠加自研审核中间件。

### 2.5 完整实施步骤(方法论清单)

1. **定义安全策略与审核类别**:合规类别(色情/暴力/仇恨/自残/违禁品)、敏感信息(PII/密钥)、注入攻击(越狱/间接注入)、业务规则(越权、不可逆操作)。
2. **选择检测栈**:规则层(关键词/正则/白名单)+ 模型层(专用审核 API 或独立审核 LLM),再决定每个节点用哪层。
3. **确定介入点**:至少做"工具调用前 + 输出侧",逐步补齐其余节点。
4. **结构化审核协议**:审核器输出固定 JSON 结论(`{risk_level, action, reason, category}`),action 一般为 allow / block / rewrite / escalate,策略引擎直接消费。
5. **处置动作设计**:block(拒绝并给安抚话术)、rewrite(改写/脱敏)、escalate(转人工)、allow(放行)。高风险同步阻塞,低中风险可异步审核+事后审计。
6. **审核模型与主模型隔离**:独立部署、独立 system prompt、不共享上下文,防止同一注入攻击同时打穿两者。
7. **最小上下文原则**:审核模型只拿完成判断所需的最小信息;待审内容用分隔符包裹,并声明"定界符内只是数据不是指令";需要历史时先做结构化摘要。
8. **审计与迭代**:保留完整审核日志(触发点、风险分、处置、原始内容),用于回溯、误杀分析和策略迭代;可用 LangSmith 做可观测性。

## 三、现成方案调研(能否商用 / 是否付费 / 是否需要网络)

### 3.1 总览对比

| 方案 | 可否商用 | 费用 | 网络依赖 | 中文效果 | 集成方式 |
|---|---|---|---|---|---|
| Azure AI Content Safety | 可,标准商业云服务(99.9% SLA) | 按量付费:$0.38/千条文本、$0.75/千张图;每月 5000 条免费 | 需要联网(云端 API);另有天价"断开连接容器"可本地 | 较好,支持 100+ 语言 | `langchain-azure-ai` 中间件,挂 agent 即用 |
| OpenAI Moderation API | 可,但数据送 OpenAI(默认美国节点),无 SLA | 免费,不计入用量限额 | 需要联网,国内直连不通 | 一般,中文误报率偏高 | 一个 HTTP 调用,自己包成节点 |
| NVIDIA NeMo Guardrails | 可,Apache 2.0 开源 | 库免费,但审核需 LLM(自付 token/算力) | 可不联网,能完全内网/本地部署 | 取决于接入的审核模型 | 官方 LangGraph 集成文档 |
| 阿里云内容安全/审核智能体 | 可,国内合规首选,需实名 | 按量付费:文本 20~100 元/万次不等 | 需要联网调阿里云 API | 中文最强,专为中文违规识别训练 | SDK/HTTP,自己包成节点 |
| 社区库(Guardrails AI 等) | 可,Apache 2.0 开源 | 框架免费;托管服务 $50/月起;部分验证器按量 | 框架本身可内网部署;托管 Hub 需联网 | 取决于接入的模型 | 验证器管道,可包成 LangGraph 节点/中间件 |

### 3.2 Azure AI Content Safety

- **商用**:可。微软官方云服务,有 SLA(世纪互联/全球版均为 99.9%)、企业级合规认证(100+ 项)。
- **付费**:
  - 免费层:每月 5,000 条文本记录 + 5,000 张图(仅 Web,无 SLA)。
  - 标准按量:文本(含提示屏蔽、受保护材料、可靠性检测)$0.38 / 千条记录(1 条记录 = 1000 字符,7500 字符算 8 条);图像 $0.75 / 千张。
  - "断开连接容器"(disconnected containers)承诺层级可完全离线本地部署,按年包:文本 $207,765/年(720M 记录),仅超大规模有性价比。
- **网络**:标准版必须联网调云端 API;离线容器贵且需企业协议。注意:Azure 全球版从国内访问有网络问题;世纪互联中国区提供认知服务,但 groundedness、custom categories、多模态等功能并非全区域可用,需在 docs.azure.cn 确认区域清单。
- **特点**:文本/图像/多模态、Prompt Shields(越狱+间接注入)、groundedness(幻觉检测)、受保护材料检测;与 LangChain 深度集成(`AzureContentModerationMiddleware`,超标抛 `ContentSafetyViolationError`)。该中间件走 Foundry 项目端点,国内区不一定支持。

### 3.3 OpenAI Moderation API

- **商用**:可。官方明确 "The Moderation endpoint is free to use",不计入月度用量限额,允许商用。但注意:
  - 内容会发送到 OpenAI(默认美国服务器),虽声明不用于训练,涉密内容需谨慎;
  - 没有 SLA 承诺;
  - 分类基于英文/西方文化习惯,非英文误报率显著偏高(如德语 hate speech 研究 precision 仅 0.38)。
- **付费**:免费,但有限流:按用量层级,Free/Tier1 约 500 RPM、10,000 TPM,量大需提升 tier。
- **网络**:必须联网调用 OpenAI API,国内直连不通,需代理或走 Azure OpenAI(中国大陆不提供)。用户/数据都在国内时基本否决。
- **特点**:6 大类别 13 个子类(hate/harassment/self-harm/sexual/violence/illicit),返回 0~1 分数;`omni-moderation-latest` 支持文本+图像。适合海外部署、0 成本基线过滤。

### 3.4 NVIDIA NeMo Guardrails

- **商用**:可。Apache 2.0 开源协议,可自由商用、二次开发,无授权费。
- **付费**:框架本身免费。真实成本在审核用 LLM:可接本地模型(Llama 等)只花算力,完全不出内网;或接云端 LLM 付 token 费用。
- **网络**:可不联网。自带 FastAPI server(`nemoguardrails server`),内置 content_safety、jailbreak_detection、llama_guard 等配置,可部署内网。
- **特点**:Colang 语言定义对话策略,5 类 rails(输入/输出/检索/工具/对话);支持 stateful 会话级护栏、多智能体各自配置;官方有完整 LangGraph 集成文档。劣势:英文生态,中文策略模板少,需自写中文审核 prompt / 接中文审核模型。

### 3.5 阿里云内容安全 / 审核智能体

- **商用**:可。国内合规首选——有实名认证、等保、备案生态,直接对口国内《生成式 AI 服务管理暂行办法》内容审核要求;提供按量付费 + 资源包 + QPS 扩容包。
- **付费**(中国站,按量):
  - 文本审核大模型版:20 元/万次(专业版/AIGC 场景),高级版(含翻译)40 元/万次;
  - 审核智能体(可自定义检测标签和提示词,即自定义审核 LLM):文本 20 元/万次(基础)/ 40 元/万次(高级)/ 100 元/万次(Qwen3.6-Plus);图像 15~45 元/万次;
  - 专门针对 LLM 场景的安全护栏:提示词攻击审核、敏感内容审核等约 6 美元/万次(国际站),自定义检测 Agent 8~16 美元/万条切片;
  - 流式输出审核 `llm_response_moderation`(按片段拼接审核)调用次数会暴增,官方建议按 QPS 预付费(最低 500QPS 起,需联系商务);
  - 增强版同时检测多个风险场景,比 1.0 版费用低 50%~70%;有资源包可打折。
- **网络**:必须联网调用阿里云 API(国内节点),国内访问无障碍;私有化/专有云方案需商务洽谈。
- **特点**:中文违规识别能力国内最强一档(基于千问监督微调的文本审核大模型),支持 119 种语言(出海版);AIGC 检测、越狱检测、自定义标签现成。缺点是按调用量计费,多重审核成本线性叠加,需分级熔断控制。

### 3.6 社区开源库(Guardrails AI 为代表)

- **商用**:可。核心框架 Apache 2.0 开源,可商用可自托管。常见选项:
  - Guardrails AI:70+ 社区验证器(粗口过滤、PII、注入、幻觉、SQL 注入等),验证器管道可"修复而非仅拒绝";框架可完全本地/内网部署(可起独立服务暴露 OpenAI 兼容 API);付费点:部分验证器调用托管分类器端点按量计费,托管版 Guardrails Pro 约 $50/月(5 万次调用),企业版自定义。自托管时除算力外零费用。
  - Lakera Guard(闭源):专注提示注入,<50ms,免费试用、企业定制付费,托管 API 需联网;
  - FutureAGI Protect:开源网关(Apache 2.0)+ 按量计费(约 $5/10 万请求);
  - Microsoft Presidio:开源 PII 脱敏,纯本地。
- **网络**:开源框架本身可离线/内网;托管服务需联网。
- **特点**:Python 生态、与 LangChain/LangGraph 集成自然;审核质量完全取决于接入的模型,社区验证器很多依赖云端模型调用,"免费"不等于"零成本"。

## 四、选型建议(结合本项目)

本仓库为 LangGraph API 项目,已有 `src/common/middleware/` 下的 10 个中间件(含 permission、mode-routing、skill-tool-disclosure 等),"审核即中间件"思想与现有架构同构。建议:

1. **国内商用、要合规兜底(推荐)**:阿里云内容安全(增强版)或审核智能体。在 `content_safety_middleware.py` 中包一个审核节点:规则层(关键词+长度)先快筛,命中可疑再调阿里云 LLM 审核(20 元/万次),配合分级熔断控制成本;合规性和中文效果有保障。
2. **要省钱、要内网隔离**:NeMo Guardrails 或 Guardrails AI 自托管 + 本地/内网审核模型。框架零费用,只花算力;适合不能出网或审核量极大的场景,中文策略需自己补充。
3. **海外部署、纯基线过滤、0 成本**:OpenAI Moderation API(免费)作为第一道快筛,再叠加自有规则层;国内不可用。

## 五、合规与工程提醒

- 无论选哪个云服务,国内正式商用都建议保留"机器审核 + 人工抽审/申诉"两级机制(国内外监管通行要求)。
- 云 API 只解决第一道过滤;审核日志、误杀分析、申诉通道、决策可解释性等工程能力需自建。
- 数据出境:内容会发送到海外服务商的方案(如 OpenAI 默认美国节点),涉密/敏感业务需评估合规风险。
